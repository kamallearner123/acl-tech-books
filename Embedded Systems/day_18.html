18.1 Solid-State Non-Volatile Memory: NOR, NAND, and EEPROM

Persistent storage is foundational for embedded engineering: calibration offsets, encryption credentials, event logs, and firmware update images must survive complete power loss. However, non-volatile solid-state memory exhibits physical and metallurgical constraints fundamentally distinct from RAM:

  • Endurance Limits: Every flash write/erase cycle stresses the microscopic dielectric oxide layer insulating floating-gate or charge-trap transistors. After 10,000 to 100,000 cycles, the oxide breaks down, permanently trapping charge and creating bad blocks.
  • Asymmetric Granularity: Flash memory allows byte or word-level reading, page-level writing (programming), but requires sector or block-level erasing. You cannot overwrite a byte without erasing an entire multi-kilobyte block.

Figure 18.0-1: Solid-State Flash Memory Cell Architectures (NOR vs NAND)
Figure Parameters Explained:
  • NOR Flash Architecture: Parallel bit-cell connections provide ultra-fast random read access, allowing the CPU to execute code directly from flash (eXecute-In-Place / XIP).
  • NAND Flash Architecture: Serial cell strings maximize silicon density for massive mass storage (SD cards, eMMC, SSDs), but require software bad-block management and Error Correction Code (ECC).
  • True EEPROM: Dual-transistor bit cell allows single-byte erasing and writing with extreme endurance (> 1,000,000 cycles), but possesses low storage density.

18.2 EEPROM Emulation in Microcontroller Flash

Because true on-chip EEPROM increases silicon fabrication wafer costs, modern microcontrollers emulate EEPROM using internal NOR Flash. By designating two identical Flash sectors (e.g., Page 0 and Page 1), the firmware writes key-value parameter pairs sequentially. When the active page fills up, valid parameters are copied to the alternate page, and the old page is erased in the background.

Figure 18.0-2: Dual-Sector EEPROM Emulation State Machine
Figure Parameters Explained:
  • Page Header (Valid / Erased): First 32-bit word in sector declares its state (0xFFFF=Erased, 0x0000=Receiving, 0x1111=Valid).
  • Key-Value Element Format: Each variable is written as a 16-bit Virtual Address + 16-bit Data Value.
  • Append-Only Updates: Modifying a parameter simply writes a new entry at the next free address without erasing.
  • Atomic Page Swap: Garbage collection only moves the latest version of each variable, minimizing flash wear.

#include <stdint.h>
#include <stdbool.h>

#define PAGE0_BASE          0x08010000U
#define PAGE1_BASE          0x08014000U
#define PAGE_SIZE           0x4000U  /* 16 KB */

#define STATE_ERASED        0xFFFFFFFFU
#define STATE_RECEIVING     0xEEEEEEEEU
#define STATE_VALID         0x00000000U

typedef struct {
    uint16_t virt_addr;
    uint16_t data;
} EepromVar_t;

extern void flash_erase_sector_by_addr(uint32_t addr);
extern void flash_write_word(uint32_t addr, uint32_t data);

bool eeprom_write_variable(uint16_t var_id, uint16_t value) {
    uint32_t active_page = PAGE0_BASE;
    uint32_t page_state = *(volatile uint32_t *)active_page;

    if (page_state != STATE_VALID) {
        active_page = PAGE1_BASE;
    }

    /* Scan for the first blank word (0xFFFFFFFF) in active page */
    uint32_t write_addr = active_page + 4U;
    while (write_addr < (active_page + PAGE_SIZE)) {
        if (*(volatile uint32_t *)write_addr == 0xFFFFFFFFU) {
            /* Pack 16-bit ID and 16-bit Data into single 32-bit word */
            uint32_t packed = ((uint32_t)var_id << 16) | value;
            flash_write_word(write_addr, packed);
            return true;
        }
        write_addr += 4U;
    }

    /* Page full: Trigger garbage collection and page swap here */
    return false;
}

18.3 External SPI NOR Flash Driver (Winbond W25Q32 / W25Q128)

When firmware data logging exceeds internal MCU flash (e.g., audio clips, high-rate flight data, local web assets), embedded systems interface external SPI or Quad-SPI (QSPI) NOR flash chips. Operating over SPI mode 0 or 3, commands follow a rigid sequence: Write Enable (0x06), Sector Erase (0x20), and Page Program (0x02).


#include <stdint.h>

#define W25Q_CMD_WRITE_ENABLE   0x06U
#define W25Q_CMD_READ_STATUS1   0x05U
#define W25Q_CMD_PAGE_PROGRAM   0x02U
#define W25Q_CMD_SECTOR_ERASE   0x20U
#define W25Q_CMD_READ_DATA      0x03U
#define W25Q_STATUS1_BUSY       (1U << 0)

extern void spi_cs_low(void);
extern void spi_cs_high(void);
extern uint8_t spi_transfer_byte(uint8_t byte);

void w25q_wait_busy(void) {
    uint8_t status;
    do {
        spi_cs_low();
        spi_transfer_byte(W25Q_CMD_READ_STATUS1);
        status = spi_transfer_byte(0xFF);
        spi_cs_high();
    } while (status & W25Q_STATUS1_BUSY);
}

void w25q_erase_4k_sector(uint32_t sector_addr) {
    /* 1. Send Write Enable command */
    spi_cs_low();
    spi_transfer_byte(W25Q_CMD_WRITE_ENABLE);
    spi_cs_high();

    /* 2. Issue 4KB Sector Erase with 24-bit address */
    spi_cs_low();
    spi_transfer_byte(W25Q_CMD_SECTOR_ERASE);
    spi_transfer_byte((uint8_t)(sector_addr >> 16));
    spi_transfer_byte((uint8_t)(sector_addr >> 8));
    spi_transfer_byte((uint8_t)(sector_addr & 0xFF));
    spi_cs_high();

    w25q_wait_busy();
}

void w25q_write_page(uint32_t page_addr, const uint8_t *data, uint16_t len) {
    if (len > 256) len = 256; /* Page boundary limit */

    spi_cs_low();
    spi_transfer_byte(W25Q_CMD_WRITE_ENABLE);
    spi_cs_high();

    spi_cs_low();
    spi_transfer_byte(W25Q_CMD_PAGE_PROGRAM);
    spi_transfer_byte((uint8_t)(page_addr >> 16));
    spi_transfer_byte((uint8_t)(page_addr >> 8));
    spi_transfer_byte((uint8_t)(page_addr & 0xFF));

    for (uint16_t i = 0; i < len; i++) {
        spi_transfer_byte(data[i]);
    }
    spi_cs_high();

    w25q_wait_busy();
}

18.4 Chan's FatFS Architecture on Embedded Media

To read and write files compatible with standard desktop operating systems (Windows, macOS, Linux), embedded systems integrate FatFS (developed by ChaN). FatFS separates the FAT12/FAT16/FAT32/exFAT filesystem algorithms from physical hardware via an abstraction layer called diskio.c.

Figure 18.0-3: FatFS Modular Layer Stack and DiskIO Abstraction
Figure Parameters Explained:
  • Application Layer: Calls high-level POSIX-like file operations (f_mount, f_open, f_printf).
  • FatFS Library: Manages cluster chains, FAT directory tables, LFN (Long File Names), and caching.
  • DiskIO Abstraction: Standard 5-function interface translating sector requests to hardware reads/writes.
  • Physical Storage: Interchangeable storage medium: microSD card via 4-bit SDMMC, or external SPI flash chip.

#include <stdio.h>
#include <string.h>
#include "ff.h"

static FATFS g_fatfs;
static FIL   g_logfile;

FRESULT log_sensor_sample_csv(uint32_t timestamp, float temp, float press) {
    FRESULT fr;
    UINT bytes_written;
    char line_buf[64];

    /* 1. Mount logical drive 0 */
    fr = f_mount(&g_fatfs, "0:", 1);
    if (fr != FR_OK) {
        return fr;
    }

    /* 2. Open or create file with Read/Write and Append flags */
    fr = f_open(&g_logfile, "0:/log.csv", FA_WRITE | FA_OPEN_ALWAYS);
    if (fr != FR_OK) {
        f_mount(NULL, "0:", 0);
        return fr;
    }

    /* 3. Seek to end of file to append new records */
    f_lseek(&g_logfile, f_size(&g_logfile));

    /* 4. Format CSV line: timestamp, temperature, pressure */
    snprintf(line_buf, sizeof(line_buf), "%lu,%.2f,%.2f
", timestamp, temp, press);

    /* 5. Write buffer to SD card */
    fr = f_write(&g_logfile, line_buf, (UINT)strlen(line_buf), &bytes_written);

    /* 6. Flush cache buffers and close file */
    f_sync(&g_logfile);
    f_close(&g_logfile);

    /* Unmount drive */
    f_mount(NULL, "0:", 0);
    return fr;
}

18.5 FAT32 Cluster Allocation and Power-Loss Corruption

A FAT32 filesystem organizes storage into Clusters (typically 4 KB, consisting of eight 512-byte sectors). The File Allocation Table (FAT) acts as a linked list: entry $N$ contains the index of the next cluster in the file. If power fails while f_write() has updated directory entries but not the FAT table, file cross-linking and corruption occurs. Embedded firmware must issue periodic f_sync() calls to commit metadata.


#include "ff.h"

#define SYNC_INTERVAL_SAMPLES   50U

static FIL g_file;
static uint32_t g_sample_count = 0;

void power_safe_logger_append(const void *record_bytes, UINT record_size) {
    UINT bw;
    f_write(&g_file, record_bytes, record_size, &bw);

    g_sample_count++;

    /* Commit cached FAT tables to physical non-volatile media periodically */
    if ((g_sample_count % SYNC_INTERVAL_SAMPLES) == 0) {
        f_sync(&g_file);
    }
}

18.6 Wear-Leveling and Flash Longevity Auditing

Unlike rotating magnetic hard disks, flash sectors will physically degrade if written repeatedly. A circular logging task writing 100 bytes every second directly to sector 0 will destroy the sector in under 3 days ($100\text{K cycles} / 86400\text{s} \approx 1.15\text{ days}$). Wear leveling distributes write cycles evenly across all available sectors.


#include <stdint.h>
#include <stdbool.h>

#define TOTAL_LOG_BLOCKS    16U
#define MAX_ALLOWED_ERASES  100000U

typedef struct {
    uint32_t physical_block_addr;
    uint32_t erase_count;
    bool is_bad_block;
} BlockWearEntry_t;

static BlockWearEntry_t g_wear_table[TOTAL_LOG_BLOCKS];

uint32_t get_optimal_wear_level_block(void) {
    uint32_t min_erases = 0xFFFFFFFFU;
    uint32_t best_index = 0;

    for (uint32_t i = 0; i < TOTAL_LOG_BLOCKS; i++) {
        if (!g_wear_table[i].is_bad_block && g_wear_table[i].erase_count < min_erases) {
            min_erases = g_wear_table[i].erase_count;
            best_index = i;
        }
    }

    /* Audit endurance limit */
    if (g_wear_table[best_index].erase_count >= (MAX_ALLOWED_ERASES * 8U / 10U)) {
        /* Warning: Sector has reached 80% of rated endurance */
    }

    g_wear_table[best_index].erase_count++;
    return g_wear_table[best_index].physical_block_addr;
}

Flash programming operates unidirectionally: Fowler-Nordheim tunneling or hot-carrier injection traps charge to clear bits from 1 to 0. Quantum discharge requires high reverse voltage applied across the entire sector.

  • To synchronize the microcontroller clock with an NTP server
f_write() buffers data in RAM caches to maximize throughput. If power cuts out before f_sync() or f_close(), unwritten data and directory allocation updates remain in RAM, causing file truncation.

Because flash blocks endure only 10K to 100K erases before oxide degradation causes bit errors, wear leveling maps logical addresses dynamically to ensure all physical blocks wear at equal rates.

  • Executing Python scripts directly in hardware
  • Running code without compiling it first
Using Memory-Mapped Mode on QSPI controllers, external serial flash appears directly inside the 32-bit physical address space (e.g., 0x90000000), allowing instruction execution with transparent cache.
5. How does Dual-Sector EEPROM Emulation handle variable updates without constantly erasing flash sectors?
  • It appends new key-value pairs sequentially into blank words in the active sector; full sector erase only occurs during periodic page transfers
  • It stores all data in volatile CPU core registers
  • It writes data into the microcontroller analog comparator
  • It relies on an external lithium battery to hold RAM states
EEPROM emulation writes new records to consecutive blank addresses. Searching for a variable reads backwards to find the newest entry, deferring sector erasure until the page is 100% exhausted.
6. What is the typical page size limit for a single SPI write operation on standard NOR flash chips like the W25Q32?
  • 256 bytes (writing beyond a 256-byte page wraps around to the beginning of the same page)
  • 16 megabytes
  • 4 kilobytes
  • 1 single bit
SPI NOR flash chips incorporate internal 256-byte SRAM page latches. Writing more than 256 bytes in one command causes the internal address pointer to wrap to the page start, overwriting earlier bytes.
7. What does a cluster in the FAT32 filesystem represent?
  • The fundamental unit of disk allocation composed of a fixed number of contiguous 512-byte sectors
  • A group of networked microcontrollers
  • A collection of 32-bit CPU registers
  • A set of FreeRTOS tasks
FAT32 allocates files in clusters (e.g., 4 KB = 8 sectors). The File Allocation Table tracks files as linked chains of cluster numbers.
8. Why is true EEPROM preferred over Flash for storing real-time automotive odometer values?
  • True EEPROM supports single-byte modification and millions of write cycles without sector erasing overhead
  • True EEPROM is completely immune to high temperatures
  • True EEPROM has larger gigabyte capacities
  • True EEPROM consumes zero current during write cycles
Odometers write frequently (e.g., every 0.1 km). Flash would quickly burn out its 100K endurance limit, whereas true EEPROM withstands 1M to 4M cycles with single-byte granularity.
9. What error occurs if an application attempts to write to a Winbond W25Q flash chip without first issuing command 0x06 (Write Enable)?
  • The chip silently ignores the programming command because its internal Write Enable Latch (WEL) bit is 0
  • The microcontroller triggers a BusFault exception
  • The chip permanently locks its SPI port
  • The Flash chip explodes
NOR flash requires an explicit Write Enable (WREN, 0x06) command before any program or erase command to prevent accidental writes caused by electrical noise on the SPI bus.
10. Which FatFS return code indicates that physical communication with the SD card or flash chip failed at the hardware level?
  • FR_DISK_ERR
  • FR_OK
  • FR_NO_FILE
  • FR_INVALID_NAME
FR_DISK_ERR indicates that the low-level diskio driver returned an error (such as an SPI timeout or CRC check failure) during physical sector read or write operations.
