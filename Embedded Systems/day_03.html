3.1 Memory-Mapped I/O and Peripheral Register Architecture

In modern microcontrollers, physical pins are commanded through General Purpose Input/Output (GPIO) peripheral controllers. Unlike older computing architectures that used dedicated CPU I/O instructions (like x86 IN and OUT), ARM Cortex-M processors interface with hardware via Memory-Mapped I/O (MMIO). Each hardware peripheral has a dedicated memory block in the peripheral address space (0x4000_0000 - 0x5FFF_FFFF). Reading from or writing to these physical memory addresses reads pin states or charges output transistor gates.

Real World Example: In an industrial relay control module, switching a high-voltage AC contactor requires driving a low-side MOSFET gate via a microcontroller GPIO pin. If the GPIO pin defaults to a floating input state at boot, electrical noise can spuriously bias the transistor and energize the contactor. Engineers configure internal pull-down resistors in hardware registers before enabling peripheral drivers.
Figure 1.2-1: STM32 GPIO Port Internal Architectural Schematic
Figure Parameters Explained:
  • P-MOS & N-MOS Transistors: Form the complementary push-pull output driver. P-MOS pulls pin to VDD (logic 1); N-MOS pulls pin to VSS (logic 0).
  • Schmitt Trigger: Converts noisy analog input signals with slow rise times into clean, hysteresis-stabilized digital 0 and 1 states.
  • Internal Pull-Up/Pull-Down: Weak internal resistors (~40k ohm) configurable via PUPDR to prevent pins from floating in high-impedance (Hi-Z) states.
  • Protection Diodes: Clamp input voltages exceeding VDD + 0.3V or falling below VSS - 0.3V to protect internal silicon.

3.2 GPIO Register Set: MODER, OTYPER, OSPEEDR, PUPDR, IDR, ODR, and BSRR

Each GPIO port on an STM32 (e.g., GPIOA, GPIOB) consists of a dedicated 32-bit register block with fixed offset addresses from the port base address:

  • MODER (Mode Register): 2 bits per pin. Configures pin as Input (00), General Purpose Output (01), Alternate Function (10), or Analog (11).
  • OTYPER (Output Type Register): 1 bit per pin. Selects Output Push-Pull (0) or Output Open-Drain (1).
  • OSPEEDR (Output Speed Register): 2 bits per pin. Configures slew rate (Low, Medium, High, Very High) to manage electromagnetic interference (EMI) vs. signal rise time.
  • PUPDR (Pull-Up/Pull-Down Register): 2 bits per pin. Configures No Pull (00), Pull-Up (01), or Pull-Down (10).
  • IDR (Input Data Register): Read-only 32-bit register where bits [15:0] reflect the current logic level of physical pins 0 through 15.
  • ODR (Output Data Register): Read/write register where bits [15:0] drive output levels. However, modifying ODR requires a read-modify-write cycle subject to interrupt race conditions.
  • BSRR (Bit Set/Reset Register): Write-only 32-bit register providing atomic single-cycle bit manipulation without read-modify-write hazards.
Figure 1.2-2: Output Push-Pull vs. Open-Drain Circuit Configurations
Figure Parameters Explained:
  • Push-Pull Output: Actively drives both logic HIGH and LOW states with low output impedance. Ideal for LEDs, push buttons, and high-speed SPI signals.
  • Open-Drain Output: Can only pull the line LOW or leave it floating (Hi-Z). Requires an external or internal pull-up resistor to reach HIGH state.
  • Wired-AND Capability: Multiple open-drain pins can be tied to a single shared bus wire without short-circuit contention (the foundation of I2C).
  • Level Shifting: Open-drain outputs allow a 3.3V microcontroller to interface safely with a 5.0V bus when using a 5V pull-up.

3.3 Atomic Pin Control: Why BSRR Eliminates Race Conditions

Modifying a GPIO pin via the Output Data Register (ODR) requires three machine instructions: Load (LDR), Modify (ORR or BIC), and Store (STR). If a high-priority hardware interrupt occurs between the LDR and STR instructions and modifies a different pin on the same port, the interrupt's modification is silently overwritten when the interrupted code resumes and executes STR!

To eliminate this critical vulnerability, Cortex-M GPIO peripherals incorporate the Bit Set/Reset Register (BSRR). BSRR is divided into two 16-bit halves: writing a 1 to bits [15:0] atomically drives the corresponding pin HIGH; writing a 1 to bits [31:16] atomically drives the pin LOW. Writing 0 has no effect. A single STR instruction sets or clears pins without reading the register first.

Figure 1.2-3: The Read-Modify-Write Race Condition vs. Atomic BSRR Execution
Figure Parameters Explained:
  • ODR Hazard (LDR -> IRQ -> STR): Thread reads ODR=0x00; IRQ fires and sets Pin 1 (ODR=0x02); thread resumes and writes back ODR=0x01, destroying Pin 1 state.
  • BSRR Lower Half (Bits 0-15): Writing a 1 to bit N sets Pin N HIGH. Zeroes are ignored by hardware.
  • BSRR Upper Half (Bits 16-31): Writing a 1 to bit (16+N) resets Pin N LOW atomically.
  • MISRA & Safety Implication: Safety-critical firmware forbids non-atomic ODR writes across shared peripheral ports.

3.4 Button Debouncing: Mechanical Bounce vs. Digital Filtering

Mechanical push buttons and switches consist of flexible metal spring contacts. When pressed or released, the contacts bounce against each other for several milliseconds before settling into steady electrical contact. Because microcontroller clock speeds exceed tens of megahertz, the MCU detects every sub-millisecond bounce as a separate button press, registering 10 to 50 false clicks per actuation.

Figure 1.2-4: Mechanical Switch Contact Bounce Oscilloscope Waveform & Debounce Filter
Figure Parameters Explained:
  • Bounce Window: Typically spans 5 ms to 25 ms depending on mechanical switch quality and aging.
  • Hardware Debouncing: Using an external RC low-pass filter (e.g. 10k resistor + 100nF capacitor) and a Schmitt trigger buffer.
  • Software Polling Filter: Periodically sampling the pin every 10 ms; a state change is only accepted after N consecutive identical samples.
  • Shift-Register Debounce: Shifting raw samples into a uint8_t; button is confirmed PRESSED only when history equals 0xFF.

3.5 Peripheral Clock Gating Architecture

In modern low-power microcontrollers, all peripheral silicon blocks are completely disconnected from the master clock tree upon power-up to conserve dynamic power. If software attempts to read or write a GPIO register before enabling its corresponding clock gate in the Reset and Clock Control (RCC) peripheral, the bus transfer terminates with an unhandled bus error, immediately throwing a HardFault exception!

Figure 1.2-5: RCC Peripheral Bus Clock Gating Distribution Network
Figure Parameters Explained:
  • RCC_AHB1ENR: AHB1 Peripheral Clock Enable Register; bit 0 enables GPIOA, bit 1 enables GPIOB, bit 2 enables GPIOC.
  • Clock Gating Power Savings: Dynamic power is proportional to C * V^2 * f; cutting clock 'f' reduces peripheral power draw to sub-microamp levels.
  • Bus Stall Hazard: Accessing a disabled peripheral register triggers an immediate BusFault or HardFault on Cortex-M processors.

3.6 Hands-On Code Implementations


#include <stdint.h>

#define RCC_AHB1ENR     (*(volatile uint32_t *)0x40023830UL)
#define GPIOA_MODER     (*(volatile uint32_t *)0x40020000UL)
#define GPIOA_ODR       (*(volatile uint32_t *)0x40020014UL)

#define GPIOA_EN        (1UL << 0)
#define LED_PIN         5

static void delay_ms(volatile uint32_t ms) {
    while (ms--) {
        for (volatile uint32_t i = 0; i < 3195; i++) {
            __asm__ volatile("nop");
        }
    }
}

int main(void) {
    /* Step 1: Enable GPIOA clock in RCC */
    RCC_AHB1ENR |= GPIOA_EN;

    /* Step 2: Configure PA5 as Output (MODER5 = 0b01) */
    GPIOA_MODER &= ~(3UL << (LED_PIN * 2));
    GPIOA_MODER |= (1UL << (LED_PIN * 2));

    while (1) {
        GPIOA_ODR ^= (1UL << LED_PIN); /* Toggle LED */
        delay_ms(500);
    }
    return 0;
}
Program 1.2-1: Bare-Metal GPIO Output: Blinking LED via Register Pointers 

#include <stdint.h>

#define RCC_AHB1ENR     (*(volatile uint32_t *)0x40023830UL)
#define GPIOA_MODER     (*(volatile uint32_t *)0x40020000UL)
#define GPIOA_BSRR      (*(volatile uint32_t *)0x40020018UL)

#define LED_PIN         5

/* Atomic Set and Reset Functions */
static inline void gpio_pin_set(volatile uint32_t *bsrr, uint8_t pin) {
    *bsrr = (1UL << pin);          /* Writes to lower 16 bits */
}

static inline void gpio_pin_reset(volatile uint32_t *bsrr, uint8_t pin) {
    *bsrr = (1UL << (pin + 16));   /* Writes to upper 16 bits */
}

int main(void) {
    RCC_AHB1ENR |= (1UL << 0);
    GPIOA_MODER &= ~(3UL << (LED_PIN * 2));
    GPIOA_MODER |= (1UL << (LED_PIN * 2));

    while (1) {
        gpio_pin_set(&GPIOA_BSRR, LED_PIN);   /* Turn ON */
        for (volatile int i = 0; i < 500000; i++);

        gpio_pin_reset(&GPIOA_BSRR, LED_PIN); /* Turn OFF */
        for (volatile int i = 0; i < 500000; i++);
    }
    return 0;
}
Program 1.2-2: Atomic Pin Control using GPIO BSRR (Thread-Safe & ISR-Safe) 

#include <stdint.h>
#include <stdbool.h>

#define RCC_AHB1ENR     (*(volatile uint32_t *)0x40023830UL)
#define GPIOA_MODER     (*(volatile uint32_t *)0x40020000UL)
#define GPIOA_BSRR      (*(volatile uint32_t *)0x40020018UL)
#define GPIOC_MODER     (*(volatile uint32_t *)0x40020800UL)
#define GPIOC_PUPDR     (*(volatile uint32_t *)0x4002080CUL)
#define GPIOC_IDR       (*(volatile uint32_t *)0x40020810UL)

#define LED_PIN         5   /* PA5 */
#define BUTTON_PIN      13  /* PC13 (Active-Low User Button on Nucleo) */

int main(void) {
    /* Enable GPIOA and GPIOC peripheral clocks */
    RCC_AHB1ENR |= (1UL << 0) | (1UL << 2);

    /* PA5 as Output */
    GPIOA_MODER &= ~(3UL << (LED_PIN * 2));
    GPIOA_MODER |= (1UL << (LED_PIN * 2));

    /* PC13 as Input with Pull-Up resistor (PUPDR = 0b01) */
    GPIOC_MODER &= ~(3UL << (BUTTON_PIN * 2));
    GPIOC_PUPDR &= ~(3UL << (BUTTON_PIN * 2));
    GPIOC_PUPDR |= (1UL << (BUTTON_PIN * 2));

    while (1) {
        /* Read pin state from IDR (Active-Low: Pressed = 0, Released = 1) */
        bool is_pressed = ((GPIOC_IDR & (1UL << BUTTON_PIN)) == 0);

        if (is_pressed) {
            GPIOA_BSRR = (1UL << LED_PIN);        /* LED ON */
        } else {
            GPIOA_BSRR = (1UL << (LED_PIN + 16)); /* LED OFF */
        }
    }
    return 0;
}
Program 1.2-3: Bare-Metal Push Button Input with Internal Pull-Up Resistor 

#include <stdint.h>
#include <stdbool.h>

typedef struct {
    uint8_t history;
    bool current_state;
    bool edge_detected;
} DebouncedButton_t;

/* Run every 5ms from a timer tick interrupt */
void button_debounce_update(DebouncedButton_t *btn, bool raw_sample) {
    /* Shift current history left and append new raw sample */
    btn->history = (btn->history << 1) | (raw_sample ? 1 : 0);
    btn->edge_detected = false;

    /* 8 consecutive 0s = Confirmed Pressed (Active-Low) */
    if (btn->history == 0x00 && !btn->current_state) {
        btn->current_state = true;
        btn->edge_detected = true; /* Rising edge of press event */
    }
    /* 8 consecutive 1s = Confirmed Released */
    else if (btn->history == 0xFF && btn->current_state) {
        btn->current_state = false;
    }
}
Program 1.2-4: Robust Shift-Register Button Debouncing Engine 

#include <stdint.h>

#define RCC_AHB1ENR     (*(volatile uint32_t *)0x40023830UL)
#define GPIOB_MODER     (*(volatile uint32_t *)0x40020400UL)
#define GPIOB_ODR       (*(volatile uint32_t *)0x40020414UL)

static void delay(volatile uint32_t n) {
    while (n--) __asm__ volatile("nop");
}

int main(void) {
    /* Enable GPIOB clock */
    RCC_AHB1ENR |= (1UL << 1);

    /* Configure GPIOB pins 0 through 7 as Outputs (MODER bits [15:0] = 0x5555) */
    GPIOB_MODER &= ~(0xFFFFUL);
    GPIOB_MODER |= 0x5555UL;

    uint8_t pattern = 0x01;
    bool forward = true;

    while (1) {
        /* Write lower 8 bits to GPIOB ODR */
        GPIOB_ODR = (GPIOB_ODR & ~0xFFUL) | pattern;
        delay(150000);

        if (forward) {
            pattern <<= 1;
            if (pattern == 0x80) forward = false;
        } else {
            pattern >>= 1;
            if (pattern == 0x01) forward = true;
        }
    }
    return 0;
}

1. What happens if firmware attempts to write to GPIOA_MODER before enabling the GPIOA clock in RCC_AHB1ENR?
  • The write succeeds silently but the pin does not output voltage
  • The CPU triggers an immediate BusFault or HardFault exception due to unclocked bus access

  • The compiler issues a warning at compile time
Accessing registers of an unclocked peripheral violates bus protocol rules, causing the bus matrix to signal a bus transfer error, triggering a HardFault.
2. Why is writing to GPIO BSRR preferred over modifying GPIO ODR in safety-critical firmware?
  • BSRR provides faster analog conversions
  • BSRR operates atomically in a single write instruction, eliminating read-modify-write race conditions
  • BSRR automatically enables the peripheral clock
  • BSRR consumes half the power of ODR
ODR requires a non-atomic read-modify-write sequence. If an interrupt occurs midway, updates to neighboring pins can be overwritten. BSRR writes atomically in one cycle.
3. To reset pin 7 LOW on GPIOA using the BSRR register, which bit in GPIOA_BSRR must be set to 1?
  • Bit 7
  • Bit 15
  • Bit 23 (7 + 16)
  • Bit 31
BSRR uses bits [15:0] for setting pins HIGH and bits [31:16] for resetting pins LOW. Pin 7 reset corresponds to bit 7 + 16 = 23.
4. What is the primary difference between a Push-Pull output and an Open-Drain output?
  • Push-pull can only drive ground; open-drain drives 5V
  • Push-pull actively drives both HIGH and LOW; open-drain can only pull LOW or float Hi-Z
  • Open-drain has higher maximum switching frequency
  • Push-pull requires an external pull-up resistor
In Push-Pull mode, complementary P-MOS and N-MOS transistors actively drive high and low. Open-Drain only activates the N-MOS to pull low, requiring an external pull-up for high.
5. How many bits in GPIO_MODER are dedicated to configuring the mode of each physical pin?
  • 1 bit
  • 2 bits
  • 4 bits
  • 8 bits
MODER allocates 2 bits per pin to represent 4 states: 00 = Input, 01 = General Output, 10 = Alternate Function, and 11 = Analog.
6. Why does a mechanical push button require debouncing in embedded firmware?
  • Because the button coil generates back-EMF
  • Because mechanical contacts physically bounce for 5-25 ms, creating multiple false digital edges
  • To reduce current draw through the internal pull-up resistor
  • Because Cortex-M processors cannot read inputs faster than 10 Hz
Mechanical contacts oscillate rapidly upon closure before making solid contact, causing an MCU running at millions of cycles per second to detect dozens of false presses.
7. What configuration prevents an unconnected input pin from picking up ambient electromagnetic noise and floating randomly?
  • Setting output speed to Very High
  • Enabling internal Pull-Up or Pull-Down resistors in PUPDR
  • Setting the pin to Open-Drain output
  • Disabling the Schmitt trigger
Internal pull-up or pull-down resistors provide a weak electrical reference to VDD or Ground, preventing high-impedance floating states.
8. Which GPIO register reflects the real-time physical logic levels present on the external microcontroller pins?
  • GPIOx_ODR
  • GPIOx_IDR
  • GPIOx_BSRR
  • GPIOx_AFR
The Input Data Register (IDR) is a read-only register that latches the synchronized digital logic levels from external pins through the Schmitt trigger.
9. What is the consequence of configuring a GPIO output with excessive slew rate (OSPEEDR = Very High) for a low-speed 1 kHz LED signal?
  • The LED burns out from excessive current
  • It generates unnecessary high-frequency electromagnetic interference (EMI) and power rail noise
  • It causes the timer prescaler to reset
  • It corrupts the Flash memory vector table
Higher slew rates create sharp current spikes (high di/dt), producing electromagnetic radiation and power rail ground bounce without providing any benefit for low-frequency signals.
10. In the shift-register debouncing pattern `btn->history = (btn->history << 1) | sample;`, how many consecutive matching samples are confirmed by `0xFF`?
  • 4 samples
  • 8 samples
  • 16 samples
  • 32 samples
A uint8_t holds 8 bits. An exact value of 0xFF (binary 11111111) confirms that all 8 most recent periodic samples were identical logic 1s.
