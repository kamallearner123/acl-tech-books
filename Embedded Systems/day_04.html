4.1 The Event-Driven Paradigm vs. Busy Polling

In elementary embedded programming, firmware developers write superloops that continuously query (poll) status registers to detect external events (such as a button press, an incoming serial byte, or an ADC conversion complete flag). While simple, busy-wait polling is inherently flawed: it consumes 100% of CPU processing bandwidth, prevents the processor from entering low-power sleep modes, introduces unbounded response latency if the CPU is busy executing other routines, and risks missing transient hardware pulses entirely.

Professional embedded systems are Interrupt-Driven and Event-Driven. The CPU executes background tasks or sleeps in low-power mode (WFI). When a physical event occurs, dedicated peripheral hardware signals the CPU core, which automatically suspends the current thread, saves its state, executes an Interrupt Service Routine (ISR) to handle the event within microseconds, and seamlessly resumes background execution.

Real World Example: An automated external defibrillator (AED) uses a high-priority hardware interrupt attached to an electrocardiogram (ECG) analog front-end. When ventricular fibrillation is detected, an interrupt immediately preempts UI display rendering, charging high-voltage capacitors and priming defibrillator shock delivery within milliseconds.
Figure 1.3-1: ARM Cortex-M Hardware Context Stacking and ISR Entry Sequence
Figure Parameters Explained:
  • Hardware Stacking (12 Cycles): The Cortex-M core saves 8 registers automatically without executing any software instructions, drastically reducing ISR latency.
  • xPSR (Program Status Register): Saves condition code flags (Negative, Zero, Carry, Overflow) and execution state.
  • EXC_RETURN Magic Value: Special value loaded into the Link Register (LR) that instructs CPU hardware how to unstack registers when returning from an exception.
  • Tail-Chaining (6 Cycles): If another interrupt is pending when an ISR exits, the CPU skips restoring and re-stacking registers, transitioning directly to the next ISR in just 6 clock cycles.

4.2 Nested Vectored Interrupt Controller (NVIC) & Priority Grouping

The Nested Vectored Interrupt Controller (NVIC) is an integral, tightly coupled silicon component of the ARM Cortex-M processor core. It manages all internal exceptions (SysTick, PendSV, HardFault) and up to 240 external peripheral interrupt lines (IRQs). Key architectural features include:

  • Vectored Architecture: The hardware directly fetches the specific ISR address from the vector table; no software dispatch tables or polling cascades are needed.
  • Preemption: A higher-priority interrupt can preempt (suspend) an already executing lower-priority ISR.
  • Priority Grouping: The 8-bit priority byte for each IRQ can be split into Preemption Priority (which determines preemption nesting) and Sub-Priority (which resolves ties if two interrupts arrive simultaneously).
  • Numerical Priority Rule: In ARM Cortex-M, lower numerical values denote higher logical priorities (Priority 0 is the highest configurable priority; Priority 15 is lower).
Figure 1.3-2: NVIC Priority Grouping Configuration and Preemption Hierarchy
Figure Parameters Explained:
  • SCB->AIRCR PRIGROUP: Application Interrupt and Reset Control Register; sets the boundary split between preemption and sub-priority fields.
  • Preemption Priority: If an incoming IRQ has a higher preemption priority than the currently running ISR, it preempts execution immediately.
  • Sub-Priority: Does NOT allow preemption; only decides which pending interrupt executes first if multiple IRQs trigger at the same time.
  • Active Priority Level: NVIC hardware tracks active interrupt levels to guarantee deterministic nesting depth.

4.3 External Interrupts: EXTI Architecture and Line Multiplexing

To detect physical voltage transitions on external GPIO pins (such as button presses, encoder ticks, or sensor alarms), microcontrollers use an External Interrupt / Event Controller (EXTI). On STM32 microcontrollers, 16 EXTI lines (EXTI0 to EXTI15) correspond to pin numbers 0 through 15 across all ports. However, because each EXTI line can only connect to one physical pin at a time, a SYSCFG Multiplexer routes which port (PA, PB, PC, etc.) owns the line.

Figure 1.3-3: STM32 SYSCFG EXTI Multiplexer Routing Topology
Figure Parameters Explained:
  • SYSCFG_EXTICR: System Configuration External Interrupt Configuration Register; selects port pin source for each EXTI line.
  • EXTI_RTSR: Rising Trigger Selection Register; enables interrupt generation on 0-to-1 voltage transitions.
  • EXTI_FTSR: Falling Trigger Selection Register; enables interrupt generation on 1-to-0 voltage transitions.
  • EXTI_PR (Pending Register): Flags pending interrupts; the ISR MUST clear this bit by writing a 1 to it before exiting, or the ISR will trigger in an infinite loop!

4.4 ISR Design Best Practices & Critical Sections

Interrupt Service Routines run in Privileged Handler mode with high urgency. Writing poorly designed ISRs can destabilize an entire embedded system. Professional firmware engineers adhere to strict rules:

  1. Keep ISRs Extremely Short: Acknowledge the hardware flag, copy volatile data into a buffer or set a state flag, and exit. Do not execute heavy mathematical filtering or blocking loops inside an ISR.
  2. Never Call Blocking Functions: Do not call delay(), printf(), or blocking I2C/SPI transactions inside an ISR.
  3. Protect Shared Variables with Critical Sections: If both the main superloop and an ISR read/write a shared multi-byte variable (such as a 32-bit timestamp or circular buffer index), wrap the main-thread access in a Critical Section (__disable_irq() / __enable_irq()) to prevent partial read/write corruption.
  4. Mandatory volatile: Any global variable written by an ISR and read by main must be declared volatile.
Figure 1.3-4: Shared State Race Condition Between Main Superloop and ISR
Figure Parameters Explained:
  • Atomicity Vulnerability: On 8-bit or 16-bit systems (or unaligned 32-bit accesses), reading multi-byte variables requires multiple machine instructions subject to interruption.
  • Critical Section: Temporarily masking interrupts via PRIMASK ensures multi-instruction read-modify-write sequences complete without interruption.
  • Interrupt Latency Trade-Off: Critical sections must be kept as short as possible (&lt; 2 microseconds) to avoid starving high-priority real-time hardware interrupts.
  • PRIMASK Register: 1-bit register; when set (via CPSID i), masks all interrupts except NMI and HardFault.

4.5 Nested Interrupt Preemption in Action

When multiple interrupts occur in real-time systems, the NVIC executes them according to their configured preemption priority. If a lower-priority interrupt (e.g. UART RX) is executing and a higher-priority interrupt (e.g. Motor Fault EXTI) triggers, the CPU suspends the UART ISR, stacks its context, executes the Motor Fault ISR, and upon completion returns to resume the UART ISR seamlessly.

Figure 1.3-5: Nested Interrupt Execution and Preemption Timeline
Figure Parameters Explained:
  • Preemption Depth: Hardware stack depth increases with each nested preemption layer; stack must be sized to accommodate worst-case simultaneous ISR nesting.
  • Late-Arrival Optimization: If a higher-priority interrupt arrives while the CPU is still stacking for a lower-priority interrupt, the CPU seamlessly switches to the higher-priority ISR without re-stacking.
  • Pending State: If an interrupt arrives that has equal or lower preemption priority than the current ISR, it is marked pending in NVIC until the active ISR exits.

#include <stdint.h>
#include <stdbool.h>

/* Register Base Addresses */
#define RCC_BASE        0x40023800UL
#define GPIOA_BASE      0x40020000UL
#define GPIOC_BASE      0x40020800UL
#define SYSCFG_BASE     0x40013800UL
#define EXTI_BASE       0x40013C00UL
#define NVIC_BASE       0xE000E100UL

/* RCC Clock Registers */
#define RCC_AHB1ENR     (*(volatile uint32_t *)(RCC_BASE + 0x30UL))
#define RCC_APB2ENR     (*(volatile uint32_t *)(RCC_BASE + 0x44UL))

/* GPIO Registers */
#define GPIOA_MODER     (*(volatile uint32_t *)(GPIOA_BASE + 0x00UL))
#define GPIOA_ODR       (*(volatile uint32_t *)(GPIOA_BASE + 0x14UL))
#define GPIOC_MODER     (*(volatile uint32_t *)(GPIOC_BASE + 0x00UL))
#define GPIOC_PUPDR     (*(volatile uint32_t *)(GPIOC_BASE + 0x0CUL))

/* SYSCFG and EXTI Registers */
#define SYSCFG_EXTICR4  (*(volatile uint32_t *)(SYSCFG_BASE + 0x14UL))
#define EXTI_IMR        (*(volatile uint32_t *)(EXTI_BASE + 0x00UL))
#define EXTI_FTSR       (*(volatile uint32_t *)(EXTI_BASE + 0x0CUL))
#define EXTI_PR         (*(volatile uint32_t *)(EXTI_BASE + 0x14UL))

/* NVIC Interrupt Set-Enable Register */
#define NVIC_ISER1      (*(volatile uint32_t *)(NVIC_BASE + 0x04UL)) /* IRQ 32-63 */
#define EXTI15_10_IRQn  40 /* IRQ number for EXTI lines 10-15 */

/* Shared Volatile Flag */
static volatile bool g_button_event = false;

/* Interrupt Service Routine for PC13 Button */
void EXTI15_10_IRQHandler(void) {
    /* Check if EXTI line 13 triggered the interrupt */
    if (EXTI_PR & (1UL << 13)) {
        /* CRITICAL: Clear pending bit by writing a 1 to it */
        EXTI_PR = (1UL << 13);
        g_button_event = true;
    }
}

int main(void) {
    /* 1. Enable clocks for GPIOA, GPIOC, and SYSCFG */
    RCC_AHB1ENR |= (1UL << 0) | (1UL << 2);
    RCC_APB2ENR |= (1UL << 14); /* SYSCFG clock */

    /* 2. Configure PA5 as Output (LED) */
    GPIOA_MODER &= ~(3UL << 10);
    GPIOA_MODER |= (1UL << 10);

    /* 3. Configure PC13 as Input with Pull-Up */
    GPIOC_MODER &= ~(3UL << 26);
    GPIOC_PUPDR &= ~(3UL << 26);
    GPIOC_PUPDR |= (1UL << 26);

    /* 4. Route PC13 to EXTI Line 13 via SYSCFG_EXTICR4 */
    SYSCFG_EXTICR4 &= ~(0xFUL << 4);
    SYSCFG_EXTICR4 |= (0x2UL << 4); /* 0b0010 selects Port C */

    /* 5. Configure Falling-Edge Trigger on EXTI Line 13 */
    EXTI_IMR |= (1UL << 13);  /* Unmask Line 13 */
    EXTI_FTSR |= (1UL << 13); /* Falling edge trigger */

    /* 6. Enable EXTI15_10_IRQn in NVIC */
    NVIC_ISER1 = (1UL << (EXTI15_10_IRQn - 32));

    while (1) {
        if (g_button_event) {
            g_button_event = false;
            GPIOA_ODR ^= (1UL << 5); /* Toggle LED */
        }
        __asm__ volatile("wfi"); /* Enter sleep mode until next interrupt */
    }
    return 0;
}

#include <stdint.h>

/* SysTick Core Peripheral Registers */
#define SysTick_BASE    0xE000E010UL
#define SysTick_CTRL    (*(volatile uint32_t *)(SysTick_BASE + 0x00UL))
#define SysTick_LOAD    (*(volatile uint32_t *)(SysTick_BASE + 0x04UL))
#define SysTick_VAL     (*(volatile uint32_t *)(SysTick_BASE + 0x08UL))

#define SysTick_CTRL_ENABLE     (1UL << 0)
#define SysTick_CTRL_TICKINT    (1UL << 1)
#define SysTick_CTRL_CLKSOURCE  (1UL << 2)

static volatile uint32_t g_system_ticks_ms = 0;

/* SysTick Exception Handler: Executes every 1 millisecond */
void SysTick_Handler(void) {
    g_system_ticks_ms++;
}

void systick_init_1ms(uint32_t cpu_freq_hz) {
    /* Reload value = (Clock Frequency / 1000) - 1 */
    SysTick_LOAD = (cpu_freq_hz / 1000UL) - 1UL;
    SysTick_VAL  = 0UL; /* Clear current counter */
    SysTick_CTRL = SysTick_CTRL_CLKSOURCE | SysTick_CTRL_TICKINT | SysTick_CTRL_ENABLE;
}

uint32_t get_millis(void) {
    /* Atomic read: single 32-bit load is atomic on Cortex-M */
    return g_system_ticks_ms;
}

void delay_nonblocking_ms(uint32_t duration_ms) {
    uint32_t start = get_millis();
    while ((get_millis() - start) < duration_ms) {
        __asm__ volatile("wfi"); /* Sleep between ticks */
    }
}
Program 1.3-2: SysTick Periodic Tick Timer & Non-Blocking Millisecond Delay 

#include <stdint.h>

/* Assembly instructions for interrupt masking */
static inline uint32_t enter_critical_section(void) {
    uint32_t primask;
    /* Read current PRIMASK register state */
    __asm__ volatile("mrs %0, primask" : "=r" (primask));
    /* Disable all configurable interrupts */
    __asm__ volatile("cpsid i" : : : "memory");
    return primask;
}

static inline void exit_critical_section(uint32_t prev_primask) {
    /* Restore prior PRIMASK state (supports nested critical sections) */
    __asm__ volatile("msr primask, %0" : : "r" (prev_primask) : "memory");
}

/* Multi-byte sensor calibration struct shared between ISR and main loop */
typedef struct {
    int32_t x_offset;
    int32_t y_offset;
    int32_t z_offset;
    uint32_t checksum;
} SensorCalibration_t;

static SensorCalibration_t g_calib;

void update_calibration_safely(const SensorCalibration_t *new_calib) {
    uint32_t key = enter_critical_section();
    
    /* Atomically update multi-word structure without ISR interruption */
    g_calib = *new_calib;
    
    exit_critical_section(key);
}
Program 1.3-3: Critical Section Implementation via CPU PRIMASK Register 

#include <stdint.h>

#define SCB_AIRCR       (*(volatile uint32_t *)0xE000ED0CUL)
#define NVIC_IPR_BASE   0xE000E400UL /* Interrupt Priority Registers */
#define NVIC_IPR(irq)   (*(volatile uint8_t *)(NVIC_IPR_BASE + (irq)))

#define AIRCR_VECTKEY       (0x5FAUL << 16)
#define AIRCR_PRIGROUP_POS  8

/* Configure priority grouping: 4 bits Preemption, 0 bits Sub-Priority */
void nvic_priority_group_init(void) {
    /* PRIGROUP = 0b011 (Group 3): Bits [7:4] Preemption, Bits [3:0] Sub-priority */
    SCB_AIRCR = AIRCR_VECTKEY | (3UL << AIRCR_PRIGROUP_POS);
}

void set_irq_priority(uint8_t irq_num, uint8_t preemption_prio) {
    /* Cortex-M4 typically implements upper 4 bits of priority byte */
    NVIC_IPR(irq_num) = (preemption_prio & 0x0F) << 4;
}

void configure_system_priorities(void) {
    nvic_priority_group_init();
    
    /* Emergency stop interrupt: Highest Preemption Priority (0) */
    set_irq_priority(6, 0);  /* EXTI0_IRQn */
    
    /* UART Communication: Medium Priority (2) */
    set_irq_priority(38, 2); /* USART2_IRQn */
    
    /* SysTick periodic scheduler: Low Priority (3) */
    set_irq_priority(15, 3);
}

#define IWDG_PR         (*(volatile uint32_t *)(IWDG_BASE + 0x04UL))
#define IWDG_RLR        (*(volatile uint32_t *)(IWDG_BASE + 0x08UL))
#define IWDG_SR         (*(volatile uint32_t *)(IWDG_BASE + 0x0CUL))

#define IWDG_KEY_RELOAD 0x0000AAAAUL
#define IWDG_KEY_ENABLE 0x0000CCCCUL
#define IWDG_KEY_WRITE  0x00005555UL

/* Initialize Watchdog for 500 ms timeout using 32 kHz Low-Speed Internal (LSI) clock */
void watchdog_init_500ms(void) {
    IWDG_KR = IWDG_KEY_ENABLE; /* Start watchdog counter */
    IWDG_KR = IWDG_KEY_WRITE;  /* Enable register access */
    
    /* Prescaler = 32 (32 kHz / 32 = 1 kHz tick rate -> 1 ms per count) */
    IWDG_PR = 0x03; 
    
    /* Reload value = 500 counts (500 ms timeout) */
    IWDG_RLR = 500; 
    
    /* Reload counter */
    IWDG_KR = IWDG_KEY_RELOAD;
}

void watchdog_kick(void) {
    /* Must be called periodically by the main superloop before timeout expires */
    IWDG_KR = IWDG_KEY_RELOAD;
}

Topic Quiz (10 Questions)

Test your conceptual understanding of today's embedded systems architecture, registers, and runtime behaviors.

1. What happens if software fails to clear the pending bit in EXTI_PR inside an External Interrupt ISR?
  • The interrupt is disabled automatically by the NVIC
  • The ISR immediately re-triggers upon exit, permanently hanging the processor in an infinite ISR loop
  • A UsageFault exception is generated
  • The peripheral clock is gated off
If EXTI_PR is not cleared, the NVIC still sees the interrupt line asserted upon returning from the ISR, re-entering the handler immediately.
2. In ARM Cortex-M interrupt priority architectures, which statement is true?
  • Higher numerical values represent higher logical execution priority
  • Lower numerical values represent higher logical execution priority (0 is highest)
  • Priority 255 is the non-maskable interrupt priority
  • All peripheral interrupts have identical fixed priority
ARM Cortex-M processors use inverted numerical priority where priority 0 is the highest configurable priority and higher numbers represent lower priorities.
3. How many clock cycles does an ARM Cortex-M4 processor take to save its context onto the stack during interrupt entry?
  • 1 cycle
  • 6 cycles
  • 12 cycles
  • 48 cycles
Cortex-M4 hardware context stacking takes exactly 12 clock cycles to push the 8 basic registers (R0-R3, R12, LR, PC, xPSR) to memory.
4. What optimization allows Cortex-M cores to transition from one ISR to another in only 6 cycles without restoring and re-stacking registers?
  • Late-arrival preemption
  • Tail-chaining
  • Branch target prediction
  • Direct Memory Access
Tail-chaining allows the processor to skip unstacking registers and immediately jump to another pending interrupt handler in just 6 cycles.
5. What is the primary role of the PendSV exception in embedded Real-Time Operating Systems (RTOS)?
  • High-precision PWM signal generation
  • Executing context switches at the lowest priority so other real-time ISRs are not delayed
  • Monitoring battery voltage thresholds
  • Resetting the watchdog timer
PendSV (Pended Service Call) is configured to the lowest priority level so that context switches occur only after all hardware ISRs finish.
6. Why is calling `printf()` inside an Interrupt Service Routine considered a critical anti-pattern?
  • Because printf is not compatible with ARM Cortex-M processors
  • Because printf is non-reentrant, heavily blocking, and drastically inflates interrupt latency
  • Because printf requires floating point hardware
  • Because it clears the NVIC pending registers
printf involves character formatting and slow serial transmission, stalling the CPU inside the ISR and starving other urgent system interrupts.
7. What is the purpose of nested critical section implementations saving and restoring the PRIMASK register?
  • To allow functions with critical sections to be called from inside other critical sections without prematurely re-enabling interrupts
  • To increase the system clock speed
  • To clear the watchdog timer automatically
  • To save battery power during sleep
Saving the prior PRIMASK state ensures that an inner critical section does not inadvertently re-enable interrupts if the outer calling function still expects interrupts to remain disabled.
8. Which peripheral multiplexer links external GPIO pin 13 on Port C to EXTI Line 13 on STM32 microcontrollers?
  • RCC_CFGR
  • SYSCFG_EXTICR4
  • GPIO_AFR
  • NVIC_ISER0
EXTI lines 12 through 15 are configured using SYSCFG_EXTICR4. Writing 0b0010 to bits [7:4] selects Port C for EXTI line 13.
9. What is the consequence of failing to refresh (kick) the Independent Watchdog (IWDG) before its reload counter reaches zero?
  • The MCU generates a Non-Maskable Interrupt (NMI)
  • The hardware triggers an immediate system reset to recover from software lockup
  • The MCU enters deep sleep mode
  • The flash memory is erased
The IWDG is a hardware safety timer clocked independently from the main CPU clock. If software hangs and fails to reload it, the MCU resets automatically.
10. What value in the Link Register (LR) indicates to the CPU that it is returning from an exception using the Main Stack Pointer (MSP)?
  • 0x00000000
  • 0xFFFFFFFF
  • 0xFFFFFFF9
  • 0x12345678
EXC_RETURN values start with 0xFFFFFFF... A value of 0xFFFFFFF9 indicates return to Handler mode using the Main Stack Pointer.
