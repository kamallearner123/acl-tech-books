24.1 Grand Capstone: The Modern Automotive Diagnostic Subsystem

Modern passenger and commercial vehicles are complex distributed networks containing between 50 and 120 interconnected Electronic Control Units (ECUs)—managing powertrain, transmission, anti-lock braking (ABS), advanced driver assistance (ADAS), and battery management (BMS). When an instrument cluster illuminates the 'Check Engine' MIL indicator, technicians query the vehicle using standardized diagnostic protocols operating over the internal Controller Area Network (CAN) bus.

24.2 OBD-II (SAE J1979) Protocol and Parameter IDs (PIDs)

The standard On-Board Diagnostics II (OBD-II / SAE J1979) protocol specifies how diagnostic tools query live sensor data from engine and transmission ECUs. Requests are broadcast on the standard functional CAN ID 0x7DF. Responding ECUs (such as the Engine Control Module at 0x7E8) reply with the requested Mode (Service) + 0x40 and the requested Parameter ID (PID).

Figure 24.0-2: OBD-II CAN Request and Response Frame Structure (PID 0x0C Engine RPM)
Figure Parameters Explained:
  • Length Byte (0x02 / 0x04): First byte declares the number of valid ISO 15765-2 single-frame diagnostic payload bytes.
  • Service Mode (0x01 / 0x41): Mode 01 = Show Current Data; response sets bit 6 (0x01 + 0x40 = 0x41).
  • Parameter ID (PID 0x0C): Standard PID 0x0C represents Engine Speed (RPM).
  • Numeric Formula: Formula $\frac{(A \times 256) + B}{4}$ decodes 16-bit raw integer into physical engine revolutions per minute.

#include <stdint.h>
#include <stdbool.h>

#define OBD_FUNCTIONAL_REQ_ID   0x7DFU
#define OBD_ENGINE_RESP_ID      0x7E8U

#define OBD_MODE_CURRENT_DATA   0x01U
#define OBD_PID_COOLANT_TEMP    0x05U
#define OBD_PID_ENGINE_RPM      0x0CU
#define OBD_PID_VEHICLE_SPEED   0x0DU
#define OBD_PID_THROTTLE_POS    0x11U

typedef struct {
    uint16_t engine_rpm;        /* Revolutions per minute */
    uint8_t  vehicle_speed_kph; /* km/h */
    int8_t   coolant_temp_degc; /* -40 to +215 deg C */
    uint8_t  throttle_pct;      /* 0 to 100 % */
} ObdLiveMetrics_t;

typedef struct {
    uint32_t id;
    uint8_t  dlc;
    uint8_t  data[8];
} CanMessage_t;

extern void can_transmit_frame(const CanMessage_t *frame);

void obd_query_pid(uint8_t pid) {
    CanMessage_t req;
    req.id = OBD_FUNCTIONAL_REQ_ID;
    req.dlc = 8;
    req.data[0] = 0x02; /* 2 bytes follow */
    req.data[1] = OBD_MODE_CURRENT_DATA;
    req.data[2] = pid;
    for (int i = 3; i < 8; i++) req.data[i] = 0x55; /* Padding */

    can_transmit_frame(&req);
}

bool obd_parse_response(const CanMessage_t *resp, ObdLiveMetrics_t *metrics) {
    if (resp->id != OBD_ENGINE_RESP_ID) return false;
    if (resp->data[1] != (OBD_MODE_CURRENT_DATA + 0x40U)) return false;

    uint8_t pid = resp->data[2];

    switch (pid) {
        case OBD_PID_ENGINE_RPM: {
            uint16_t a = resp->data[3];
            uint16_t b = resp->data[4];
            metrics->engine_rpm = (uint16_t)(((a * 256U) + b) / 4U);
            return true;
        }

        case OBD_PID_VEHICLE_SPEED: {
            metrics->vehicle_speed_kph = resp->data[3]; /* A = km/h */
            return true;
        }

        case OBD_PID_COOLANT_TEMP: {
            metrics->coolant_temp_degc = (int8_t)((int16_t)resp->data[3] - 40); /* A - 40 */
            return true;
        }

        case OBD_PID_THROTTLE_POS: {
            metrics->throttle_pct = (uint8_t)(((uint16_t)resp->data[3] * 100U) / 255U); /* A * 100 / 255 */
            return true;
        }

        default:
            return false;
    }
}

24.3 ISO 14229 Unified Diagnostic Services (UDS) and ISO-TP (ISO 15765-2)

Beyond standard emissions OBD-II, modern automotive systems implement ISO 14229 (UDS) for dealership-level diagnostics. Services include:

  • Service 0x22 (ReadDataByIdentifier): Queries manufacturer-specific Data Identifiers (DIDs), such as reading the 17-character Vehicle Identification Number (VIN) under DID 0xF190.
  • Service 0x19 (ReadDTCInformation): Retrieves active, pending, and confirmed Diagnostic Trouble Codes.
  • Service 0x14 (ClearDiagnosticInformation): Erases stored fault codes and resets freeze frame black-box data.
Because payloads frequently exceed the 8-byte limit of standard CAN frames, messages are segmented using ISO 15765-2 (ISO-TP) transport protocol frames: Single Frame (SF), First Frame (FF), Flow Control (FC), and Consecutive Frames (CF).

Figure 24.0-3: ISO 15765-2 (ISO-TP) Multi-Frame Transmission Sequence
Figure Parameters Explained:
  • Single Frame (SF - 0x0N): Used for requests and responses that fit within 7 payload bytes.
  • First Frame (FF - 0x1NNN): Sent by ECU when response length exceeds 7 bytes; specifies 12-bit total message byte count.
  • Flow Control (FC - 0x30): Sent by tester to throttle transmission, specifying Block Size (BS) and Separation Time (STmin).
  • Consecutive Frame (CF - 0x2N): Carries remaining payload chunks with a 4-bit rolling sequence index (0 to 15).

#include <stdint.h>
#include <stdbool.h>
#include <string.h>

#define UDS_REQ_ID              0x7E0U
#define UDS_RESP_ID             0x7E8U
#define UDS_SERVICE_READ_DID    0x22U
#define DID_VIN                 0xF190U

typedef struct {
    uint8_t  vin_str[18]; /* 17 ASCII chars + null */
    uint8_t  bytes_received;
    uint8_t  expected_length;
    bool     vin_complete;
} UdsVinReceiver_t;

extern void can_transmit_frame(const CanMessage_t *frame);

void uds_request_vin(void) {
    CanMessage_t req;
    req.id = UDS_REQ_ID;
    req.dlc = 8;
    req.data[0] = 0x03; /* 3 bytes follow */
    req.data[1] = UDS_SERVICE_READ_DID;
    req.data[2] = (uint8_t)(DID_VIN >> 8);
    req.data[3] = (uint8_t)(DID_VIN & 0xFF);
    for (int i = 4; i < 8; i++) req.data[i] = 0xAA;

    can_transmit_frame(&req);
}

void uds_send_flow_control(void) {
    CanMessage_t fc;
    fc.id = UDS_REQ_ID;
    fc.dlc = 8;
    fc.data[0] = 0x30; /* Flow Control: Continue to send (CTS) */
    fc.data[1] = 0x00; /* Block size = 0 (send all without pause) */
    fc.data[2] = 0x0A; /* STmin = 10 ms separation time */
    for (int i = 3; i < 8; i++) fc.data[i] = 0xAA;

    can_transmit_frame(&fc);
}

void uds_process_isotp_frame(const CanMessage_t *frame, UdsVinReceiver_t *rec) {
    uint8_t pci = frame->data[0] >> 4; /* Protocol Control Information */

    if (pci == 0x1) { /* First Frame (FF) */
        uint16_t total_len = ((uint16_t)(frame->data[0] & 0x0F) << 8) | frame->data[1];
        rec->expected_length = (uint8_t)total_len;
        rec->bytes_received = 0;

        /* Verify response is positive response to 0x22 0xF190 */
        if (frame->data[2] == 0x62 && frame->data[3] == 0xF1 && frame->data[4] == 0x90) {
            /* Copy first 3 VIN ASCII bytes from FF */
            memcpy(&rec->vin_str[0], &frame->data[5], 3);
            rec->bytes_received = 3;
            uds_send_flow_control();
        }
    } else if (pci == 0x2) { /* Consecutive Frame (CF) */
        uint8_t chunk = (rec->expected_length - rec->bytes_received - 3);
        if (chunk > 7) chunk = 7;

        memcpy(&rec->vin_str[rec->bytes_received], &frame->data[1], chunk);
        rec->bytes_received += chunk;

        if (rec->bytes_received >= 17) {
            rec->vin_str[17] = '';
            rec->vin_complete = true;
        }
    }
}

24.4 Reading and Clearing Diagnostic Trouble Codes (DTCs)

A Diagnostic Trouble Code (DTC) is a 3-byte standardized identifier indicating an active or historic vehicle malfunction. The first byte encodes the physical system prefix:

  • 0x00 - 0x3F: P (Powertrain) — Engine, transmission, emissions. (e.g. P0300 Random Misfire).
  • 0x40 - 0x7F: C (Chassis) — ABS brakes, electronic stability control, suspension.
  • 0x80 - 0xBF: B (Body) — Airbags, climate control, lighting, door locks.
  • 0xC0 - 0xFF: U (Network) — CAN bus timeouts, loss of communication between ECUs.
Using UDS Service 0x19 02 (ReadDTCByStatusMask), the tool fetches all stored DTCs; calling Service 0x14 FF FF FF clears all fault memory across all vehicle modules.


#include <stdint.h>
#include <stdio.h>

#define UDS_REQ_ID              0x7E0U
#define UDS_SERVICE_CLEAR_DTC   0x14U
#define UDS_SERVICE_READ_DTC    0x19U

typedef struct {
    char     dtc_formatted[6]; /* e.g. "P0301" */
    uint8_t  status_mask;
} DecodedDtc_t;

extern void can_transmit_frame(const CanMessage_t *frame);

void uds_decode_single_dtc(const uint8_t *raw_3bytes, DecodedDtc_t *out) {
    uint8_t b1 = raw_3bytes[0];
    uint8_t b2 = raw_3bytes[1];
    out->status_mask = raw_3bytes[2];

    char prefix;
    uint8_t prefix_type = (b1 >> 6) & 0x03;
    switch (prefix_type) {
        case 0: prefix = 'P'; break; /* Powertrain */
        case 1: prefix = 'C'; break; /* Chassis */
        case 2: prefix = 'B'; break; /* Body */
        case 3: prefix = 'U'; break; /* Network */
    }

    uint8_t digit2 = (b1 >> 4) & 0x03;
    uint8_t digit3 = b1 & 0x0F;
    uint8_t digit4 = (b2 >> 4) & 0x0F;
    uint8_t digit5 = b2 & 0x0F;

    snprintf(out->dtc_formatted, sizeof(out->dtc_formatted), "%c%X%X%X%X",
             prefix, digit2, digit3, digit4, digit5);
}

void uds_clear_all_dtcs(void) {
    CanMessage_t req;
    req.id = UDS_REQ_ID;
    req.dlc = 8;
    req.data[0] = 0x04; /* 4 bytes follow */
    req.data[1] = UDS_SERVICE_CLEAR_DTC;
    req.data[2] = 0xFF; /* Clear all DTC groups */
    req.data[3] = 0xFF;
    req.data[4] = 0xFF;
    req.data[5] = 0x55;
    req.data[6] = 0x55;
    req.data[7] = 0x55;

    can_transmit_frame(&req);
}

24.5 Concurrent Wireless BLE Telemetry and MicroSD Black-Box Logger

To deliver an exceptional user experience, the tool streams live PID data wirelessly to mobile devices while simultaneously logging every transaction to an SD card. The BLE task advertises a custom Automotive GATT Service with notify characteristics for RPM, Speed, and Coolant Temp, while a background FAT32 task flushes comma-separated records to disk.


#include <stdio.h>
#include <string.h>
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "ff.h"

typedef struct {
    uint32_t timestamp_ms;
    uint16_t rpm;
    uint8_t  speed_kph;
    int8_t   coolant_degc;
    uint8_t  throttle_pct;
} TelemetryRecord_t;

extern QueueHandle_t g_telemetry_queue;
extern void ble_notify_characteristic(uint16_t char_handle, const void *data, uint16_t len);

void vBlackBoxLoggerTask(void *pvParams) {
    FATFS fs;
    FIL log_file;
    TelemetryRecord_t record;
    char csv_line[64];
    UINT bw;

    f_mount(&fs, "0:", 1);
    f_open(&log_file, "0:/drive_log.csv", FA_WRITE | FA_OPEN_ALWAYS);
    f_lseek(&log_file, f_size(&log_file));

    /* Write CSV header */
    const char *header = "Timestamp,RPM,Speed_KPH,Coolant_C,Throttle_Pct
";
    f_write(&log_file, header, strlen(header), &bw);

    for (;;) {
        if (xQueueReceive(g_telemetry_queue, &record, portMAX_DELAY) == pdPASS) {
            /* 1. Push notification to connected smartphone via BLE GATT */
            uint8_t ble_payload[4];
            ble_payload[0] = (uint8_t)(record.rpm & 0xFF);
            ble_payload[1] = (uint8_t)(record.rpm >> 8);
            ble_payload[2] = record.speed_kph;
            ble_payload[3] = (uint8_t)record.coolant_degc;
            ble_notify_characteristic(0x002A, ble_payload, 4);

            /* 2. Format and append record to MicroSD FAT32 CSV file */
            snprintf(csv_line, sizeof(csv_line), "%lu,%u,%u,%d,%u
",
                     record.timestamp_ms, record.rpm, record.speed_kph,
                     record.coolant_degc, record.throttle_pct);
            f_write(&log_file, csv_line, strlen(csv_line), &bw);
            f_sync(&log_file);
        }
    }
}

Topic Quiz (10 Questions)

Test your conceptual understanding of today's embedded systems architecture, registers, and runtime behaviors.

1. What is the standard functional CAN identifier used by diagnostic scan tools to broadcast OBD-II queries to all ECUs?
  • 0x7DF
  • 0x000
  • 0x1FFFFFFF
  • 0x301
SAE J1979 specifies 0x7DF as the 11-bit standard functional broadcast request identifier. All emissions-related ECUs listen to this ID and reply with their physical ID (0x7E8 for Engine, 0x7E9 for Transmission).
2. How is Engine RPM decoded from the 2 data bytes (Byte A and Byte B) returned in OBD-II PID 0x0C?
  • Formula: ((A * 256) + B) / 4
  • Formula: A + B
  • Formula: (A * 100) + B
  • Formula: (A * 256) - B
The 16-bit word represents RPM in quarter-revolution increments. Dividing the 16-bit integer by 4 yields the true engine speed in revolutions per minute.
3. What does a Diagnostic Trouble Code beginning with the letter 'P' indicate (e.g., P0300)?
  • Powertrain fault (Engine, Transmission, Emissions, or Fuel System)
  • Power window motor failure
  • Parking brake sensor error
  • Passenger seat airbag error
Standard DTC prefixes are: P = Powertrain, C = Chassis, B = Body, and U = Network (communication buses).
4. What is the primary role of the ISO 15765-2 (ISO-TP) transport protocol layer in automotive diagnostics?
  • To segment and reassemble multi-byte diagnostic messages (up to 4095 bytes) across standard 8-byte CAN frames using Flow Control frames
  • To encrypt CAN bus data using AES-128
  • To increase the physical CAN bus voltage from 5V to 12V
  • To convert CAN bus messages into Ethernet packets directly on physical wires
Standard CAN 2.0 frames hold only 8 bytes. ISO-TP provides flow control and sequence numbering so diagnostic messages (like reading the 17-byte VIN) can be streamed reliably.
5. Which UDS Service identifier is invoked to command all vehicle ECUs to clear their stored fault codes and reset freeze frames?
  • Service 0x14 (ClearDiagnosticInformation)
  • Service 0x22 (ReadDataByIdentifier)
  • Service 0x27 (SecurityAccess)
  • Service 0x11 (ECUReset)
UDS Service 0x14 followed by the 3-byte group mask 0xFFFFFF commands all connected ECUs to purge active and historic DTCs from non-volatile memory.
6. What does an ECU response starting with byte 0x7F indicate in UDS diagnostics?
  • A Negative Response (NRC) indicating that the requested service was rejected or unsupported
  • A Positive Response with 79 bytes of data
  • That the CAN bus is currently operating in low-power sleep mode
  • A broadcast warning that the vehicle battery is low
0x7F is the standard UDS Negative Response Service ID. The following bytes declare the rejected service ID and the specific Negative Response Code (NRC, e.g. 0x31 Request Out of Range).
7. Why is the vehicle OBD-II diagnostic port physically accessible within 2 feet of the steering wheel on all passenger cars?
  • Because government environmental regulations (EPA / CARB) mandate standardized, accessible ports for roadside emissions testing
  • To make it easier for drivers to charge smartphones
  • Because the CAN bus wires cannot physically exceed 2 feet in total length
  • To connect external audio speakers to the radio
Clean Air Act legislation mandates that the 16-pin OBD-II port be unlatched and accessible without tools beneath the steering column for mandatory state emissions inspections.
8. What is 'Freeze Frame' data in automotive diagnostics?
  • A snapshot of critical engine sensor values (RPM, speed, coolant temp, engine load) recorded in non-volatile memory at the exact instant a DTC was logged
  • A thermal camera image of the radiator
  • The pause state of the in-cabin infotainment video player
  • A mechanism that locks the vehicle brakes during icy weather
When an engine fault trips (e.g. misfire), the ECU captures a 'freeze frame' snapshot of all operating parameters, allowing technicians to see the exact driving conditions when the fault occurred.
9. What is the function of UDS Service 0x27 (SecurityAccess)?
  • To authenticate diagnostic scan tools using a cryptographic seed-key exchange before permitting restricted actions like ECU flash reprogramming
  • To unlock the physical doors of the vehicle using a key fob
  • To check if the driver is wearing a seatbelt
  • To configure the internal cabin anti-theft alarm siren
SecurityAccess protects sensitive ECU functions: the tester requests a random seed, computes an authorized key response using a secret algorithm, and sends it back to unlock protected memory.
10. How does USB Communications Device Class (CDC) enable an embedded system to communicate with host PCs without installing proprietary drivers?
  • USB CDC is natively supported by Windows, macOS, and Linux as a standard Virtual COM Port (ttyACM / COM), accessible via standard serial terminals
  • USB CDC operates using Bluetooth radio waves
  • USB CDC converts USB into analog audio signals
  • USB CDC eliminates the need for USB hardware controllers
USB CDC is an industry-standard USB device class. Operating systems provide built-in kernel drivers, letting PC software communicate via standard serial file handles.
