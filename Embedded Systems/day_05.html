5.1 Hardware Timer Architecture: Prescalers, Counters, and Auto-Reload

Software delay loops are inherently inaccurate: their duration varies wildly with compiler optimization flags, CPU clock frequency, and interrupt preemption overhead. Modern microcontrollers offload all precise timekeeping to dedicated Hardware Timers. A general-purpose microcontroller timer is a programmable digital counter clocked independently from CPU instructions.

The core timer architecture consists of three fundamental register stages:

  • Prescaler (PSC): A 16-bit register that divides the input timer bus clock frequency ($f_{TIM}$) by $(PSC + 1)$.
  • Counter (CNT): A 16-bit or 32-bit register that increments (up-counting), decrements (down-counting), or counts up-and-down (center-aligned mode) on each prescaled tick.
  • Auto-Reload Register (ARR): Defines the counter overflow ceiling. When $CNT$ reaches $ARR$, the counter generates an Update Event (UIE), reloads its start value, and can trigger an interrupt or DMA transfer.
Real World Example: In an electric vehicle motor inverter, a center-aligned 3-phase timer operates at 20 kHz. The counter increments and decrements symmetrically, generating complementary Pulse Width Modulation (PWM) waveforms with microsecond hardware dead-time insertion to prevent shoot-through short circuits across the high-voltage IGBT bridge.
Figure 1.4-1: General-Purpose Hardware Timer Block Diagram
Figure Parameters Explained:
  • Prescaler (PSC): Divides input clock: f_CNT = f_CLK / (PSC + 1). Allows configuring tick resolutions from nanoseconds to milliseconds.
  • Auto-Reload (ARR): Determines timer period: Overflow Frequency f_OVF = f_CLK / ((PSC + 1) * (ARR + 1)).
  • CCR1 - CCR4 Registers: Store comparison thresholds for PWM duty cycles or capture timestamps of input pin transitions.
  • Update Event (UEV): Fires upon counter reaching ARR, reloading shadow registers and driving the TIMx_IRQHandler interrupt.

5.2 Pulse Width Modulation (PWM): Frequency, Duty Cycle, and Edge vs. Center Aligned

Pulse Width Modulation (PWM) generates an analog-equivalent average voltage from a purely digital pin by rapidly switching the output HIGH and LOW at high frequency. The ratio of the pulse HIGH duration ($T_{ON}$) to the total period ($T$) is defined as the Duty Cycle:

$$\text{Duty Cycle (\%)} = \frac{T_{ON}}{T} \times 100 = \frac{CCR}{ARR + 1} \times 100$$

In PWM Mode 1 (Edge-Aligned), the output pin stays HIGH while $CNT < CCRx$, and transitions to LOW when $CNT \ge CCRx$. By dynamically varying the value of $CCRx$ between $0$ and $ARR$, software commands exact duty cycles from 0% to 100% with zero CPU intervention.

Figure 1.4-2: PWM Waveform Generation via Counter and Compare Thresholds
Figure Parameters Explained:
  • ARR (Period Ceiling): Defines the PWM switching frequency. Higher ARR values provide finer duty cycle resolution at lower frequencies.
  • CCR (Duty Threshold): Controls pulse width: when CCR = ARR / 2, the output is a 50% duty square wave.
  • Edge-Aligned Mode: Counter ramps monotonically 0 to ARR; phase jitter occurs at the beginning/end of pulses.
  • Center-Aligned Mode: Counter counts up to ARR and down to 0; pulses are centered symmetrically, minimizing electromagnetic acoustic noise in motors.

5.3 Input Capture: Measuring Pulse Widths and Signal Frequency

While Output Compare generates signals, Input Capture Mode measures incoming external signals. When an electrical edge (rising or falling) occurs on a timer channel pin, the timer hardware latches the instantaneous value of the counter $CNT$ into the Capture/Compare Register ($CCRx$) in single-cycle silicon time and asserts an interrupt flag. By computing the difference between two successive capture values, software calculates frequency, period, and pulse widths with sub-microsecond precision.

Figure 1.4-3: Input Capture Mode Timing Waveform Analysis
Figure Parameters Explained:
  • Input Filter & Prescaler: Configures digital glitch rejection filters (eliminating sub-microsecond spikes) and prescales input pulses.
  • Direct Capture (IC1 -> CCR1): Hardware captures the counter value directly into the register upon detecting the programmed edge.
  • Counter Wrap-Around Handling: If the counter overflows between captures, software adds (ARR + 1) to the delta calculation: Delta = (t2 >= t1) ? (t2 - t1) : ((ARR - t1) + t2 + 1).

5.4 The Real-Time Clock (RTC) & Calendar Subsystem

Standard timers stop counting when the microcontroller enters low-power standby sleep modes. For calendar tracking (Year, Month, Day, Hour, Minute, Second) and battery-powered wakeups, microcontrollers incorporate an independent Real-Time Clock (RTC) peripheral. The RTC is clocked by a dedicated 32.768 kHz Low-Speed External (LSE) crystal oscillator powered through a dedicated battery backup pin ($V_{BAT}$) when main power is disconnected.

Figure 1.4-4: STM32 RTC Calendar Block Diagram and Clock Dividers
Figure Parameters Explained:
  • 32.768 kHz Crystal: Chosen because 32768 is exactly 2^15, allowing binary dividers to easily produce a precise 1 Hz (1 pulse per second) clock.
  • Binary Coded Decimal (BCD): RTC registers store time and date in BCD format (e.g. 0x25 represents decimal 25) for direct human-readable parsing.
  • Backup Domain (VBAT): Dedicated power domain containing the RTC, LSE oscillator, and backup registers powered by an external coin cell during main power outages.

5.5 Timer Cascading & Master/Slave Synchronization

When measuring very long time periods or generating complex synchronized multi-channel signals, microcontrollers support Timer Master/Slave Cascading. One timer (Master) outputs its internal trigger (TRGO) on update, reset, or compare events. Another timer (Slave) uses this trigger as its clock prescaler or gate, linking two 16-bit timers together to form a seamless 32-bit counter without software intervention.

Figure 1.4-5: Master-Slave Timer Cascading Architecture
Figure Parameters Explained:
  • Internal Trigger (ITR): Silicon interconnect routing trigger signals between timers without using external GPIO pins.
  • TRGO (Trigger Output): Configurable trigger output event (Reset, Enable, Update, Compare Pulse) broadcast to slave timers or ADC converters.
  • Gated Mode: Slave timer only counts when the master timer output signal is HIGH, enabling automated burst generation.

#include <stdint.h>
#include <stdbool.h>

#define RCC_APB1ENR     (*(volatile uint32_t *)0x40023840UL)
#define TIM2_BASE       0x40000000UL
#define TIM2_CR1        (*(volatile uint32_t *)(TIM2_BASE + 0x00UL))
#define TIM2_DIER       (*(volatile uint32_t *)(TIM2_BASE + 0x0CUL))
#define TIM2_SR         (*(volatile uint32_t *)(TIM2_BASE + 0x10UL))
#define TIM2_PSC        (*(volatile uint32_t *)(TIM2_BASE + 0x28UL))
#define TIM2_ARR        (*(volatile uint32_t *)(TIM2_BASE + 0x2CUL))

#define NVIC_ISER0      (*(volatile uint32_t *)0xE000E100UL)
#define TIM2_IRQn       28

static volatile uint32_t g_seconds_elapsed = 0;

void TIM2_IRQHandler(void) {
    if (TIM2_SR & (1UL << 0)) {
        TIM2_SR &= ~(1UL << 0); /* Clear Update Interrupt Flag (UIF) */
        g_seconds_elapsed++;
    }
}

/* Configure TIM2 for 1.0 Hz periodic interrupt assuming 16 MHz APB1 timer clock */
void tim2_init_1hz(void) {
    RCC_APB1ENR |= (1UL << 0); /* Enable TIM2 clock */

    /* Step 1: Prescaler divides 16,000,000 Hz down to 1,000 Hz */
    TIM2_PSC = 16000UL - 1UL;

    /* Step 2: Auto-Reload counts 1,000 ticks = exactly 1.000 second */
    TIM2_ARR = 1000UL - 1UL;

    /* Step 3: Enable Update Interrupt in DIER */
    TIM2_DIER |= (1UL << 0);

    /* Step 4: Enable TIM2 in NVIC */
    NVIC_ISER0 = (1UL << TIM2_IRQn);

    /* Step 5: Start counter */
    TIM2_CR1 |= (1UL << 0);
}

#include <stdint.h>

#define RCC_AHB1ENR     (*(volatile uint32_t *)0x40023830UL)
#define RCC_APB1ENR     (*(volatile uint32_t *)0x40023840UL)

#define GPIOA_MODER     (*(volatile uint32_t *)0x40020000UL)
#define GPIOA_AFRL      (*(volatile uint32_t *)0x40020020UL)

#define TIM3_BASE       0x40000400UL
#define TIM3_CR1        (*(volatile uint32_t *)(TIM3_BASE + 0x00UL))
#define TIM3_CCMR1      (*(volatile uint32_t *)(TIM3_BASE + 0x18UL))
#define TIM3_CCER       (*(volatile uint32_t *)(TIM3_BASE + 0x20UL))
#define TIM3_PSC        (*(volatile uint32_t *)(TIM3_BASE + 0x28UL))
#define TIM3_ARR        (*(volatile uint32_t *)(TIM3_BASE + 0x2CUL))
#define TIM3_CCR1       (*(volatile uint32_t *)(TIM3_BASE + 0x34UL))

/* Initialize 1 kHz PWM on PA6 (TIM3 CH1, Alternate Function AF2) */
void pwm_led_init_1khz(void) {
    RCC_AHB1ENR |= (1UL << 0); /* GPIOA clock */
    RCC_APB1ENR |= (1UL << 1); /* TIM3 clock */

    /* PA6 Alternate Function mode (MODER6 = 0b10) */
    GPIOA_MODER &= ~(3UL << (6 * 2));
    GPIOA_MODER |= (2UL << (6 * 2));

    /* Route PA6 to AF2 (TIM3_CH1): AFRL pin 6 is bits [27:24] = 0x02 */
    GPIOA_AFRL &= ~(0xFUL << 24);
    GPIOA_AFRL |= (0x2UL << 24);

    /* Timer clock = 16 MHz. Prescaler = 15 -> f_cnt = 1 MHz (1 tick = 1 us) */
    TIM3_PSC = 16 - 1;
    /* ARR = 999 -> Period = 1000 us = 1 ms (1 kHz PWM frequency) */
    TIM3_ARR = 1000 - 1;

    /* PWM Mode 1 on Channel 1: OC1M = 0b110, enable preload OC1PE = 1 */
    TIM3_CCMR1 |= (6UL << 4) | (1UL << 3);

    /* Enable output on Channel 1 (CC1E = 1) */
    TIM3_CCER |= (1UL << 0);

    /* Initial duty cycle = 0% */
    TIM3_CCR1 = 0;

    /* Enable auto-reload preload and start timer */
    TIM3_CR1 |= (1UL << 7) | (1UL << 0);
}

void pwm_set_duty(uint16_t duty_0_to_1000) {
    if (duty_0_to_1000 > 999) duty_0_to_1000 = 999;
    TIM3_CCR1 = duty_0_to_1000;
}

Program 1.5-3: Servo Motor Control: 50 Hz PWM with 1-2 ms Precision Pulse 

#include <stdint.h>
#include <stdbool.h>

#define TIM1_BASE       0x40010000UL
#define TIM1_SR         (*(volatile uint32_t *)(TIM1_BASE + 0x10UL))
#define TIM1_CCR1       (*(volatile uint32_t *)(TIM1_BASE + 0x34UL))

static volatile uint32_t t1 = 0, t2 = 0;
static volatile bool capture_ready = false;

void TIM1_CC_IRQHandler(void) {
    static bool first_edge = true;
    
    if (TIM1_SR & (1UL << 1)) { /* CC1IF Capture flag */
        if (first_edge) {
            t1 = TIM1_CCR1; /* First rising edge */
            first_edge = false;
        } else {
            t2 = TIM1_CCR1; /* Second rising edge */
            first_edge = true;
            capture_ready = true;
        }
    }
}

uint32_t calculate_measured_frequency(uint32_t timer_clk_hz) {
    if (!capture_ready) return 0;
    
    uint32_t delta = (t2 >= t1) ? (t2 - t1) : ((0xFFFFUL - t1) + t2 + 1);
    capture_ready = false;
    
    return timer_clk_hz / delta;
}

#include <stdint.h>

#define RTC_BASE        0x40002800UL
#define RTC_TR          (*(volatile uint32_t *)(RTC_BASE + 0x00UL))
#define RTC_DR          (*(volatile uint32_t *)(RTC_BASE + 0x04UL))
#define RTC_WPR         (*(volatile uint32_t *)(RTC_BASE + 0x24UL))

typedef struct {
    uint8_t hours;
    uint8_t minutes;
    uint8_t seconds;
} RTC_Time_t;

/* Convert BCD byte to standard binary decimal integer */
static inline uint8_t bcd_to_dec(uint8_t bcd) {
    return ((bcd >> 4) * 10) + (bcd & 0x0F);
}

void rtc_get_time(RTC_Time_t *time) {
    uint32_t tr = RTC_TR; /* Read Time Register */
    
    time->hours   = bcd_to_dec((tr >> 16) & 0x3F);
    time->minutes = bcd_to_dec((tr >> 8) & 0x7F);
    time->seconds = bcd_to_dec(tr & 0x7F);
}

  • PSC = 15, ARR = 999
  • PSC = 16000, ARR = 1
  • PSC = 0, ARR = 16000
f = f_clk / ((PSC + 1) * (ARR + 1)). With PSC = 15, timer ticks at 16 MHz / 16 = 1 MHz. With ARR = 999 (1000 steps), frequency = 1 MHz / 1000 = 1 kHz.
2. In PWM Mode 1, what happens to the output channel pin when the counter CNT equals or exceeds CCRx?
  • The output pin transitions from HIGH to LOW
  • The counter immediately resets to 0
  • The output pin transitions to High-Impedance (Hi-Z)
  • A HardFault exception is triggered
In PWM Mode 1, the channel is active (HIGH) as long as CNT < CCRx, and switches inactive (LOW) when CNT >= CCRx.
3. Why is 32.768 kHz universally chosen as the crystal frequency for Real-Time Clock (RTC) peripherals?
  • It is the resonant frequency of copper traces
  • 32768 is exactly 2^15, which can be divided down to exactly 1.000 Hz using a 15-bit binary ripple counter
  • It generates minimum electromagnetic interference at radio frequencies
  • It matches the human audible hearing threshold
2^15 = 32,768. A simple cascade of 15 flip-flops divides 32.768 kHz down to an exact 1 Hz tick with zero fractional rounding error.
4. What is the typical PWM frequency and pulse width range required to position a hobby RC servo motor across 0 to 180 degrees?
  • 1 kHz frequency, 50% to 100% duty cycle
  • 50 Hz frequency (20 ms period), with 1.0 ms to 2.0 ms pulse widths
  • 100 kHz frequency, 1 us to 2 us pulse widths
  • 10 Hz frequency, 10 ms to 90 ms pulse widths
Standard analog RC servos require a 50 Hz control frame (20 ms period) with pulse widths ranging between 1.0 ms (0 deg) and 2.0 ms (180 deg).
5. How does Input Capture mode handle measuring a pulse width if the timer counter overflows between the rising and falling edges?
  • The measurement is invalid and must be discarded
  • Software adds (ARR + 1) to the delta calculation upon detecting the timer overflow flag
  • The hardware automatically halts the timer
  • The input pin is reconfigured as an open-drain output
When an overflow occurs between edge captures, software accounts for the wrap-around by calculating: Delta = (ARR - t1) + t2 + 1.
6. What is the purpose of the Shadow Registers (Preload Registers) in ARM Cortex-M timer architectures?
  • To double the effective clock frequency
  • To prevent glitching by ensuring new ARR or CCR values only take effect synchronously on the next Update Event (counter rollover)
  • To mirror register values to external SPI Flash
  • To encrypt timer registers against hacking
Preload buffering ensures that if software writes a new CCR or ARR value mid-count, it is buffered and latched only at counter rollover, preventing truncated pulses.
7. Which timer mode allows two 90-degree out-of-phase encoder signals (Phase A and Phase B) to be decoded directly in hardware?
  • PWM Mode 2
  • Encoder Interface Mode
  • One-Pulse Mode
  • Forced Inactive Mode
Encoder Interface mode decodes quadrature signals automatically, incrementing or decrementing the counter based on phase relationship without CPU interrupts.
8. What format does the STM32 RTC peripheral use to store Hours, Minutes, and Seconds in the RTC_TR register?
  • Raw Unix Epoch 32-bit seconds
  • Binary Coded Decimal (BCD)
  • ASCII strings
  • IEEE-754 Floating Point
RTC registers store date and time components in BCD format, where each 4-bit nibble represents one decimal digit (0-9).
9. In center-aligned PWM mode, how does the counter operate?
  • It counts only on even clock edges
  • It counts up from 0 to ARR, then counts down from ARR to 0 symmetrically
  • It uses two separate hardware counters running in opposite directions
  • It stops when CNT reaches ARR/2
Center-aligned mode alternates up-counting and down-counting, centering output pulses around the midpoint to reduce acoustic and electrical harmonics.
10. What pin connects an external coin-cell battery to keep the RTC and backup domain alive when VDD power is lost?
  • NRST
  • BOOT0
  • VBAT
  • VREF+
The VBAT pin connects a 1.8V-3.6V coin-cell battery that powers the RTC and low-speed oscillator when main VDD drops below threshold.
