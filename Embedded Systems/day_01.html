1.1 What is an Embedded System?

An embedded system is a purpose-built electronic computing system engineered to perform a dedicated, real-time function within a larger mechanical or electrical infrastructure. Unlike general-purpose personal computers running monolithic operating systems (such as Windows, macOS, or desktop Linux) with gigabytes of dynamic RAM and multi-gigahertz processors, embedded systems operate under severe resource constraints: clock speeds often ranging between 8 MHz and 400 MHz, Flash storage measured in tens or hundreds of kilobytes, and static RAM (SRAM) typically spanning 4 KB to 512 KB.

Real World Example: In an automotive Electronic Control Unit (ECU) controlling Anti-lock Braking Systems (ABS), the microcontroller must sample wheel speed sensor pulses, execute slip calculations, and pulse hydraulic solenoid valves within a strict 4-millisecond deadline. A desktop operating system experiencing a garbage collection pause or background thread scheduling delay would cause catastrophic brake lockup.
Figure 1.0-1: General-Purpose PC Architecture vs. Embedded Microcontroller Architecture
Figure Parameters Explained:
  • Host CPU vs MCU: General-purpose CPUs require external memory controllers and storage bridges; MCUs integrate processing core, non-volatile Flash, volatile SRAM, and peripheral engines on a single silicon die.
  • Bus Matrix (AHB/APB): Advanced High-performance Bus (AHB) handles high-bandwidth memory transfers; Advanced Peripheral Bus (APB) routes low-power control registers to peripherals.
  • Memory-Mapped Registers: Peripherals are controlled entirely by reading and writing to dedicated 32-bit physical addresses mapped directly into the CPU's memory address space.

1.2 Microcontrollers vs Microprocessors

The distinction between a microcontroller (MCU) and a microprocessor (MPU) dictates system design, power consumption, boot latency, and software architecture. An MCU is a self-contained computer-on-a-chip that boots instantaneously into user code from internal Flash memory. An MPU (e.g., ARM Cortex-A series or x86) lacks internal non-volatile memory for application code, requiring external DDR SDRAM, eMMC or NAND flash, and multi-stage bootloaders (U-Boot, Linux kernel).

1.3 The Embedded C Cross-Compilation Toolchain

When developing software for a microcontroller, your workstation (typically an x86-64 or Apple Silicon machine) serves as the host system, while the target microcontroller (e.g., ARM Cortex-M4) is the target. Because the host architecture cannot natively execute Cortex-M Thumb-2 machine code, you must employ a cross-compiler such as arm-none-eabi-gcc (ARM architecture, no vendor OS, EABI standard binary interface).

Figure 1.0-2: The Embedded C Cross-Compilation and Linking Pipeline
Figure Parameters Explained:
  • arm-none-eabi-gcc: Invokes preprocessor (macro expansion, header inclusion), compiler (translates C AST into assembly), and assembler (outputs relocatable .o objects).
  • arm-none-eabi-ld: Resolves cross-module symbols, places code and data into physical target memory regions as prescribed by the memory layout directives in the linker script.
  • .elf vs .bin / .hex: The ELF file contains symbol tables, section headers, and DWARF debug info for GDB; .bin is a contiguous byte dump burned into MCU physical Flash.

1.4 Microcontroller Memory Map & C Memory Sections

In standard C programming on an OS, memory layout is virtualized by a Memory Management Unit (MMU). In bare-metal Cortex-M microcontrollers, physical addresses are exposed directly. The 4 GB (32-bit) address space is divided into architectural regions defined by the ARM standard:

  • 0x0000_0000 - 0x1FFF_FFFF: Code / Flash memory region (Internal Flash on STM32 typically starts at 0x0800_0000, aliased to 0x0000_0000 at boot).
  • 0x2000_0000 - 0x3FFF_FFFF: SRAM region for volatile variables, stack, and heap.
  • 0x4000_0000 - 0x5FFF_FFFF: Peripheral registers (Timer, GPIO, UART, SPI, I2C, ADC).
  • 0xE000_0000 - 0xE00F_FFFF: Core Internal Peripherals (NVIC, SysTick, MPU, SCB, DWT).
Figure 1.0-3: Microcontroller Address Map & C Memory Segments
Figure Parameters Explained:
  • .text Section: Contains compiled machine instructions stored permanently in non-volatile Flash memory.
  • .rodata Section: Contains read-only data, string constants, and const look-up tables stored directly in Flash.
  • .data Section: Global and static variables initialized with non-zero values. Initial values reside in Flash (LMA) and are copied to SRAM (VMA) during reset startup.
  • .bss Section: Uninitialized or zero-initialized globals. Startup code zeroes this memory block in SRAM before jumping to main().
  • Stack & Heap: Stack allocates function call frames, parameters, and local variables from top of SRAM down; Heap manages dynamic memory growing upwards.

1.5 The Vector Table & Startup Sequence

When power is applied to an ARM Cortex-M microcontroller, the hardware executes a hardwired bootstrap sequence before executing a single line of C code:

  1. The CPU reads the 32-bit word at physical address 0x0000_0000 and loads it into the Main Stack Pointer (MSP).
  2. The CPU reads the 32-bit word at physical address 0x0000_0004 and loads it into the Program Counter (PC). This address points to the Reset_Handler().
  3. The CPU begins executing instructions at Reset_Handler().
Figure 1.0-4: Cortex-M Vector Table Layout & Reset Sequence
Figure Parameters Explained:
  • Vector Table Base (VTOR): Defaults to 0x00000000; can be relocated to SRAM or another Flash bank by configuring SCB->VTOR.
  • Thumb Bit (LSB = 1): All function pointer entries in the vector table must have bit 0 set to 1 to signify ARM Thumb instruction mode; otherwise a UsageFault INVSTATE occurs.
  • Reset_Handler(): Initializes the C runtime environment by copying .data from Flash to SRAM, zeroing .bss in SRAM, calling SystemInit() to set clocks, and branching to main().

1.6 Direct Register Programming & The volatile Keyword

Microcontroller hardware peripherals are configured via Memory-Mapped Registers. Each register behaves like an ordinary memory location, but its bits are physically wired to hardware flip-flops controlling peripheral circuitry. Writing to a register sets hardware control lines; reading a register inspects hardware status pins.

View Buggy/Legacy Code Pattern: Omitting the volatile Qualifier

The code below attempts to poll a hardware UART status register bit without using volatile. When compiled with optimization flag -O2 or -O3, the compiler notices that the loop body does not write to *status_reg. Assuming it cannot change, the compiler hoists the memory read outside the loop, creating an infinite loop that hangs the microcontroller indefinitely!


/* DANGEROUS: Omitting volatile on hardware registers */
uint32_t *uart_sr = (uint32_t *)0x40004400; /* USART2 Status Register */

void wait_for_tx_complete(void) {
    /* Compiler optimizes this to:
       uint32_t val = *uart_sr;
       while (!(val & (1 << 7))) ; // Infinite loop!
    */
    while (!(*uart_sr & (1 << 7))) {
        /* Polling for TXE bit */
    }
}
Figure 1.0-5: Compiler Optimization with and without the volatile Keyword
Figure Parameters Explained:
  • Without volatile: Compiler assumes standard C memory semantics where variables only change via program writes. LDR is emitted once; subsequent checks read from CPU core register.
  • With volatile: Informs the compiler that the value at this memory address can change asynchronously at any microsecond due to external hardware events. Forces strict bus reads/writes.
  • MISRA-C Rule: All hardware registers and variables shared between ISRs and main thread must be qualified with volatile.

1.7 Hands-On Code Implementations


#include <stdint.h>

/* STM32F401 / STM32F411 Memory Base Addresses */
#define RCC_BASE            (0x40023800UL)
#define GPIOA_BASE          (0x40020000UL)

/* Register Offsets */
#define RCC_AHB1ENR_OFFSET  (0x30UL)
#define GPIO_MODER_OFFSET   (0x00UL)
#define GPIO_ODR_OFFSET     (0x14UL)

/* Pointer Dereferencing with volatile */
#define RCC_AHB1ENR         (*(volatile uint32_t *)(RCC_BASE + RCC_AHB1ENR_OFFSET))
#define GPIOA_MODER         (*(volatile uint32_t *)(GPIOA_BASE + GPIO_MODER_OFFSET))
#define GPIOA_ODR           (*(volatile uint32_t *)(GPIOA_BASE + GPIO_ODR_OFFSET))

/* Bit Field Definitions for PA5 (On-board Green LED on Nucleo-F401RE) */
#define RCC_AHB1ENR_GPIOAEN (1UL << 0)
#define GPIO_MODER_MODER5_OUTPUT (1UL << 10) /* Bits 11:10 = 01 for General Output */
#define GPIO_ODR_OD5        (1UL << 5)

static void delay_cycles(volatile uint32_t count) {
    while (count--) {
        __asm__ volatile("nop");
    }
}

int main(void) {
    /* Step 1: Enable clock gate for GPIOA peripheral on AHB1 bus */
    RCC_AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

    /* Step 2: Configure PA5 pin as general-purpose push-pull output */
    GPIOA_MODER &= ~(3UL << 10);          /* Clear mode bits 11:10 */
    GPIOA_MODER |= GPIO_MODER_MODER5_OUTPUT; /* Set mode to 01 (Output) */

    /* Step 3: Superloop toggling PA5 output data register */
    while (1) {
        GPIOA_ODR ^= GPIO_ODR_OD5; /* Toggle bit 5 */
        delay_cycles(500000);       /* Primitive delay */
    }

    return 0;
}
Program 1.0-1: Bare-Metal LED Blink via Direct Memory-Mapped Register Access 

#include <stdint.h>

/* Linker script exported boundary symbols */
extern uint32_t _sidata; /* Start of .data section in Flash (LMA) */
extern uint32_t _sdata;  /* Start of .data section in SRAM  (VMA) */
extern uint32_t _edata;  /* End of .data section in SRAM    (VMA) */
extern uint32_t _sbss;   /* Start of .bss section in SRAM   (VMA) */
extern uint32_t _ebss;   /* End of .bss section in SRAM     (VMA) */
extern uint32_t _estack; /* End of SRAM (Initial Stack Pointer value) */

int main(void);
void Default_Handler(void);
void Reset_Handler(void);

/* Interrupt Vector Table placed in .isr_vector section */
__attribute__((section(".isr_vector")))
void (* const g_pfnVectors[])(void) = {
    (void (*)(void))(&_estack), /* 0: Initial Stack Pointer */
    Reset_Handler,              /* 1: Reset Handler */
    Default_Handler,            /* 2: NMI Handler */
    Default_Handler,            /* 3: HardFault Handler */
    Default_Handler,            /* 4: MemManage Handler */
    Default_Handler,            /* 5: BusFault Handler */
    Default_Handler,            /* 6: UsageFault Handler */
    0, 0, 0, 0,                 /* Reserved */
    Default_Handler,            /* 11: SVCall Handler */
    Default_Handler,            /* 12: Debug Monitor */
    0,                          /* Reserved */
    Default_Handler,            /* 14: PendSV Handler */
    Default_Handler             /* 15: SysTick Handler */
};

void Reset_Handler(void) {
    /* 1. Copy initialized .data variables from Flash (LMA) to SRAM (VMA) */
    uint32_t *pSrc = &_sidata;
    uint32_t *pDst = &_sdata;
    while (pDst < &_edata) {
        *pDst++ = *pSrc++;
    }

    /* 2. Zero-initialize the .bss section in SRAM */
    uint32_t *pBss = &_sbss;
    while (pBss < &_ebss) {
        *pBss++ = 0UL;
    }

    /* 3. Invoke user application main */
    main();

    /* Trap CPU if main returns */
    while (1) {
        __asm__ volatile("wfi");
    }
}

void Default_Handler(void) {
    while (1) {}
}
Program 1.0-2: C Runtime Startup Implementation (startup.c) 

/* Linker Script for STM32F401RE (512KB Flash, 96KB SRAM) */
ENTRY(Reset_Handler)

MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    SRAM  (rwx) : ORIGIN = 0x20000000, LENGTH = 96K
}

_estack = ORIGIN(SRAM) + LENGTH(SRAM); /* End of SRAM (Top of stack) */

SECTIONS
{
    /* Vector table and executable code stored in Flash */
    .text :
    {
        . = ALIGN(4);
        KEEP(*(.isr_vector)) /* Vector table must not be discarded */
        *(.text)
        *(.text*)
        *(.rodata)
        *(.rodata*)
        . = ALIGN(4);
        _etext = .;
    } > FLASH

    /* Load Memory Address (LMA) in Flash for initialized data */
    _sidata = LOADADDR(.data);

    /* Initialized data placed in SRAM, loaded from Flash */
    .data :
    {
        . = ALIGN(4);
        _sdata = .;
        *(.data)
        *(.data*)
        . = ALIGN(4);
        _edata = .;
    } > SRAM AT > FLASH

    /* Uninitialized variables in SRAM zeroed by startup code */
    .bss :
    {
        . = ALIGN(4);
        _sbss = .;
        *(.bss)
        *(.bss*)
        *(COMMON)
        . = ALIGN(4);
        _ebss = .;
    } > SRAM
}
Program 1.0-3: Minimalist GNU Linker Script (stm32_flash.ld) 

# Target device toolchain configuration
CC      = arm-none-eabi-gcc
OBJCOPY = arm-none-eabi-objcopy
SIZE    = arm-none-eabi-size

TARGET  = firmware
MCU     = -mcpu=cortex-m4 -mthumb -mfloat-abi=soft
CFLAGS  = $(MCU) -Wall -Wextra -O2 -g3 -ffreestanding -nostdlib
LDFLAGS = $(MCU) -Tstm32_flash.ld -Wl,-Map=$(TARGET).map -nostdlib

SRCS    = main.c startup.c
OBJS    = $(SRCS:.c=.o)

all: $(TARGET).bin $(TARGET).hex
	@echo "--- Build Complete: Firmware Size ---"
	$(SIZE) $(TARGET).elf

%.o: %.c
	$(CC) $(CFLAGS) -c $< -o $@

$(TARGET).elf: $(OBJS)
	$(CC) $(OBJS) $(LDFLAGS) -o $@

$(TARGET).bin: $(TARGET).elf
	$(OBJCOPY) -O binary $< $@

$(TARGET).hex: $(TARGET).elf
	$(OBJCOPY) -O ihex $< $@

clean:
	rm -f $(OBJS) $(TARGET).elf $(TARGET).bin $(TARGET).hex $(TARGET).map

flash: $(TARGET).bin

Topic Quiz (10 Questions)

Test your conceptual understanding of today's embedded systems architecture, registers, and runtime behaviors.

1. Which memory section holds global variables that are declared without an explicit initial value or initialized to zero?
  • .text
  • .rodata
  • .bss
  • .data
The .bss (Block Started by Symbol) section contains uninitialized and zero-initialized global and static variables. Startup code zeroes this region in SRAM before main() executes.
2. What is the physical address read by an ARM Cortex-M processor upon reset to initialize the Main Stack Pointer (MSP)?
  • 0x00000004
  • 0x00000000
  • 0x08000000
  • 0x20000000
At address 0x00000000, the first 4 bytes of the vector table define the initial value of the Main Stack Pointer (MSP). The Reset Handler address resides at 0x00000004.
3. Why must all function pointer vectors in an ARM Cortex-M vector table have their least significant bit (LSB) set to 1?
  • To specify supervisor execution mode
  • To indicate the processor must execute in Thumb instruction state
  • To enable hardware floating-point acceleration
  • To bypass the memory protection unit (MPU)
Cortex-M cores only support the Thumb instruction set. Bit 0 of branch targets indicates the instruction state; clearing it causes an INVSTATE UsageFault.
4. What happens if a hardware register pointer is declared without the volatile qualifier when compiled with -O3 optimization?
  • The compiler issues a fatal syntax error
  • The memory access is moved from SRAM to Flash
  • The compiler may cache the read in a CPU register, creating an infinite polling loop
  • The processor triggers a HardFault on bus read
Without volatile, the optimizing compiler assumes the memory location cannot change without a program write, hoisting reads out of polling loops.
5. In a GNU linker script, what is the difference between VMA (Virtual Memory Address) and LMA (Load Memory Address)?
  • VMA is used for Flash; LMA is used for external EEPROM
  • VMA is the runtime address during execution; LMA is the physical storage address where data is loaded in Flash
  • VMA is computed by the compiler; LMA is assigned dynamically by the operating system
  • VMA is 16-bit; LMA is 32-bit
For the .data section, LMA is in Flash where initial values are permanently stored, while VMA is in SRAM where variables live and mutate during execution.
6. Which ARM Cortex-M processor family incorporates a 6-stage dual-issue superscalar pipeline and L1 instruction/data caches?
  • Cortex-M0+
  • Cortex-M3
  • Cortex-M4
  • Cortex-M7
The Cortex-M7 is a high-performance core with a dual-issue superscalar pipeline, double-precision FPU, and optional L1 instruction and data caches.
7. What is the primary role of the Advanced High-performance Bus (AHB) in an ARM microcontroller bus matrix?
  • Connecting slow peripherals like UART and I2C
  • High-bandwidth interconnect between CPU core, Flash, SRAM, and DMA
  • Regulating internal core LDO voltages
  • Providing galvanic isolation for automotive CAN transceivers
AHB connects high-throughput system masters (CPU core, DMA controllers) to high-speed memories (Flash, SRAM) and peripheral bridges.
8. In the standard GCC toolchain naming convention 'arm-none-eabi', what does 'none' represent?
  • No hardware floating point unit
  • Target operating system is bare-metal (no OS vendor)
  • No optimization flags are allowed
  • No debug symbols generated
The vendor/OS field in 'arm-none-eabi' indicates the target platform does not have an operating system like Linux ('none' = bare-metal).
9. What instruction is executed by Reset_Handler() to place the CPU in low-power sleep if main() unexpectedly exits?
  • NOP
  • WFI (Wait For Interrupt)
  • BKPT
  • SVC
WFI (Wait For Interrupt) halts the CPU clock, entering sleep mode until an interrupt or reset event occurs, preventing errant execution.
10. Which file format contains ELF symbol headers, function addresses, and DWARF debug data used by GDB during SWD debugging?
  • .bin
  • .hex
  • .elf
  • .dts
The Executable and Linkable Format (.elf) contains complete debugging symbol tables, section metadata, and relocation information required by debuggers.
