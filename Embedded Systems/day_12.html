12.1 The Need for Direct Memory Access (DMA)

Transferring high-bandwidth data streams—such as 48 kHz 24-bit digital audio, high-speed SPI Flash memory sectors, camera pixel streams, or dense ADC multi-channel arrays—via CPU instructions quickly exhausts processor bandwidth. Using software polling wastes 100% of CPU cycles in busy-wait loops; using an interrupt-per-byte approach creates millions of context switches per second, choking the system with interrupt stacking overhead.

The Direct Memory Access (DMA) controller is a dedicated silicon co-processor architected specifically to transfer high-speed blocks of data directly between memory and peripherals (or memory to memory) across the internal AHB bus matrix with zero CPU intervention. While DMA moves millions of bytes through silicon, the CPU core remains completely free to execute control loops, process neural networks, or sleep in low-power modes.

Real World Example: In a high-resolution thermal imaging camera, a sensor array outputs 30 frames per second at 320x240 resolution (153,600 bytes per frame). An STM32 DMA controller moves 4.6 Megabytes of pixel data per second from the Digital Camera Interface (DCMI) directly into SRAM while the Cortex-M core executes real-time color-palette mapping algorithms concurrently.
Figure 2.3-1: STM32 Dual DMA Controller and Crossbar Interconnect Architecture
Figure Parameters Explained:
  • DMA Controller (DMA1 / DMA2): Independent bus masters arbitrating data transfers across the AHB bus crossbar.
  • Streams (0 through 7): Unidirectional hardware channels capable of managing one independent transfer pipeline.
  • Channel Multiplexer (0 to 7): Hardwired silicon selector routing specific peripheral triggers (e.g. USART2_TX, SPI1_RX, ADC1) to a designated stream.
  • Arbiter: Prioritizes concurrent stream requests using software priority levels (Low, Medium, High, Very High) followed by hardware stream indexing.

12.2 Transfer Directions and DMA Operating Modes

DMA controllers support three fundamental transfer topologies:

  • Peripheral-to-Memory (P2M): Incoming data from an input peripheral (e.g. ADC, UART RX, SPI RX) is written into an SRAM buffer.
  • Memory-to-Peripheral (M2P): Outgoing data from an SRAM buffer is written into a peripheral data register (e.g. DAC, UART TX, SPI TX).
  • Memory-to-Memory (M2M): High-speed hardware memory block copies between different regions of Flash, internal SRAM, or external SDRAM (supported exclusively on DMA2).

In Normal Mode, the DMA stops automatically after transferring $N$ items. In Circular Mode, the DMA automatically resets its pointers upon completion, re-triggering the transfer loop indefinitely without software intervention.

Figure 2.3-2: Peripheral-to-Memory and Memory-to-Peripheral Data Flow
Figure Parameters Explained:
  • Peripheral Address (PAR): Fixed hardware register address (e.g. &USART2->DR); typically configured with no increment.
  • Memory Address (MAR / M0AR): Base address of RAM array; configured with auto-increment enabled to step through buffer.
  • Data Width Matching: Hardware automatically handles packing and unpacking when memory width (e.g. 32-bit word) differs from peripheral width (e.g. 8-bit byte).
  • Number of Data Items (NDTR): 16-bit down-counter decrementing after each transfer; hits 0 to signal Transfer Complete.

12.3 Double-Buffering (Ping-Pong) DMA: Continuous Stream Processing

When processing continuous high-speed data (such as audio DSP filtering or SDR radio telemetry), the processor cannot wait for the DMA buffer to completely fill before processing: stopping the DMA causes sample loss, while processing a buffer while DMA writes to it causes severe race conditions and audio glitching.

Embedded systems solve this using Double-Buffering (Ping-Pong DMA):

  • Buffer Split: A buffer of size $2N$ is divided into two halves: Buffer A (first half) and Buffer B (second half).
  • Half-Transfer Interrupt (HT): Fires when DMA finishes filling Buffer A. The CPU immediately processes Buffer A while the DMA autonomously continues filling Buffer B!
  • Transfer-Complete Interrupt (TC): Fires when DMA finishes filling Buffer B. The CPU processes Buffer B while DMA loops back to overwrite Buffer A!
Figure 2.3-3: Double-Buffer (Ping-Pong) Real-Time Audio Streaming Pipeline
Figure Parameters Explained:
  • Zero Dropped Samples: DMA never halts; hardware transitions seamlessly between Buffer A and Buffer B.
  • Half-Transfer Flag (HTIF): Notifies application that the first half of memory is stable and ready for algorithmic consumption.
  • Transfer Complete Flag (TCIF): Notifies application that the second half of memory is ready for processing.
  • Real-Time Constraint: CPU processing duration for half-buffer must strictly be less than the time DMA takes to fill the other half.

12.4 DMA FIFO Architecture and Burst Transfers

Advanced DMA controllers (such as STM32F4/F7/H7) incorporate a 4-word (16-byte) internal FIFO Buffer per stream. The FIFO decouples peripheral timing from system memory bus timing, enabling Burst Transfers (4-beat, 8-beat, or 16-beat AHB bursts). Instead of arbitrating for the AHB bus matrix on every single byte, the DMA fills its internal FIFO and transfers a burst of words across the bus in consecutive clock cycles, dramatically minimizing bus contention for the CPU.

Figure 2.3-4: DMA FIFO Thresholds and Multi-Beat AHB Burst Transmission
Figure Parameters Explained:
  • Direct Mode: Bypasses FIFO; each peripheral request generates an immediate single AHB bus transfer.
  • FIFO Thresholds: Transfers are deferred until the FIFO accumulates 4, 8, 12, or 16 bytes, packing transfers efficiently.
  • Burst Packaging: Reduces bus arbitration overhead by retaining ownership of the AHB bus across multiple continuous beats.
  • FIFO Error (FEIF): Flags underrun or overrun conditions if peripheral transfer rates exceed internal bus bandwidth.

12.5 The ARM Cortex-M7 Cache Coherency Hazard

High-performance microcontrollers (such as ARM Cortex-M7 and Cortex-M55) incorporate L1 Data Caches (D-Cache). The CPU accesses memory through its high-speed cache, while the DMA controller interfaces directly with physical SRAM. This creates a lethal Cache Coherency Hazard:

  • DMA RX Hazard: DMA writes new sensor data into physical SRAM. However, the CPU reads stale data from its D-Cache because it does not know SRAM changed!
  • DMA TX Hazard: The CPU prepares telemetry in its D-Cache (write-back mode). The DMA streams data from physical SRAM before the cache has flushed dirty words, transmitting obsolete garbage!

Firmware engineers resolve this using Cache Maintenance Instructions (SCB_InvalidateDCache, SCB_CleanDCache) or configuring non-cacheable SRAM regions via the Memory Protection Unit (MPU).

Figure 2.3-5: Cortex-M7 L1 Data Cache Coherency Hazard and MPU Resolution
Figure Parameters Explained:
  • SCB_CleanDCache(): Forces modified dirty cache lines to be flushed out to physical SRAM before DMA transmits.
  • SCB_InvalidateDCache(): Invalidates cached lines, forcing the CPU to fetch fresh data from physical SRAM after DMA receives.
  • 32-Byte Cache Line Alignment: DMA buffers must be aligned to 32-byte boundaries (size multiple of 32) to prevent accidental cache line corruption.
  • MPU Non-Cacheable Zone: Configuring the DMA buffer region as Non-Cacheable in the MPU completely eliminates coherency hazards.

12.6 Hands-On Code Implementations


#include <stdint.h>

#define RCC_AHB1ENR         (*(volatile uint32_t *)0x40023830UL)
#define DMA2_BASE           0x40026400UL
#define DMA2_S0CR           (*(volatile uint32_t *)(DMA2_BASE + 0x10UL))
#define DMA2_S0NDTR         (*(volatile uint32_t *)(DMA2_BASE + 0x14UL))
#define DMA2_S0PAR          (*(volatile uint32_t *)(DMA2_BASE + 0x18UL))
#define DMA2_S0M0AR         (*(volatile uint32_t *)(DMA2_BASE + 0x1CUL))

#define BUFFER_SIZE         256
static uint16_t g_adc_samples[BUFFER_SIZE];

void dma2_adc_circular_init(void) {
    /* 1. Enable DMA2 clock in RCC */
    RCC_AHB1ENR |= (1UL << 22);

    /* 2. Disable Stream 0 to configure */
    DMA2_S0CR &= ~(1UL << 0);
    while (DMA2_S0CR & (1UL << 0));

    /* 3. Set Peripheral Address to ADC1 Data Register */
    DMA2_S0PAR = 0x4001204CUL;

    /* 4. Set Memory Address to SRAM buffer */
    DMA2_S0M0AR = (uint32_t)g_adc_samples;

    /* 5. Set Number of Data Items */
    DMA2_S0NDTR = BUFFER_SIZE;

    /* 6. Configure Stream 0:
     * - Channel 0 (ADC1)
     * - Peripheral size 16-bit (PSIZE = 0b01)
     * - Memory size 16-bit (MSIZE = 0b01)
     * - Memory increment enabled (MINC = 1)
     * - Circular mode enabled (CIRC = 1)
     * - Direction: Peripheral-to-Memory (DIR = 0b00)
     */
    DMA2_S0CR = (0UL << 25) | (1UL << 13) | (1UL << 11) | 
                (1UL << 10) | (1UL << 8)  | (0UL << 6);

    /* 7. Enable DMA Stream */
    DMA2_S0CR |= (1UL << 0);
}

#define AUDIO_BUF_SIZE      512
#define HALF_BUF_SIZE       (AUDIO_BUF_SIZE / 2)

static int16_t g_audio_ping_pong[AUDIO_BUF_SIZE];

/* Prototype for application DSP filter */
void process_audio_half_buffer(int16_t *buffer, uint16_t length);

/* DMA Interrupt Service Routine */
void DMA1_Stream5_IRQHandler(void) {
    volatile uint32_t isr = *(volatile uint32_t *)0x40026000UL; /* DMA_HISR */

    /* Half-Transfer Interrupt: Buffer A (first half) is full */
    if (isr & (1UL << 10)) {
        *(volatile uint32_t *)0x40026008UL = (1UL << 10); /* Clear HTIF */
        process_audio_half_buffer(&g_audio_ping_pong[0], HALF_BUF_SIZE);
    }

    /* Transfer-Complete Interrupt: Buffer B (second half) is full */
    if (isr & (1UL << 11)) {
        *(volatile uint32_t *)0x40026008UL = (1UL << 11); /* Clear TCIF */
        process_audio_half_buffer(&g_audio_ping_pong[HALF_BUF_SIZE], HALF_BUF_SIZE);
    }
}

The CPU reads from its internal cache. If DMA updates physical SRAM, the cache becomes stale unless invalidated by software.
4. Why must DMA memory buffers on ARM Cortex-M7 systems be aligned to 32-byte address boundaries?
  • To match the 32-byte cache line size of the L1 Data Cache, preventing adjacent variable corruption during cache invalidation
  • Because Cortex-M7 can only address memory in 32-byte chunks
  • To double the baud rate of the UART
  • To enable hardware floating point instructions
Cache maintenance operates on whole 32-byte cache lines. Unaligned buffers risk invalidating neighboring variables that happen to share the same line.
5. In STM32 microcontrollers, which DMA controller supports high-speed Memory-to-Memory (M2M) transfers?
  • DMA1 only
  • DMA2 only
  • Both DMA1 and DMA2 equally
  • Neither; M2M requires external FPGA bridges
On STM32 architectures, only DMA2 has master bus access to both memory ports of the AHB crossbar matrix required for Memory-to-Memory transfers.
6. What is the function of the DMA Number of Data Items (NDTR) register?
  • It sets the baud rate
  • It is a 16-bit down-counter tracking the remaining items to transfer, automatically decrementing after each transfer cycle
  • It stores the checksum of the buffer
  • It defines the priority level of the stream
NDTR indicates how many data items remain to be transferred. When it reaches 0, the Transfer Complete flag (TCIF) asserts.
7. What occurs when a DMA stream is configured in Circular Mode?
  • The stream halts after one buffer and waits for CPU reset
  • Upon transferring the last item, NDTR reloads automatically and memory pointers reset to the start, looping indefinitely
  • The memory buffer is erased with zeroes
  • The stream alternates between SPI and UART
Circular mode re-arms the transfer parameters automatically, making it ideal for continuous ADC sampling and streaming audio.
8. What is the purpose of the 4-word FIFO incorporated into STM32 DMA streams?
  • To encrypt telemetry packets
  • To pack individual bytes into multi-word AHB burst transfers, drastically reducing AHB bus arbitration contention
  • To convert analog signals to digital integers
  • To store task context during RTOS interrupts
The FIFO buffers bytes until threshold is reached, executing a multi-beat burst across the memory bus in consecutive cycles.
9. What interrupt flag indicates that exactly half of the total DMA buffer has been transferred?
  • TCIF (Transfer Complete Interrupt Flag)
  • HTIF (Half-Transfer Interrupt Flag)
  • TEIF (Transfer Error Interrupt Flag)
  • FEIF (FIFO Error Interrupt Flag)
HTIF asserts when the counter decrements through half the initial NDTR value, signaling that the first half of memory is ready for processing.
10. Why is `SCB_CleanDCache()` mandatory before initiating a DMA transmit (M2P) on a cached microcontroller?
  • To clear all peripheral interrupt masks
  • To flush modified dirty data from the L1 Data Cache to physical SRAM so the DMA controller reads current values rather than stale memory
  • To double the clock prescaler
  • To reset the DMA FIFO pointers
If the CPU updated a buffer in write-back cache, physical SRAM contains obsolete data until the cache line is explicitly cleaned (flushed).
