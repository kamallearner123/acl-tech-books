8.1 Module 1 Capstone: End-to-End System Architecture

Over the preceding seven days, we mastered individual hardware peripherals in isolation: clock tree configuration, bare-metal GPIO manipulation, atomic bitmask registers, interrupt handling via the NVIC, precision hardware timers, analog-to-digital conversion, and serial protocols. In this Module 1 Capstone Project, we integrate these disparate elements into an integrated, production-grade Interrupt-Driven Sensor Logging Engine.

The goal is to build an autonomous embedded data logger that samples an analog NTC thermistor and an I2C barometric pressure sensor periodically, buffers measurements inside a thread-safe circular ring buffer, serializes data into structured ASCII NMEA-style frames with checksum validation, and streams telemetry over UART using DMA—all while maximizing processor sleep time between acquisition cycles.

Real World Application: This architecture serves as the foundation for industrial condition-monitoring sensor pods installed on wind turbines and railroad wheel bearings. These pods monitor thermal decay and vibration signatures, streaming periodic time-stamped health frames over RS-485 serial buses to predictive maintenance gateways.

8.2 The Thread-Safe Circular Ring Buffer Design Pattern

When an interrupt-driven peripheral produces data faster than a communication channel can transmit it (or when transmission bursts require temporary staging), firmware engineers employ a Circular Ring Buffer (FIFO). The buffer uses fixed-size memory with two monotonic index pointers: head (where producers write new data) and tail (where consumers read old data).

By sizing the buffer to an exact power of two ($2^N$), index wrap-around is achieved using an ultra-fast bitwise AND mask (index = (index + 1) & (BUFFER_SIZE - 1)) rather than costly division or modulo operations. Furthermore, when single-byte indices are used, producer-consumer operations remain inherently atomic on 32-bit Cortex-M processors.

Figure 1.7-2: Power-of-Two Circular Ring Buffer (FIFO) Architecture
Figure Parameters Explained:
  • Head Pointer: Index where the Producer (Timer / ADC ISR) writes the next incoming sensor packet.
  • Tail Pointer: Index where the Consumer (UART DMA engine) reads the next pending packet for transmission.
  • Bitwise Wrap-Around: Buffer size = 16 (0x10); Mask = 15 (0x0F). Index 15 + 1 becomes (16 & 0x0F) = 0 automatically.
  • Buffer Full Condition: One slot is left empty to distinguish unambiguously between an empty buffer and a full buffer.

8.3 The Interrupt-Driven Sensor Acquisition Pipeline

To eliminate CPU busy-wait loops, the data acquisition pipeline is governed entirely by hardware events:

  1. Hardware Timer Trigger: General-purpose timer TIM2 fires an Update Event (UEV) every 100 milliseconds.
  2. ADC Conversion: TIM2 TRGO triggers ADC1 conversion of the NTC thermistor channel in hardware.
  3. ADC End of Conversion (EOC): ADC ISR reads the converted digital value, kicks off a rapid non-blocking I2C read of the BMP280 sensor, and calculates physical engineering units.
  4. Ring Buffer Push: The resulting sensor packet is pushed into the circular telemetry ring buffer.
  5. UART DMA Dispatch: If the UART DMA transmitter is idle, the next packet is serialized and DMA transmission begins immediately.
Figure 1.7-3: Data Pipeline: Hardware Timer Trigger to UART DMA Output
Figure Parameters Explained:
  • TIM2 TRGO Trigger: Hardware internal routing triggers ADC conversion without CPU software intervention.
  • Decoupled Producer/Consumer: ISRs quickly push raw readings into the ring buffer; serialization and formatting occur in background thread.
  • Non-Blocking Execution: No peripheral driver ever halts CPU execution with while-loop polling flags.

8.4 Structured ASCII Log Frame Format with XOR Checksum

To ensure robust data parsing on host systems (such as Python telemetry collectors or industrial PLCs), sensor readings are formatted into standardized ASCII frames modeled after the marine NMEA-0183 standard. Each frame incorporates a preamble header, sequence counter, comma-separated engineering values, and an 8-bit XOR checksum to detect line corruption:

$LOG,<seq>,<temp_c>,<pressure_pa>,<uptime_ms>*<XOR_HEX>

Example: $LOG,1042,24.85,101325,104200*5B
Figure 1.7-4: Structured ASCII Log Frame Packet Format and Checksum Verification
Figure Parameters Explained:
  • Preamble ($LOG): Enables the host parser to resynchronize immediately if serial bytes are dropped or garbled.
  • Sequence Counter: Monotonically increasing integer tracking packet loss over long deployment periods.
  • XOR Checksum: Computed by XOR-ing all ASCII character bytes between '$' and '*'. Guaranteed detection of single-bit bursts.
  • CRLF (\r\n): Standard end-of-frame packet delimiter for stream-based line buffering.

8.5 Overrun Detection and Fault Management

In real-world deployment, serial cables may be disconnected or transmission buffers may fill up if the baud rate is insufficient. A production-grade embedded logger must detect and report Buffer Overrun Faults. When a newly generated sensor reading cannot fit into the ring buffer, an overrun counter is incremented, an amber Error LED is illuminated, and a diagnostic fault flag is injected into the next successful log packet.

Figure 1.7-5: Sensor Logger Operational State Machine Flowchart
Figure Parameters Explained:
  • STATE_INIT: Configures PLL to 168 MHz, initializes GPIOs, Timers, ADC, I2C, and UART DMA.
  • STATE_SLEEP: Executes WFI instruction; CPU core halts clocking, saving up to 80% dynamic power.
  • FAULT_OVERRUN: Latches overrun event, sets diagnostic warning flag, and asserts hardware alert pin.

#include <stdint.h>

#define RCC_BASE        0x40023800UL
#define RCC_CR          (*(volatile uint32_t *)(RCC_BASE + 0x00UL))
#define RCC_PLLCFGR     (*(volatile uint32_t *)(RCC_BASE + 0x04UL))
#define RCC_CFGR        (*(volatile uint32_t *)(RCC_BASE + 0x08UL))
#define FLASH_ACR       (*(volatile uint32_t *)0x40023C00UL)

/* Configure STM32F4 clock tree: External 8MHz Crystal (HSE) -> PLL -> 168 MHz Core Clock */
void bsp_clock_init_168mhz(void) {
    /* 1. Enable HSE oscillator */
    RCC_CR |= (1UL << 16);
    while (!(RCC_CR & (1UL << 17))); /* Wait for HSE ready */

    /* 2. Configure Flash Latency: 5 wait states for 168 MHz operation at 3.3V */
    FLASH_ACR = (1UL << 9) | (1UL << 10) | (5UL << 0); /* Prefetch, I-Cache, D-Cache, 5 WS */

    /* 3. Configure PLL: PLL_M = 8, PLL_N = 336, PLL_P = 2 -> (8MHz / 8) * 336 / 2 = 168 MHz */
    RCC_PLLCFGR = (8UL << 0) | (336UL << 6) | (0UL << 16) | (1UL << 22);

    /* 4. Enable PLL */
    RCC_CR |= (1UL << 24);
    while (!(RCC_CR & (1UL << 25))); /* Wait for PLL ready */

    /* 5. Set AHB prescaler = 1 (168MHz), APB1 = 4 (42MHz), APB2 = 2 (84MHz) */
    RCC_CFGR |= (0UL << 4) | (5UL << 10) | (4UL << 13);

    /* 6. Switch System Clock source to PLL */
    RCC_CFGR |= (2UL << 0);
    while ((RCC_CFGR & (3UL << 2)) != (2UL << 2)); /* Wait for switch */
}

#include <stdint.h>
#include <stdbool.h>

#define RING_BUFFER_SIZE    16 /* Must be power of two */
#define RING_BUFFER_MASK    (RING_BUFFER_SIZE - 1)

typedef struct {
    uint32_t timestamp_ms;
    float    temperature_c;
    float    pressure_pa;
    uint32_t sequence_num;
} SensorRecord_t;

typedef struct {
    SensorRecord_t records[RING_BUFFER_SIZE];
    volatile uint8_t head;
    volatile uint8_t tail;
    volatile uint32_t overrun_count;
} TelemetryRingBuffer_t;

void ring_buf_init(TelemetryRingBuffer_t *rb) {
    rb->head = 0;
    rb->tail = 0;
    rb->overrun_count = 0;
}

bool ring_buf_push(TelemetryRingBuffer_t *rb, const SensorRecord_t *item) {
    uint8_t next_head = (rb->head + 1) & RING_BUFFER_MASK;
    
    if (next_head == rb->tail) {
        /* Buffer is full! Record overrun event */
        rb->overrun_count++;
        return false;
    }
    
    rb->records[rb->head] = *item;
    rb->head = next_head;
    return true;
}

bool ring_buf_pop(TelemetryRingBuffer_t *rb, SensorRecord_t *item) {
    if (rb->head == rb->tail) {
        return false; /* Buffer empty */
    }
    
    *item = rb->records[rb->tail];
    rb->tail = (rb->tail + 1) & RING_BUFFER_MASK;
    return true;
}

#include <stdint.h>

/* Sensor acquisition API returning physical engineering units */
float sensor_read_ntc_temperature(void) {
    /* Reads PA0 ADC1 channel, computes Steinhart-Hart equation */
    uint16_t raw_adc = 2048; /* Simulated nominal reading */
    float voltage = (raw_adc / 4095.0f) * 3.3f;
    float resistance = 10000.0f * (voltage / (3.3f - voltage));
    
    /* Approximate linear conversion around 25C for demonstration */
    return 25.0f + (10000.0f - resistance) * 0.005f;
}

float sensor_read_bmp280_pressure(void) {
    /* Reads BMP280 via I2C1 registers, applies factory calibration */
    return 101325.0f; /* Standard atmospheric pressure in Pascals */
}

#include <stdint.h>
#include <stdio.h>
#include <string.h>

uint8_t calculate_xor_checksum(const char *str) {
    uint8_t checksum = 0;
    /* Skip leading '$' if present */
    if (*str == '$') str++;
    
    while (*str && *str != '*') {
        checksum ^= (uint8_t)(*str++);
    }
    return checksum;
}

int serialize_log_frame(char *buffer, uint16_t max_len, uint32_t seq, float temp, float press, uint32_t time_ms) {
    char temp_buf[96];
    
    /* Format payload without checksum */
    int len = snprintf(temp_buf, sizeof(temp_buf), "$LOG,%lu,%.2f,%.0f,%lu*", 
                       seq, temp, press, time_ms);
                       
    if (len < 0 || len >= (int)sizeof(temp_buf)) return -1;
    
    /* Compute 8-bit XOR checksum */
    uint8_t chk = calculate_xor_checksum(temp_buf);
    
    /* Append checksum in two hex digits and CRLF */
    return snprintf(buffer, max_len, "%s%02X\r\n", temp_buf, chk);
}
Program 1.7-4: NMEA-Style Log Frame Serializer with XOR Checksum Calculation 

#include <stdint.h>
#include <stdbool.h>

static TelemetryRingBuffer_t g_telemetry_queue;
static volatile bool g_sample_trigger_flag = false;
static uint32_t g_sequence_counter = 0;

/* TIM2 Interrupt Service Routine: Sets trigger flag every 100 ms */
void TIM2_IRQHandler(void) {
    /* Clear update interrupt flag */
    *(volatile uint32_t *)0x40000010UL &= ~(1UL << 0);
    g_sample_trigger_flag = true;
}

int main(void) {
    bsp_clock_init_168mhz();
    ring_buf_init(&g_telemetry_queue);
    
    char tx_packet_buffer[128];

    while (1) {
        if (g_sample_trigger_flag) {
            g_sample_trigger_flag = false;
            
            /* Acquire sensor telemetry */
            SensorRecord_t record;
            record.timestamp_ms = g_sequence_counter * 100;
            record.temperature_c = sensor_read_ntc_temperature();
            record.pressure_pa = sensor_read_bmp280_pressure();
            record.sequence_num = ++g_sequence_counter;
            
            /* Push to circular buffer */
            if (!ring_buf_push(&g_telemetry_queue, &record)) {
                /* Hardware Error LED assertion on buffer overrun */
            }
        }
        
        /* Process pending queue records */
        SensorRecord_t pending_item;
        if (ring_buf_pop(&g_telemetry_queue, &pending_item)) {
            int frame_len = serialize_log_frame(tx_packet_buffer, sizeof(tx_packet_buffer),
                                               pending_item.sequence_num,
                                               pending_item.temperature_c,
                                               pending_item.pressure_pa,
                                               pending_item.timestamp_ms);
            if (frame_len > 0) {
                /* Initiate non-blocking UART DMA streaming */
            }
        }
        
        /* Sleep until next hardware interrupt */
        __asm__ volatile("wfi");
    }
    return 0;
}

  • A Buffer Overrun condition occurs; firmware must either drop the sample or overwrite oldest data while logging the fault
  • The timer frequency is automatically halved
  • The UART baud rate is doubled
A full buffer cannot accept new items without dropping them or overwriting unread data. Robust systems log the overrun count to alert supervisors.
4. What instruction is executed at the end of the main acquisition loop to put the ARM Cortex-M processor into low-power sleep until the next interrupt?
  • NOP
  • WFI (Wait For Interrupt)
  • SVC 0
  • BKPT 0
The WFI (Wait For Interrupt) instruction stops the CPU core clock, drastically cutting power consumption until any enabled interrupt wakes it.
5. Why is separating the raw data acquisition (in ISR) from the ASCII string formatting (in main loop) an essential architectural pattern?
  • Because string formatting functions like snprintf() are heavy and non-reentrant, and would severely inflate interrupt latency if executed inside an ISR
  • Because ISRs cannot access character arrays
  • Because snprintf() requires an external FPU coprocessor
  • Because ASCII characters cannot be stored in SRAM
String formatting consumes thousands of clock cycles and stack memory. Executing it inside an ISR starves other urgent hardware interrupts.
6. How does the ring buffer full condition `(head + 1) & MASK == tail` prevent ambiguous buffer states?
  • It leaves one buffer slot intentionally empty so `head == tail` always uniquely denotes an empty buffer
  • It doubles the buffer capacity automatically
  • It triggers a DMA interrupt
  • It reverses the queue direction
Reserving one empty slot guarantees that head == tail signifies an empty queue, while (head + 1) & MASK == tail uniquely identifies a full queue.
7. What clock configuration step must be executed before increasing the CPU core frequency from 16 MHz to 168 MHz on an STM32F4?
  • Disabling all GPIO pins
  • Increasing the Flash ACR wait states (latency) to 5 wait states to prevent memory read corruption
  • Enabling the software watchdog
  • Setting all UART ports to 9600 baud
Internal Flash memory cannot be read at 168 MHz. Software must increase Flash wait states (latency cycles) in FLASH_ACR before accelerating the clock.
8. What is the primary benefit of streaming telemetry packets via UART using a DMA controller instead of an interrupt-per-byte approach?
  • DMA eliminates electromagnetic interference
  • DMA requires zero CPU interrupts during the entire multi-byte packet transfer, firing only once when the transmission completes
  • DMA automatically verifies the XOR checksum
  • DMA converts ASCII characters to binary bytes
DMA offloads memory-to-peripheral transfers entirely, freeing the CPU core to sleep or compute sensor filters without taking 100+ context switches.
9. In the context of the sensor logger, why is a monotonically increasing sequence counter included in each transmitted frame?
  • To calibrate the ADC voltage reference
  • To allow the receiving host to immediately detect dropped packets or transmission dropouts
  • To set the real-time clock time
  • To synchronize SPI phase clocks
A missing sequence number (e.g. jumping from 104 to 106) immediately alerts the receiving system that a packet was lost over the communication channel.
10. What hardware peripheral trigger automatically initiates the ADC conversion in our Capstone pipeline without CPU software intervention?
  • TIM2 TRGO (Trigger Output) event
