13.1 The Backbone of Automotive Electronics: CAN Bus Architecture

Modern automobiles contain between 70 and 150 independent Electronic Control Units (ECUs) controlling powertrain, braking, steering, battery management, climate control, and body lighting. Point-to-point wiring between all ECUs would create an unimaginably heavy, expensive, and fault-prone copper wiring harness weighing over 100 kilograms! In 1986, Robert Bosch GmbH invented the Controller Area Network (CAN Bus) to solve this crisis with a robust, multi-drop, two-wire differential serial network.

CAN operates with extreme noise immunity in harsh electromagnetic environments (such as proximity to ignition coils and electric traction inverters). The physical layer consists of two twisted-pair copper wires labeled CAN_H (High) and CAN_L (Low) terminated at both physical ends with 120-ohm resistors to prevent high-frequency transmission line signal reflections.

Automotive Reality: When you press the brake pedal in a car, the Hydraulic Brake ECU broadcasts a high-priority CAN message with ID 0x0C8. The Engine ECU, Transmission ECU, and Regenerative Inverter ECU all receive and act upon this exact same packet simultaneously within 500 microseconds over the vehicle CAN bus.
Figure 2.4-1: CAN Physical Layer Differential Signaling and Bus Voltage Levels
Figure Parameters Explained:
  • Recessive Bit (Logic 1): CANH = 2.5V, CANL = 2.5V (V_diff = 0V). Driven weakly; can be overridden by any transmitter.
  • Dominant Bit (Logic 0): CANH = 3.5V, CANL = 1.5V (V_diff = 2.0V). Actively driven; dominates the bus completely.
  • Common-Mode Noise Rejection: Electromagnetic noise couples equally into both twisted wires; the receiver differential amplifier (CANH - CANL) subtracts common-mode spikes perfectly.
  • 120 Ohm Termination Resistors: Placed across CANH and CANL at the two extreme cable ends to match the 120-ohm characteristic impedance of the twisted pair.

13.2 CAN Data Frame Architecture: 11-Bit Standard vs. 29-Bit Extended

Unlike Ethernet or IP packets, CAN messages do not contain source or destination node addresses. Instead, CAN messages are content-addressed: every frame contains an Arbitration Identifier (ID) that identifies the meaning and real-time urgency of the payload (e.g. ID 0x0C0 = Engine RPM). There are two standard framing formats:

  • CAN 2.0A (Standard Format): 11-bit identifier (allowing $2^{11} = 2048$ unique message IDs).
  • CAN 2.0B (Extended Format): 29-bit identifier (11-bit base ID + 18-bit extended ID, yielding over 536 million unique message IDs, standard in SAE J1939 heavy trucks).
Figure 2.4-2: CAN 2.0A Standard Data Frame Bit-Level Architecture
Figure Parameters Explained:
  • SOF (Start of Frame): Single dominant bit synchronizing all receiving node clocks on the bus.
  • Arbitration ID: 11-bit message identifier; also serves as the message priority during bus contention.
  • RTR (Remote Transmission Request): 0 for Data Frames; 1 for Remote Frames requesting data from another node.
  • DLC (Data Length Code): 4-bit binary field defining payload length from 0 to 8 bytes.
  • CRC (Cyclic Redundancy Check): 15-bit polynomial error detection code protecting frame integrity.
  • ACK Slot: Transmitter sends recessive 1; any receiver that decodes a valid CRC drives dominant 0 to acknowledge.

13.3 Non-Destructive Bitwise Arbitration (CSMA/CR)

CAN operates under Carrier Sense Multiple Access with Collision Resolution (CSMA/CR). Multiple nodes can begin transmitting simultaneously. While transmitting the arbitration ID, each node monitors the physical bus voltage. If Node A transmits a recessive 1 but reads back a dominant 0 (because Node B transmitted a 0), Node A realizes it lost arbitration. Node A immediately ceases transmission and switches to receiver mode, allowing Node B to continue uninterrupted with zero lost bus cycles!

Core Rule of CAN Arbitration: The lower the numerical ID value, the higher the message priority.

Figure 2.4-3: Non-Destructive Bitwise Bus Arbitration in Action
Figure Parameters Explained:
  • Bit-by-Bit Arbitration: Nodes transmit their ID MSB first; dominant bits (0) override recessive bits (1).
  • Zero Collisions: Unlike Ethernet CSMA/CD, no bandwidth is wasted on collision backoffs; the highest-priority message completes without delay.
  • Bus Latency Guarantee: Highest-priority frames (e.g. 0x000) experience zero arbitration delay regardless of total bus traffic load.

13.4 Bit Timing, Time Quanta, and Sample Point Configuration

Because CAN is asynchronous, every node must independently reconstruct bit boundaries. A single nominal bit time is divided into 4 non-overlapping segments composed of integer multiples of Time Quanta ($t_q$):

  • Sync_Seg (Synchronization Segment): 1 $t_q$. Edge transitions occur here.
  • Prop_Seg (Propagation Segment): Compensates for physical wire delays and transceiver delays.
  • Phase_Seg1 & Phase_Seg2: Compensate for oscillator phase errors; adjusted dynamically via the Synchronization Jump Width (SJW).

The point where the bit value is latched is the Sample Point. Automotive standards (CiA 303-1) mandate locating the sample point at exactly 87.5% of the bit time for 500 kbps powertrain networks.

Figure 2.4-4: CAN Bit Timing Segments and 87.5% Sample Point Location
Figure Parameters Explained:
  • Time Quantum (t_q): Basic unit of timer resolution derived from prescaled peripheral APB clock.
  • Baud Rate Formula: Baud Rate = 1 / (Nominal Bit Time) = f_clk / (BRP * (1 + TS1 + TS2)).
  • Sample Point Position: Sample Point (%) = ((1 + TS1) / (1 + TS1 + TS2)) * 100.
  • SJW (Sync Jump Width): Maximum number of time quanta by which Phase Segments can be lengthened or shortened to resynchronize.

13.5 Fault Confinement: Error State Machine & Bus-Off Recovery

CAN incorporates hardware fault confinement to prevent a malfunctioning ECU from bringing down the entire vehicle network. Each node maintains two internal error counters: Transmit Error Counter (TEC) and Receive Error Counter (REC). Based on error counts, a node transitions through three states:

  1. Error-Active (TEC < 128, REC < 128): Normal operation; transmits active error flags (dominant 0s).
  2. Error-Passive (TEC ≥ 128 or REC ≥ 128): Node is degraded; transmits passive error flags (recessive 1s) to avoid disrupting the bus.
  3. Bus-Off (TEC > 255): The node is completely disconnected from the bus by hardware; it cannot transmit or receive. Safe recovery requires explicit software reset or waiting for 128 occurrences of 11 consecutive recessive bits.
Figure 2.4-5: CAN Node Fault Confinement Finite State Machine
Figure Parameters Explained:
  • TEC / REC Counters: Incremented on transmit/receive errors (bit error, stuff error, CRC error, form error, ACK error).
  • Bus-Off State: Isolates a damaged ECU from the vehicle bus so it cannot jam communication.
  • Automatic Bus-Off Recovery: Requires software to clear the ABOM bit or monitor 128 occurrences of bus idle sequences.

13.6 Hands-On Code Implementations


#include <stdint.h>

#define RCC_APB1ENR     (*(volatile uint32_t *)0x40023840UL)
#define CAN1_BASE       0x40006400UL
#define CAN_MCR         (*(volatile uint32_t *)(CAN1_BASE + 0x00UL))
#define CAN_MSR         (*(volatile uint32_t *)(CAN1_BASE + 0x04UL))
#define CAN_BTR         (*(volatile uint32_t *)(CAN1_BASE + 0x1CUL))

/* Configure CAN1 at 500 kbps assuming 42 MHz APB1 peripheral clock:
 * Target: 500 kbps -> Bit Time = 2000 ns.
 * Total Time Quanta = 14 tq -> 1 tq = 142.85 ns -> Prescaler BRP = 6 (42MHz / 6 = 7 MHz).
 * Sync_Seg = 1 tq, TS1 = 11 tq, TS2 = 2 tq -> Total = 14 tq.
 * Sample Point = (1 + 11) / 14 = 85.7% (Meets ISO 11898 standard).
 */
void can1_init_500kbps(void) {
    /* 1. Enable CAN1 peripheral clock */
    RCC_APB1ENR |= (1UL << 25);

    /* 2. Request Initialization mode (INRQ = 1) and exit sleep (SLEEP = 0) */
    CAN_MCR |= (1UL << 0);
    CAN_MCR &= ~(1UL << 1);
    while (!(CAN_MSR & (1UL << 0))); /* Wait for INAK initialization acknowledge */

    /* 3. Configure Bit Timing: BRP=6, TS1=11, TS2=2, SJW=1 */
    /* Note: Register fields store (Value - 1) */
    CAN_BTR = ((1UL - 1UL) << 24)  |  /* SJW = 1 tq */
              ((2UL - 1UL) << 20)  |  /* TS2 = 2 tq */
              ((11UL - 1UL) << 16) |  /* TS1 = 11 tq */
              ((6UL - 1UL) << 0);     /* BRP = 6 */

    /* 4. Exit Initialization mode into Normal operating mode */
    CAN_MCR &= ~(1UL << 0);
    while (CAN_MSR & (1UL << 0));     /* Wait for INAK cleared */
}
Program 2.4-1: STM32 bxCAN Controller Initialization (500 kbps, 87.5% Sample Point) 

#include <stdint.h>
#include <stdbool.h>

#define CAN_TI0R        (*(volatile uint32_t *)0x40006580UL)
#define CAN_TDT0R       (*(volatile uint32_t *)0x40006584UL)
#define CAN_TDL0R       (*(volatile uint32_t *)0x40006588UL)
#define CAN_TDH0R       (*(volatile uint32_t *)0x4000658CUL)
#define CAN_TSR         (*(volatile uint32_t *)0x40006408UL)

/* Transmit 8-byte CAN message: ID 0x100 (Standard), Engine RPM + Throttle Position */
bool can_transmit_engine_frame(uint16_t rpm, uint8_t throttle_percent) {
    /* Check if Mailbox 0 is empty (TME0 = 1) */
    if (!(CAN_TSR & (1UL << 26))) {
        return false; /* All mailboxes busy */
    }

    /* 1. Set 11-bit Standard Identifier into bits [31:21] */
    CAN_TI0R = (0x100UL << 21);

    /* 2. Set Data Length Code (DLC = 8 bytes) */
    CAN_TDT0R = (8UL << 0);

    /* 3. Pack payload: Bytes 0-1 = RPM (big-endian), Byte 2 = Throttle % */
    uint32_t data_low = ((uint32_t)(rpm >> 8) << 0)  |
                        ((uint32_t)(rpm & 0xFF) << 8) |
                        ((uint32_t)throttle_percent << 16);
    CAN_TDL0R = data_low;
    CAN_TDH0R = 0x00000000; /* Remaining bytes */

    /* 4. Request transmission by setting TXRQ bit */
    CAN_TI0R |= (1UL << 0);
    return true;
}
Program 2.4-2: CAN Message Transmit Engine: Broadcasting Engine Telemetry 

#include <stdint.h>

#define CAN_FMR         (*(volatile uint32_t *)0x40006600UL)
#define CAN_FA1R        (*(volatile uint32_t *)0x4000661CUL)
#define CAN_FS1R        (*(volatile uint32_t *)0x4000660CUL)
#define CAN_FM1R        (*(volatile uint32_t *)0x40006604UL)
#define CAN_FFA1R       (*(volatile uint32_t *)0x40006614UL)
#define CAN_F0R1        (*(volatile uint32_t *)0x40006640UL)
#define CAN_F0R2        (*(volatile uint32_t *)0x40006644UL)

/* Configure Filter Bank 0: Accept only CAN IDs 0x100 through 0x1FF (Mask 0x700) */
void can_filter_config(void) {
    /* Enter Filter Initialization mode */
    CAN_FMR |= (1UL << 0);

    /* Deactivate Filter Bank 0 */
    CAN_FA1R &= ~(1UL << 0);

    /* 32-bit scale for Filter Bank 0 */
    CAN_FS1R |= (1UL << 0);

    /* Id/Mask mode (FM1R = 0) */
    CAN_FM1R &= ~(1UL << 0);

    /* Assign to FIFO 0 (FFA1R = 0) */
    CAN_FFA1R &= ~(1UL << 0);

    /* Filter ID: 0x100 (aligned to bits [31:21]) */
    CAN_F0R1 = (0x100UL << 21);

    /* Filter Mask: 0x700 (Matches upper 3 bits: only 0x100-0x1FF accepted) */
    CAN_F0R2 = (0x700UL << 21);

    /* Activate Filter Bank 0 */
    CAN_FA1R |= (1UL << 0);

    /* Exit Filter Initialization mode */
    CAN_FMR &= ~(1UL << 0);
}
Program 2.4-3: Hardware Acceptance Filter Configuration (Filter Bank 0) 

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <net/if.h>
#include <sys/ioctl.h>
#include <sys/socket.h>
#include <linux/can.h>
#include <linux/can/raw.h>

int main(void) {
    int s;
    struct sockaddr_can addr;
    struct ifreq ifr;
    struct can_frame frame;

    /* 1. Open raw CAN socket */
    s = socket(PF_CAN, SOCK_RAW, CAN_RAW);
    strcpy(ifr.ifr_name, "can0");
    ioctl(s, SIOCGIFINDEX, &ifr);

    addr.can_family = AF_CAN;
    addr.can_ifindex = ifr.ifr_ifindex;
    bind(s, (struct sockaddr *)&addr, sizeof(addr));

    /* 2. Populate CAN 2.0A frame */
    frame.can_id = 0x100;
    frame.can_dlc = 8;
    frame.data[0] = 0x0A; /* RPM High */
    frame.data[1] = 0x28; /* RPM Low (2600 RPM) */
    frame.data[2] = 45;   /* Throttle 45% */

    /* 3. Send frame to virtual or physical CAN bus */
    write(s, &frame, sizeof(struct can_frame));
    printf("Transmitted CAN frame ID 0x%03X successfully over can0\n", frame.can_id);

    close(s);
    return 0;
}
Program 2.4-4: Linux SocketCAN Host Client in C (send_can.c) 

#include <stdint.h>
#include <stdio.h>

#define CAN_RI0R        (*(volatile uint32_t *)0x400065B0UL)
#define CAN_RDT0R       (*(volatile uint32_t *)0x400065B4UL)
#define CAN_RDL0R       (*(volatile uint32_t *)0x400065B8UL)
#define CAN_RDH0R       (*(volatile uint32_t *)0x400065BCUL)
#define CAN_RF0R        (*(volatile uint32_t *)0x4000640CUL)

void can_sniffer_poll(void) {
    /* Check if message pending in FIFO 0 */
    if ((CAN_RF0R & (3UL << 0)) != 0) {
        uint32_t id = (CAN_RI0R >> 21) & 0x7FF;
        uint8_t dlc = CAN_RDT0R & 0x0F;
        uint32_t data_l = CAN_RDL0R;
        uint32_t data_h = CAN_RDH0R;

        printf("CAN RX -> ID: 0x%03lX | DLC: %u | DATA: %02lX %02lX %02lX %02lX %02lX %02lX %02lX %02lX\r\n",
               id, dlc,
               (data_l >> 0) & 0xFF, (data_l >> 8) & 0xFF, (data_l >> 16) & 0xFF, (data_l >> 24) & 0xFF,
               (data_h >> 0) & 0xFF, (data_h >> 8) & 0xFF, (data_h >> 16) & 0xFF, (data_h >> 24) & 0xFF);

        /* Release FIFO 0 output mailbox */
        CAN_RF0R |= (1UL << 5);
    }

Topic Quiz (10 Questions)

Test your conceptual understanding of today's embedded systems architecture, registers, and runtime behaviors.

1. What is the physical voltage level on the CAN_H and CAN_L lines during a Recessive (Logic 1) state?
  • CAN_H = 0V, CAN_L = 0V
  • CAN_H = 2.5V, CAN_L = 2.5V (Differential Voltage = 0V)
  • CAN_H = 5.0V, CAN_L = 0V
  • CAN_H = 3.5V, CAN_L = 1.5V
During recessive bits, both lines idle at half the transceiver supply (2.5V), yielding zero differential voltage across the termination resistors.
2. In CAN bus bitwise arbitration, which message wins bus access when two nodes transmit at the exact same instant?
  • The message with the larger payload size (DLC)
  • The message with the numerically lower Arbitration ID
  • The message with the numerically higher Arbitration ID
  • The node closest to the 120-ohm termination resistor
Dominant bits (0) override recessive bits (1). Therefore, frames with lower numerical IDs contain more leading zeroes and win arbitration.
3. Why are 120-ohm termination resistors mandatory at both ends of a high-speed CAN network?
  • To step down battery voltages
  • To match the characteristic impedance of the twisted-pair cable, preventing high-frequency signal reflections from corrupting bits
  • To power the microcontrollers
  • To invert the parity bits
Unterminated transmission lines cause signal edges to reflect back along the wire, causing destructive interference and bit corruption.
4. What happens when a CAN node's Transmit Error Counter (TEC) exceeds 255?
  • The node resets the baud rate to 10 kbps
  • The node enters the Bus-Off state, physically disconnecting its transmitter from the network to protect other nodes
  • The node begins transmitting at double frequency
  • A Non-Maskable Interrupt (NMI) is triggered
The CAN fault-confinement state machine forces defective nodes into Bus-Off (TEC > 255) to prevent a broken ECU from jamming traffic.
5. What is the maximum payload data length of a standard CAN 2.0A or 2.0B frame?
  • 4 Bytes
  • 8 Bytes
  • 64 Bytes
  • 1500 Bytes
Standard CAN 2.0 frames are limited to a maximum payload of 8 bytes (DLC = 8). CAN FD expands this to 64 bytes.
6. Where is the recommended bit Sample Point location for automotive 500 kbps powertrain CAN networks?
  • 50.0%
  • 75.0%
  • 87.5%
  • 99.0%
Automotive CiA 303-1 and ISO 11898 standards mandate placing the sample point at 87.5% of the bit duration to tolerate propagation delays.
7. How does an acknowledging node confirm successful receipt of a valid CAN frame?
  • By driving a dominant 0 during the ACK Slot bit on the bus
  • By replying with a 64-byte ACK frame
  • By toggling an external handshake line
  • By resetting its receive error counter
The transmitting node outputs a recessive 1 during the ACK bit; any receiver that computed a matching CRC pulls the bus dominant (0).
8. What feature distinguishes CAN FD from legacy CAN 2.0?
  • CAN FD uses fiber optic cables instead of copper
  • CAN FD supports larger payloads up to 64 bytes and switches to higher clock speeds (up to 8 Mbps) during the data phase
  • CAN FD eliminates the CRC checksum
  • CAN FD requires 6 physical wires
CAN Flexible Data-rate retains classical arbitration speeds (e.g. 500 kbps) but accelerates data phase clocks up to 5-8 Mbps with 64-byte payloads.
9. What is the role of the Linux SocketCAN kernel subsystem?
  • To emulate USB printers
  • To treat CAN controllers as network interfaces (like eth0), allowing applications to use standard Berkeley socket APIs
  • To convert CAN frames into Python scripts
  • To simulate analog battery degradation
SocketCAN integrates CAN natively into the Linux networking stack, allowing software to use standard socket(), bind(), and write() syscalls.
10. What is Bit Stuffing in CAN communication?
  • Padding payload data with random noise
  • An automatic rule where the transmitter inserts an opposite bit after 5 consecutive identical bits to guarantee clock synchronization edges
  • Compressing 16-bit integers into 8 bits
  • Overclocking the prescaler
To prevent receivers from losing clock synchronization during long runs of 1s or 0s, CAN inserts a stuffed bit of complementary polarity after 5 identical bits.
