Module 2 Capstone Project

Toolchains, Linker Scripts & Binary Analysis

Firmware engineers cannot rely on black-box vendor IDEs to manage memory layouts and builds. A professional must understand the transition from source code to machine bits: configuring cross-compilers, orchestrating builds with Make/CMake, handcrafting custom linker scripts, inspecting ELF symbols, and automating memory budget enforcement in Git CI pipelines. This capstone guides you through building a complete cross-compilation pipeline on Linux/WSL and crafting a zero-IDE bare-metal firmware project with custom linker scripts on an STM32 microcontroller.

Part 1: Linux / WSL Project — Multi-Target Build Matrix & Binary Bloat Inspector

In commercial firmware development, builds must support both Host Simulation (for rapid automated unit testing on x86_64) and Target Cross-Compilation (for flashing to ARM Cortex-M). Furthermore, firmware teams use automated bloat gates to reject pull requests that exceed strict SRAM or Flash memory thresholds.

Step 1: Production Multi-Target Makefile

This Makefile cleanly decouples host native builds (make host) from target cross-compilation (make target), generates disassembly, symbol maps, and invokes our bloat inspector: 

# ==============================================================================
# Multi-Target Firmware Makefile
# Supports: Host Native (x86_64) & Cross-Target (ARM Cortex-M4)
# ==============================================================================

PROJECT_NAME := sensor_firmware
BUILD_DIR    := build

# Host Compilers
HOST_CC      := gcc
HOST_CFLAGS  := -std=c11 -Wall -Wextra -Werror -O2 -g

# Target Cross-Toolchain
TARGET_PREFIX := arm-none-eabi-
TARGET_CC     := $(TARGET_PREFIX)gcc
TARGET_OBJCOPY:= $(TARGET_PREFIX)objcopy
TARGET_OBJDUMP:= $(TARGET_PREFIX)objdump
TARGET_SIZE   := $(TARGET_PREFIX)size
TARGET_NM     := $(TARGET_PREFIX)nm

# Cortex-M4 Hardware Flags
TARGET_MCU_FLAGS := -mcpu=cortex-m4 -mthumb -mfloat-abi=hard -mfpu=fpv4-sp-d16
TARGET_CFLAGS    := $(TARGET_MCU_FLAGS) -std=c11 -Wall -Wextra -Werror -Os -g3 \
                    -ffunction-sections -fdata-sections -DSTM32F401xE
TARGET_LDFLAGS   := $(TARGET_MCU_FLAGS) -T stm32_flash.ld \
                    -Wl,-Map=$(BUILD_DIR)/$(PROJECT_NAME).map,--cref \
                    -Wl,--gc-sections --specs=nano.specs --specs=nosys.specs

# Sources
SRCS_COMMON := src/sensor.c
SRCS_HOST   := src/main_host.c $(SRCS_COMMON)
SRCS_TARGET := src/main_target.c src/startup_stm32.c $(SRCS_COMMON)

.PHONY: all host target clean bloat-check

all: target

# Target Cross-Compilation Rule
target: $(BUILD_DIR)/$(PROJECT_NAME).elf $(BUILD_DIR)/$(PROJECT_NAME).bin bloat-check

$(BUILD_DIR)/$(PROJECT_NAME).elf: $(SRCS_TARGET) stm32_flash.ld | $(BUILD_DIR)
	@echo "--> Cross-compiling target ELF for Cortex-M4..."
	$(TARGET_CC) $(TARGET_CFLAGS) $(SRCS_TARGET) $(TARGET_LDFLAGS) -o $@
	@echo "--> Generating Disassembly Listing..."
	$(TARGET_OBJDUMP) -d -S $@ > $(BUILD_DIR)/$(PROJECT_NAME).asm
	@echo "--> Generating Sorted Symbol Footprint..."
	$(TARGET_NM) --size-sort -C -r $@ > $(BUILD_DIR)/symbols_by_size.txt
	@echo "--> Memory Utilization Summary:"
	$(TARGET_SIZE) -B $@

$(BUILD_DIR)/$(PROJECT_NAME).bin: $(BUILD_DIR)/$(PROJECT_NAME).elf
	$(TARGET_OBJCOPY) -O binary $< $@

# Host Native Build Rule
host: $(SRCS_HOST) | $(BUILD_DIR)
	@echo "--> Compiling native host binary..."
	$(HOST_CC) $(HOST_CFLAGS) $(SRCS_HOST) -o $(BUILD_DIR)/$(PROJECT_NAME)_host
	@echo "--> Executing host simulator:"
	./$(BUILD_DIR)/$(PROJECT_NAME)_host

# Automated Binary Bloat Gate
bloat-check: $(BUILD_DIR)/$(PROJECT_NAME).elf
	@chmod +x scripts/bloat_check.sh
	@scripts/bloat_check.sh $(BUILD_DIR)/$(PROJECT_NAME).elf 524288 98304

$(BUILD_DIR):
	mkdir -p $(BUILD_DIR)

clean:
	rm -rf $(BUILD_DIR)

Step 2: Binary Bloat Inspector Script (scripts/bloat_check.sh)

This bash script parses the ELF output using arm-none-eabi-size and arm-none-eabi-nm. It halts the build if Flash or RAM thresholds are exceeded or if any single symbol exceeds budget: 

#!/usr/bin/env bash
# ==============================================================================
# scripts/bloat_check.sh: Embedded Binary Footprint & Memory Budget Gate
# Usage: ./bloat_check.sh <elf_file> <max_flash_bytes> <max_ram_bytes>
# ==============================================================================
set -euo pipefail

ELF_FILE="${1:-build/sensor_firmware.elf}"
MAX_FLASH="${2:-524288}" # 512 KB
MAX_RAM="${3:-98304}"    # 96 KB

if [ ! -f "$ELF_FILE" ]; then
    echo "ERROR: ELF file '$ELF_FILE' not found!"
    exit 1
fi

# Extract text, data, bss sections using size in Berkeley format
SIZE_OUTPUT=$(arm-none-eabi-size -B "$ELF_FILE" | tail -n 1)
TEXT=$(echo "$SIZE_OUTPUT" | awk '{print $1}')
DATA=$(echo "$SIZE_OUTPUT" | awk '{print $2}')
BSS=$(echo "$SIZE_OUTPUT"  | awk '{print $3}')

# Flash = .text + .data
TOTAL_FLASH=$((TEXT + DATA))
# RAM = .data + .bss
TOTAL_RAM=$((DATA + BSS))

FLASH_PERCENT=$(awk "BEGIN {printf \"%.2f\", ($TOTAL_FLASH / $MAX_FLASH) * 100}")
RAM_PERCENT=$(awk "BEGIN {printf \"%.2f\", ($TOTAL_RAM / $MAX_RAM) * 100}")

echo "================ MEMORY BUDGET REPORT ================"
echo "FLASH: ${TOTAL_FLASH} / ${MAX_FLASH} bytes (${FLASH_PERCENT}%)"
echo "  RAM: ${TOTAL_RAM} / ${MAX_RAM} bytes (${RAM_PERCENT}%)"
echo "  Breakdown: .text=${TEXT}B, .data=${DATA}B, .bss=${BSS}B"
echo "------------------------------------------------------"

# Audit Top 5 Largest Symbols
echo "Top 5 Memory-Consuming Symbols:"
arm-none-eabi-nm --size-sort -r -C "$ELF_FILE" | head -n 5

# Enforce Budgets
if [ "$TOTAL_FLASH" -gt "$MAX_FLASH" ]; then
    echo "ERROR: FLASH OVERFLOW! Exceeded budget by $((TOTAL_FLASH - MAX_FLASH)) bytes!"
    exit 2
fi

if [ "$TOTAL_RAM" -gt "$MAX_RAM" ]; then
    echo "ERROR: RAM OVERFLOW! Exceeded budget by $((TOTAL_RAM - MAX_RAM)) bytes!"
    exit 3
fi

echo "STATUS: Memory budget PASSED."
exit 0

Step 3: Git Pre-Commit Hook Integration

Integrate the bloat check directly into your local Git repository so no developer can commit code that breaks memory constraints: 

# Install Git pre-commit hook in .git/hooks/pre-commit
cat << 'EOF' > .git/hooks/pre-commit
#!/usr/bin/env bash
echo "Running firmware pre-commit verification..."
make clean
make target || { echo "Build failed! Commit aborted."; exit 1; }
echo "Pre-commit verification succeeded."
EOF

chmod +x .git/hooks/pre-commit

Part 2: Physical STM32 Board Project — Zero-IDE Bare-Metal Firmware with Custom Linker Script

Professional embedded firmware demands absolute control over the reset sequence and memory layout. Here, we discard vendor auto-generated code and build our own custom Linker Script (.ld) and C Startup Routine (startup_stm32.c) from first principles.

Step 1: Custom Linker Script (stm32_flash.ld)

This script defines the physical Flash (512K) and SRAM (96K) boundaries, maps the vector table to address 0x08000000, defines the VMA/LMA relocation mechanics for .data, zeroes .bss, and reserves top-of-RAM for the Main Stack Pointer (MSP): 

/* Entry Point symbol defined in startup code */
ENTRY(Reset_Handler)

/* Memory Layout for STM32F401RET6 */
MEMORY
{
    FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
    RAM   (xrw) : ORIGIN = 0x20000000, LENGTH = 96K
}

/* Stack boundary calculation: Top of RAM */
_estack = ORIGIN(RAM) + LENGTH(RAM);

SECTIONS
{
    /* 1. Vector Table: Must reside at base of Flash */
    .isr_vector :
    {
        . = ALIGN(4);
        KEEP(*(.isr_vector))
        . = ALIGN(4);
    } > FLASH

    /* 2. Program Code and Read-Only Constants */
    .text :
    {
        . = ALIGN(4);
        *(.text)
        *(.text*)
        *(.rodata)
        *(.rodata*)
        . = ALIGN(4);
        _etext = .; /* Symbol marking end of code in Flash */
    } > FLASH

    /* 3. Initialized Data Section: VMA in RAM, LMA in Flash */
    _sidata = LOADADDR(.data);
    .data :
    {
        . = ALIGN(4);
        _sdata = .; /* Start of .data in RAM */
        *(.data)
        *(.data*)
        . = ALIGN(4);
        _edata = .; /* End of .data in RAM */
    } > RAM AT > FLASH

    /* 4. Zero-Initialized BSS Section in RAM */
    .bss :
    {
        . = ALIGN(4);
        _sbss = .;  /* Start of .bss in RAM */
        *(.bss)
        *(.bss*)
        *(COMMON)
        . = ALIGN(4);
        _ebss = .;  /* End of .bss in RAM */
    } > RAM

    /* Discard unused debugging metadata */
    /DISCARD/ :
    {
        *(.note.GNU-stack)
    }
}

Step 2: C Startup File & Vector Table (src/startup_stm32.c)

Rather than writing assembly, modern embedded practice implements CRT0 in pure C. The startup code copies initialized variables from Flash to RAM, fills .bss with zeros, and jumps to main(): 

/**
 * @file startup_stm32.c
 * @brief Bare-Metal C Startup Routine & Vector Table for STM32F4
 */
#include <stdint.h>

/* Symbols exported by the Linker Script */
extern uint32_t _estack;
extern uint32_t _etext;
extern uint32_t _sidata;
extern uint32_t _sdata;
extern uint32_t _edata;
extern uint32_t _sbss;
extern uint32_t _ebss;

/* Prototypes */
void Reset_Handler(void);
void Default_Handler(void);
extern int main(void);

/* Exception Handler Aliases pointing to Default_Handler */
void NMI_Handler(void)        __attribute__((weak, alias("Default_Handler")));
void HardFault_Handler(void)  __attribute__((weak, alias("Default_Handler")));
void MemManage_Handler(void)  __attribute__((weak, alias("Default_Handler")));
void BusFault_Handler(void)   __attribute__((weak, alias("Default_Handler")));
void UsageFault_Handler(void) __attribute__((weak, alias("Default_Handler")));
void SysTick_Handler(void)    __attribute__((weak, alias("Default_Handler")));

/* Vector Table placed in .isr_vector section */
__attribute__((section(".isr_vector"), used))
const uint32_t * const g_vector_table[] = {
    (uint32_t *)&_estack,        /* Initial Stack Pointer (MSP) */
    (uint32_t *)Reset_Handler,   /* Reset Handler */
    (uint32_t *)NMI_Handler,     /* NMI Handler */
    (uint32_t *)HardFault_Handler,/* HardFault Handler */
    (uint32_t *)MemManage_Handler,
    (uint32_t *)BusFault_Handler,
    (uint32_t *)UsageFault_Handler,
    0, 0, 0, 0,                  /* Reserved */
    (uint32_t *)Default_Handler, /* SVCall */
    (uint32_t *)Default_Handler, /* Debug Monitor */
    0,                           /* Reserved */
    (uint32_t *)Default_Handler, /* PendSV */
    (uint32_t *)SysTick_Handler  /* SysTick */
};

/* C Runtime Initialization (CRT0) */
void Reset_Handler(void) {
    /* 1. Copy initialized .data section from Flash (LMA) to RAM (VMA) */
    uint32_t *p_src = &_sidata;
    uint32_t *p_dest = &_sdata;
    while (p_dest < &_edata) {
        *p_dest++ = *p_src++;
    }

    /* 2. Zero-initialize the .bss section in RAM */
    uint32_t *p_bss = &_sbss;
    while (p_bss < &_ebss) {
        *p_bss++ = 0U;
    }

    /* 3. Call application entry point */
    main();

    /* 4. Safety trap if main ever returns */
    while (1) {
        __asm volatile ("wfi");
    }
}

/* Default Catch-All Exception Trap */
void Default_Handler(void) {
    while (1) {
        /* Hang in loop for debugger attachment */
    }
}

Step 3: Target Application (src/main_target.c)

A clean firmware application demonstrating global variables (in .data and .bss) to verify our startup initialization: 

/**
 * @file main_target.c
 * @brief Hardware Demonstration of Linker Sections & Startup
 */
#include <stdint.h>

/* Hardware Register Definitions */
#define RCC_AHB1ENR   (*(volatile uint32_t *)(0x40023830UL))
#define GPIOA_MODER   (*(volatile uint32_t *)(0x40020000UL))
#define GPIOA_BSRR    (*(volatile uint32_t *)(0x40020018UL))

/* Variable in .data (Initialized, must be copied from Flash to RAM) */
uint32_t g_blink_period_ticks = 400000UL;

/* Variable in .bss (Uninitialized, must be zeroed by Reset_Handler) */
uint32_t g_heartbeat_counter;

static void delay(volatile uint32_t count) {
    while (count > 0) {
        count--;
    }
}

int main(void) {
    /* Enable GPIOA Clock */
    RCC_AHB1ENR |= (1UL << 0);

    /* Configure PA5 (LD2) as Output */
    GPIOA_MODER &= ~(3UL << (5 * 2));
    GPIOA_MODER |=  (1UL << (5 * 2));

    /* Verification check: If CRT0 failed to copy .data, period would be 0! */
    if (g_blink_period_ticks == 0UL) {
        g_blink_period_ticks = 50000UL; /* Fast error blink */
    }

    while (1) {
        GPIOA_BSRR = (1UL << 5);       /* LED ON */
        delay(g_blink_period_ticks);
        GPIOA_BSRR = (1UL << (5 + 16)); /* LED OFF */
        delay(g_blink_period_ticks);

        g_heartbeat_counter++;
    }

    return 0;
}

3. What is the very first entry at index 0 of the ARM Cortex-M vector table?

4. Which flag in arm-none-eabi-nm sorts symbols by their memory size in descending order?

5. Why is --specs=nano.specs commonly passed to the linker in embedded ARM GCC projects?

6. What happens if the startup code fails to initialize .bss memory?

7. What information does the .map file provide to an embedded engineer?

8. In stm32_flash.ld, why is KEEP(*(.isr_vector)) necessary?

9. What is the role of LOADADDR(.data) in the linker script?

Challenge 1 (Host)

Symbol Bloat Regression CLI

Extend bloat_check.sh to compare the newly compiled ELF against the previous Git commit's ELF (using git show HEAD:build/firmware.elf). Fail the build if any individual function grew by more than 15%.

Challenge 2 (Host)

CMake Multi-Toolchain Target Matrix

Write a single CMakeLists.txt that uses a CMake toolchain file (arm-gcc.cmake) to build the target firmware when passed -DCMAKE_TOOLCHAIN_FILE=arm-gcc.cmake, and builds a host simulator when omitted.

Challenge 3 (STM32)

Custom Flash Sector for Calibration Data

Modify stm32_flash.ld to carve out a dedicated 16KB Flash sector named .calib_data at address 0x0807C000. Place a const calibration_t struct into this section using GCC __attribute__((section(".calib_data"))) and verify in the .map file.

Challenge 4 (STM32)

Stack Watermarking & Overflow Guard

In startup_stm32.c, fill the RAM region between _ebss and _estack - 1024 with a watermark pattern (0xDEADBEEF). In main(), count how many words of the watermark were overwritten to determine peak stack usage.

Challenge 5 (Toolchain Automation)

Disassembly Annotation Automation

Add a Makefile target make annotate that generates mixed C and assembly listings using arm-none-eabi-objdump -S -l, highlighting compiler optimization differences between -O0, -O2, and -Os.
