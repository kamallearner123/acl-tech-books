Topic 23

Reusable Software Components in Embedded C

In typical embedded engineering organizations, firmware developers reinvent the wheel on every project: rewriting circular ring buffers, button debouncers, CRC generators, and packet parsers from scratch. Invariably, subtle race conditions, off-by-one errors, and buffer overflow bugs are reintroduced each time.

A Reusable Embedded Component is a hardened, self-contained software module designed to operate seamlessly across different microcontroller families (ARM Cortex-M, RISC-V, AVR, ESP32) and host test environments. It enforces zero reliance on dynamic memory allocation, operates without global variables, and achieves mathematical reentrancy.

23.2 Canonical Component 1: The Lock-Free SPSC Ring Buffer

A Circular Ring Buffer is the primary data structure bridging asynchronous hardware Interrupt Service Routines (ISRs) to background superloop tasks.

Power-of-Two Masking Optimization

Standard ring buffers compute index advancement using the modulo operator: head = (head + 1) % capacity. On microcontroller cores lacking hardware integer division (such as ARM Cortex-M0 and Cortex-M0+), integer division requires an expensive software runtime routine consuming 40 to 80 CPU clock cycles!

By enforcing that buffer capacity is strictly a power of two ($2^N$), modulo division is replaced by a lightning-fast bitwise AND operation executing in 1 single clock cycle:

index = (index + 1U) & (capacity - 1U); /* Power of Two Optimization */

Production Implementation (MISRA-Compliant)

/* ring_buffer.h */
#ifndef RING_BUFFER_H
#define RING_BUFFER_H

#include <stdint.h>
#include <stddef.h>
#include <stdbool.h>

typedef struct {
    uint8_t *p_buffer;
    size_t   capacity;
    size_t   mask;
    volatile size_t head; /* Modified only by Producer */
    volatile size_t tail; /* Modified only by Consumer */
} RingBuffer_t;

typedef enum {
    RING_BUF_OK = 0,
    RING_BUF_ERR_NULL_PTR,
    RING_BUF_ERR_INVALID_SIZE,
    RING_BUF_FULL,
    RING_BUF_EMPTY
} RingBufStatus_t;

RingBufStatus_t ring_buffer_init(RingBuffer_t * const p_rb, uint8_t * const p_storage, const size_t capacity);
RingBufStatus_t ring_buffer_put(RingBuffer_t * const p_rb, const uint8_t data);
RingBufStatus_t ring_buffer_get(RingBuffer_t * const p_rb, uint8_t * const p_data);
size_t          ring_buffer_get_count(const RingBuffer_t * const p_rb);
bool            ring_buffer_is_empty(const RingBuffer_t * const p_rb);
bool            ring_buffer_is_full(const RingBuffer_t * const p_rb);

#endif /* RING_BUFFER_H */
Program 23.1: Reusable SPSC Ring Buffer Header Interface
/* ring_buffer.c */
#include "ring_buffer.h"

static bool is_power_of_two(const size_t val) {
    return ((val > 0U) && ((val & (val - 1U)) == 0U));
}

RingBufStatus_t ring_buffer_init(
    RingBuffer_t * const p_rb, 
    uint8_t * const      p_storage, 
    const size_t         capacity) 
{
    if ((p_rb == NULL) || (p_storage == NULL)) {
        return RING_BUF_ERR_NULL_PTR;
    }
    if (!is_power_of_two(capacity)) {
        return RING_BUF_ERR_INVALID_SIZE;
    }

    p_rb->p_buffer = p_storage;
    p_rb->capacity = capacity;
    p_rb->mask     = capacity - 1U;
    p_rb->head     = 0U;
    p_rb->tail     = 0U;

    return RING_BUF_OK;
}

RingBufStatus_t ring_buffer_put(RingBuffer_t * const p_rb, const uint8_t data) {
    if (p_rb == NULL) return RING_BUF_ERR_NULL_PTR;

    const size_t current_head = p_rb->head;
    const size_t next_head = (current_head + 1U) & p_rb->mask;

    /* If next head reaches tail, buffer is full */
    if (next_head == p_rb->tail) {
        return RING_BUF_FULL;
    }

    p_rb->p_buffer[current_head] = data;
    __DMB(); /* ARM Cortex Data Memory Barrier ensures data write finishes */
    p_rb->head = next_head;

    return RING_BUF_OK;
}

RingBufStatus_t ring_buffer_get(RingBuffer_t * const p_rb, uint8_t * const p_data) {
    if ((p_rb == NULL) || (p_data == NULL)) return RING_BUF_ERR_NULL_PTR;

    const size_t current_tail = p_rb->tail;

    /* If tail equals head, buffer is empty */
    if (current_tail == p_rb->head) {
        return RING_BUF_EMPTY;
    }

    *p_data = p_rb->p_buffer[current_tail];
    __DMB();
    p_rb->tail = (current_tail + 1U) & p_rb->mask;

    return RING_BUF_OK;
}
Program 23.2: Lock-Free Single-Producer Single-Consumer FIFO Implementation

Single-Producer Single-Consumer (SPSC) Lock-Free Safety

In Program 23.2, the Producer (e.g. UART RX ISR) only modifies head and only reads tail. The Consumer (e.g. main loop) only modifies tail and only reads head. Because 32-bit aligned reads and writes are atomic on ARM Cortex-M processors and memory barriers (__DMB()) prevent CPU pipeline reordering, no critical section (disabling interrupts) is required!

23.3 Canonical Component 2: Hardware-Agnostic CRC-16 Engine

Data integrity verification over communication links (UART, SPI, CAN) requires Cyclic Redundancy Checks (CRC). Below is a fast table-driven CRC-16-CCITT ($x^{16} + x^{12} + x^5 + 1$) engine: 

#include <stdint.h>
#include <stddef.h>

/* 256-word Lookup Table in Flash ROM (.rodata) */
static const uint16_t s_crc16_table[256] = {
    0x0000U, 0x1021U, 0x2042U, 0x3063U, 0x4084U, 0x50A5U, 0x60C6U, 0x70E7U,
    0x8108U, 0x9129U, 0xA14AU, 0xB16BU, 0xC18CU, 0xD1ADU, 0xE1CEU, 0xF1EFU,
    /* ... 240 additional precomputed polynomial coefficients ... */
};

uint16_t crc16_ccitt_compute(
    const uint8_t * const p_data, 
    const size_t          len_bytes, 
    uint16_t              seed) 
{
    if (p_data == NULL) return 0U;

    uint16_t crc = seed;
    for (size_t i = 0; i < len_bytes; ++i) {
        const uint8_t tbl_idx = (uint8_t)((crc >> 8) ^ p_data[i]);
        crc = (uint16_t)((crc << 8) ^ s_crc16_table[tbl_idx]);
    }

    return crc;
}

23.4 Canonical Component 3: Parallel Bit-Shift Debouncer

Mechanical push buttons bounce for 5 to 20 ms. While novice code uses blocking delays, a professional reusable debouncer uses an 8-bit shift register integrator sampled periodically (e.g. every 5 ms): 

#include <stdint.h>
#include <stdbool.h>

typedef struct {
    uint8_t shift_reg;
    bool    stable_state;
    bool    edge_pressed;
    bool    edge_released;
} DebounceChannel_t;

void debouncer_update(DebounceChannel_t * const p_btn, const bool raw_pin_level) {
    if (p_btn == NULL) return;

    /* Shift history and insert latest raw physical sample */
    p_btn->shift_reg = (uint8_t)((p_btn->shift_reg << 1) | (raw_pin_level ? 1U : 0U));

    /* Reset edge flags */
    p_btn->edge_pressed  = false;
    p_btn->edge_released = false;

    /* 8 consecutive identical samples confirm state transition */
    if ((p_btn->shift_reg == 0xFFU) && (!p_btn->stable_state)) {
        p_btn->stable_state  = true;
        p_btn->edge_pressed  = true;  /* Clean debounced rising edge */
    } else if ((p_btn->shift_reg == 0x00U) && (p_btn->stable_state)) {
        p_btn->stable_state  = false;
        p_btn->edge_released = true; /* Clean debounced falling edge */
    }
}

23.5 Code Comparison: Hardcoded vs. Reusable Component

Compare a hardcoded UART ring buffer with a reusable, multi-instance component.

Compare Architecture: Circular Buffer Implementation

❌ Hardcoded & Non-Reusable

/* Fixed buffer inside C file */
static uint8_t buf[100];
static int head = 0;
static int tail = 0;

void uart_put(uint8_t c) {
    /* Slow division modulo */
    head = (head + 1) % 100;
    buf[head] = c;
}

Flaws: Cannot be reused for UART2 or SPI (only 1 global instance exists). Uses slow division modulo. Fixed 100-byte size cannot be adjusted without editing driver code.

✔ Reusable Multi-Instance Component

/* Unlimited instances; caller injects storage */
RingBuffer_t uart1_rb;
RingBuffer_t uart2_rb;
uint8_t mem1[256];
uint8_t mem2[64];

ring_buffer_init(&uart1_rb, mem1, 256);
ring_buffer_init(&uart2_rb, mem2, 64);

ring_buffer_put(&uart1_rb, 0x55);
ring_buffer_put(&uart2_rb, 0xAA);

Safety: Supports multiple independent channels, zero heap allocation, power-of-two bitwise masking, verified lock-free reentrancy.

23.6 Interactive Knowledge Check

Test your understanding of reusable embedded components, buffer math, and reentrant data structures.

1. Why should circular ring buffer capacities always be sized to a power of two (e.g. 64, 128, 256)?
  • Because silicon Flash sectors are always 64 bytes.
  • It allows replacing slow software integer division modulo (%) with a 1-cycle bitwise AND operation: (idx + 1) & (cap - 1).
  • Because C compilers reject arrays that are not powers of two.
  • To enable DMA burst transfers of 1024 bytes.
Explanation: On Cortex-M0/M0+ cores without a hardware divide instruction, modulo % requires a multi-cycle subroutine. Bitwise masking executes in 1 clock cycle.
2. What does "Storage Injection" mean in reusable component design?
  • Writing directly to external SD cards.
  • The component allocates no internal buffers or heap; instead, the caller passes an allocated memory buffer and size during initialization.
  • Injecting SQL queries into EEPROM.
  • Using the linker script to erase RAM.
Explanation: Storage injection allows the caller to determine buffer sizing and memory placement (e.g. fast DTCM RAM vs slow external SRAM) without modifying component code.
3. In a lock-free Single-Producer Single-Consumer (SPSC) ring buffer, why are mutexes or interrupt disables unnecessary?
  • Because Cortex-M CPUs execute all code in parallel.
  • Because the Producer only modifies head and only reads tail, while the Consumer only modifies tail and only reads head, with atomic 32-bit index access.
  • Because interrupts are automatically masked by the C preprocessor.
  • Ring buffers are never used in interrupts.
Explanation: SPSC separation ensures neither context ever writes to the other's pointer, eliminating write races and avoiding expensive interrupt disabling.
4. What is the role of the ARM __DMB() (Data Memory Barrier) instruction inside the ring buffer put and get functions?
  • To flush the display screen.
  • To ensure that payload data is completely written into memory before the index pointer is updated and observed by the other context.
  • To clear the watchdog timer.
  • To put the CPU into deep sleep.
Explanation: Out-of-order execution or write buffering could update the head pointer before the byte is physically written to RAM. __DMB() enforces strict memory ordering.
5. How many distinct switch press events does an 8-bit shift register debouncer require before confirming a state change?
  • 1 sample.
  • 8 consecutive identical samples (register equals 0xFF for press, 0x00 for release).
  • 256 samples.
  • Exactly 1000 samples.
Explanation: Shifting pin states into an 8-bit register requires 8 consecutive high samples (0xFF) to accept a press, cleanly rejecting contact chatter.
6. What is the primary difference between a checksum (like Fletcher-16) and a CRC (like CRC-16)?
  • Checksums are 64-bit; CRCs are 8-bit.
  • CRCs use polynomial division, providing superior mathematical detection of burst bit errors compared to additive checksums.
  • Checksums can only be computed in hardware.
  • CRCs require floating point math.
Explanation: CRCs treat data as binary polynomial coefficients, providing strong guarantees against burst noise errors common in industrial electrical environments.
7. Why must reusable C components avoid defining variables with static storage duration inside functions?
  • Because static variables are placed in Flash ROM.
  • Function-local static variables make the function non-reentrant, preventing multiple instances from functioning independently.
  • Because the GCC compiler deletes static local variables.
  • To reduce MCU clock speed.
Explanation: A local static variable is shared across all callers. If two instances call the function, they corrupt each other's state.
8. What framing technique replaces delimiter bytes (like 0x00) with offset pointers to guarantee zero-overhead packet demarcation?
  • Base64 encoding.
  • Consistent Overhead Byte Stuffing (COBS).
  • Manchester encoding.
  • RSA encryption.
Explanation: COBS encodes packets so that byte 0x00 never appears inside the payload, allowing 0x00 to serve as an unambiguous end-of-packet delimiter with minimal overhead.
9. In the ring buffer in Program 23.2, why is one slot reserved as empty (usable capacity is $N - 1$)?
  • To store the buffer checksum.
  • To unambiguously distinguish between the buffer being completely EMPTY (head == tail) and completely FULL ((head + 1) == tail).
  • To prevent stack collisions.
  • Because ARM architecture requires odd memory addresses.
Explanation: Without an explicit count variable, reserving one empty slot differentiates the empty condition (head == tail) from the full condition.
10. How should a reusable component report operational errors to the caller?
  • By printing error text directly to the UART console.
  • By returning an explicit enumeration status code (e.g. STATUS_OK, STATUS_FULL) allowing the caller to decide the recovery policy.
  • By calling exit(1).
  • By asserting a hardware CPU reset.
Explanation: A library component must never dictate recovery policy or assume a UART console exists; it must return typed status codes to the calling application.

23.7 Hands-On Engineering Laboratories

Execute these 5 laboratory assignments to construct a verified repository of reusable embedded firmware components.

Assignment 1: Multi-Channel Ring Buffer Stress Harness

Task: Instantiate four independent ring buffers (sizes: 16, 64, 128, 512 bytes). Write a host test program with two threads (one simulated ISR producer, one background consumer) pushing and pulling 10,000,000 random bytes. Verify zero data corruption, zero lost bytes, and correct boundary flags.

Assignment 2: Bit-Parallel 8-Button Debounce Engine

Task: Implement vertical counter debouncing where an entire 8-bit GPIO port (8 mechanical pushbuttons) is sampled and debounced simultaneously in parallel using bitwise logic (AND, OR, XOR) in less than 10 CPU clock cycles.

Assignment 3: CRC-16 Table Generator & Benchmark

Task: Write a C utility that generates the 256-entry lookup table for the CRC-16-CCITT polynomial and outputs it as formatted C code. Benchmark the table-driven algorithm against bit-by-bit calculation on an ARM microcontroller and record the execution speedup.

Assignment 4: Reusable COBS Packet Framer

Task: Implement a pair of reusable functions: cobs_encode(dst, src, len) and cobs_decode(dst, src, len). Verify with test packets containing arbitrary binary data (including multiple 0x00 bytes) and confirm that encoded frames are cleanly separated by 0x00 delimiters.

Assignment 5: Fixed-Block Memory Pool Allocator

Task: Build a reusable, deterministic block pool manager: pool_init(pool, storage, block_size, num_blocks), pool_alloc(pool), and pool_free(pool, p_block). Guarantee $O(1)$ constant allocation time, zero fragmentation, and MISRA-C Rule 21.3 compliance.
