Chapter 0 · Setup & Environment

Installing STM32CubeMX, IDE & Programmer

Configure your complete development environment — code generator, integrated IDE, and hardware programmer — on macOS, Windows, and Linux Ubuntu before writing your first line of embedded C.

⏱ ~45 min 🛠 Hands-on Setup 🎯 All Platforms

🎯 Learning Objectives

  • Understand the role of STM32CubeMX, STM32CubeIDE, and ST-LINK Programmer in the embedded workflow.
  • Download and install all three tools on macOS, Windows 10/11, and Linux Ubuntu 22.04/24.04.
  • Configure the Java runtime dependency where required.
  • Verify the installation with a blink project on a Nucleo or Discovery board.
  • Troubleshoot common installation errors on each platform.

0.1   Tool Landscape Overview

STMicroelectronics provides a unified, free-of-charge ecosystem for STM32 development. Three tools form the backbone of every project in this course:

⚙️

STM32CubeMX

A graphical code-generation wizard. Configure pins, clocks, peripherals (UART, SPI, I²C, Timers, DMA, ADC…) and generate initialisation C code for your target MCU — no hand-crafting register values.

  • GUI-based MCU configurator
  • Clock-tree visualiser & calculator
  • HAL / LL / Bare-Metal code generator
  • Middleware (FreeRTOS, USB, LwIP) integration
  • Exports directly to STM32CubeIDE, Makefile, or IAR
Standalone App · Java Required
💻

STM32CubeIDE

A full-featured Integrated Development Environment built on Eclipse CDT + GCC ARM cross-compiler. Write, build, and debug STM32 firmware all in one window. CubeMX is also embedded inside it as a plugin.

  • Eclipse-based IDE with GCC ARM toolchain
  • Integrated CubeMX peripheral configurator
  • One-click GDB debugging over ST-LINK
  • Code analysis, syntax highlighting, refactoring
  • Live expressions, memory browser, register view
Recommended Primary Tool
🔌

STM32CubeProgrammer (ST-LINK)

A standalone flash programmer and memory inspector for STM32 devices. Download firmware (.bin, .hex, .elf), read/write option bytes, and erase flash — via USB/ST-LINK, UART, or SWD.

  • Flash .elf / .bin / .hex binaries
  • Erase, verify, and read flash memory
  • Configure option bytes (read protection, boot mode)
  • Works with ST-LINK/V2, ST-LINK/V3, USB DFU
  • CLI mode for scripted CI/CD flashing pipelines
Required for Standalone Flashing
💡 Quick Tip: If you install STM32CubeIDE, it bundles a version of CubeMX internally. You only need the standalone CubeMX app if you prefer a separate workflow or want the latest MCU database updates before CubeIDE ships them.

0.4   🍎 Installation on macOS

A. Install Java Runtime (JRE 11+)

STM32CubeMX standalone requires Java. The easiest method is via Homebrew: 

# Install Homebrew if not present
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Install OpenJDK 21 (LTS)
brew install openjdk@21

# Symlink so system Java wrappers find it
sudo ln -sfn /opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk \
     /Library/Java/JavaVirtualMachines/openjdk-21.jdk

# Verify
java -version
# Output: openjdk version "21.x.x" ...

B. Install STM32CubeIDE

  1. Double-click the downloaded .dmg file to mount it.
  2. Drag STM32CubeIDE.app into your /Applications folder.
  3. On first launch, macOS may show "App from unidentified developer".
  4. Open System Preferences → Privacy & Security → Security and click "Open Anyway" next to the STM32CubeIDE entry.
  5. Alternatively, use Terminal to remove quarantine: 
    xattr -dr com.apple.quarantine /Applications/STM32CubeIDE.app
  6. Choose a workspace folder (e.g., ~/STM32CubeIDE/workspace) and click Launch.

C. Install STM32CubeMX (Standalone)

  1. Unzip the downloaded STM32CubeMX-Mac-vX.Y.Z.zip.
  2. Run the SetupSTM32CubeMX-X.Y.Z.app installer package.
  3. Follow the installation wizard and accept the license agreement.
  4. Launch from /Applications/STMicroelectronics/STM32CubeMX.app or use Spotlight: ⌘ Space → type STM32CubeMX.
  5. On first launch, CubeMX will prompt you to install firmware packages (HAL libraries) for your MCU family (e.g., STM32F4, STM32H7). Click Install Now.

D. Install STM32CubeProgrammer

  1. Run the downloaded SetupSTM32CubeProgrammer-X.Y.Z.app.
  2. Follow the wizard — default install path is /Applications/STMicroelectronics/STM32CubeProgrammer.
  3. Add the CLI tool to your PATH for terminal use: 
    # Add to ~/.zshrc
echo 'export PATH="/Applications/STMicroelectronics/STM32CubeProgrammer/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# Verify
STM32_Programmer_CLI --version

E. ST-LINK USB Driver on macOS

✅ No driver installation needed on macOS. The ST-LINK USB driver is built into the macOS kernel. Simply plug in your Nucleo or Discovery board via USB and it will be detected automatically.

F. Apple Silicon (M1 / M2 / M3) Notes

⚠️ Rosetta 2 Required. STM32CubeIDE and STM32CubeMX ship as x86-64 binaries. On Apple Silicon, macOS will prompt you to install Rosetta 2 on first launch — click Install and enter your password. Performance is good; native ARM builds are expected in future releases. 
# Manually install Rosetta 2 if prompted
softwareupdate --install-rosetta --agree-to-license

0.5   🪟 Installation on Windows 10 / 11

A. Install STM32CubeIDE

  1. Run the downloaded st-stm32cubeide_X.Y.Z_YYYYMMDD_setup.exe as Administrator.
  2. Accept the license agreement and choose an install directory (default: C:\ST\STM32CubeIDE_X.Y.Z\).
  3. The installer automatically installs:
    • GCC ARM Embedded Toolchain
    • ST-LINK USB driver (ST-LINK/V2 and ST-LINK/V3)
    • GDB Server
  4. Click Finish. A desktop shortcut is created.
  5. On first launch, choose or create a workspace directory and click Launch.
💡 Antivirus Warning: Some antivirus software (Windows Defender, Avast) may flag the ARM GCC compiler binaries as suspicious. Add C:\ST\ to your AV exclusions list before installation to avoid interruptions.

B. Install STM32CubeMX (Standalone)

  1. Run SetupSTM32CubeMX-X.Y.Z.exe as Administrator.
  2. The installer bundles a compatible JRE — no separate Java installation is needed on Windows.
  3. Accept defaults and click Next → Install → Finish.
  4. Launch from Start Menu: STMicroelectronics → STM32CubeMX.
  5. On first run, go to Help → Manage Embedded Software Packages and install the HAL package for your MCU family (e.g., STM32F4, STM32L4, STM32H7).

C. Install STM32CubeProgrammer

  1. Run SetupSTM32CubeProgrammer-X.Y.Z.exe as Administrator.
  2. The ST-LINK USB driver is installed automatically alongside the programmer.
  3. After installation, the CLI is accessible at:
    C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin\STM32_Programmer_CLI.exe
  4. Add to system PATH (optional):
    1. Press Win + X → System → Advanced System Settings → Environment Variables.
    2. Edit the Path system variable → click New.
    3. Paste: C:\Program Files\STMicroelectronics\STM32Cube\STM32CubeProgrammer\bin
    4. Click OK all the way out and restart your terminal.

D. ST-LINK USB Driver on Windows

  1. The ST-LINK/V2 driver is installed automatically by both CubeIDE and CubeProgrammer installers.
  2. Plug in your Nucleo board — Windows should detect it as "STMicroelectronics STLink Virtual COM Port".
  3. Verify in Device Manager (Win + X → Device Manager):
    • Under Ports (COM & LPT): STLink Virtual COM Port (COMx)
    • Under Universal Serial Bus devices: STM32 STLink
  4. If the driver shows a yellow warning icon, download the driver manually from: https://www.st.com/en/development-tools/stsw-link009.html

E. Windows Subsystem for Linux (WSL2) Option

💡 Advanced: Developers who prefer a Linux terminal environment on Windows can use WSL2 with a GCC ARM toolchain for command-line builds, then use STM32CubeIDE on the Windows side for flashing and debugging. USB passthrough to WSL2 requires usbipd-win — covered in an advanced appendix.

0.6   🐧 Installation on Linux Ubuntu (22.04 / 24.04)

A. System Dependencies

# Update package index
sudo apt update && sudo apt upgrade -y

# Install required libraries for STM32CubeIDE (Eclipse/GTK)
sudo apt install -y \
  libncurses5 \
  libncurses5-dev \
  libpython3-dev \
  python3-pip \
  unzip \
  wget \
  curl \
  git \
  make \
  cmake \
  build-essential \
  libudev-dev \
  libusb-1.0-0-dev

B. Install Java Runtime (JRE 21)

# Install OpenJDK 21
sudo apt install -y openjdk-21-jdk

# Verify
java -version
# openjdk version "21.x.x" ...

# Set JAVA_HOME
echo 'export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64' >> ~/.bashrc
echo 'export PATH=$JAVA_HOME/bin:$PATH' >> ~/.bashrc
source ~/.bashrc

C. Install STM32CubeIDE

  1. Make the downloaded installer executable: 
    chmod +x st-stm32cubeide_X.Y.Z_YYYYMMDD_amd64.deb_bundle.sh
  2. Run as root: 
    sudo ./st-stm32cubeide_X.Y.Z_YYYYMMDD_amd64.deb_bundle.sh
  3. Follow the prompts — the installer installs to /opt/st/stm32cubeide_X.Y.Z/.
  4. Create a desktop launcher or launch from terminal: 
    /opt/st/stm32cubeide_X.Y.Z/stm32cubeide
  5. Optionally add a symlink for convenience: 
    sudo ln -s /opt/st/stm32cubeide_X.Y.Z/stm32cubeide /usr/local/bin/stm32cubeide
# Then launch with:
stm32cubeide

D. Install STM32CubeMX (Standalone)

  1. Make executable and run the installer: 
    chmod +x SetupSTM32CubeMX-X.Y.Z.linux
sudo ./SetupSTM32CubeMX-X.Y.Z.linux
  2. Accept the license and choose install directory (default: /home/<user>/STM32CubeMX).
  3. Launch CubeMX: 
    ~/STM32CubeMX/STM32CubeMX
# Or if installed system-wide:
/usr/local/STM32CubeMX/STM32CubeMX
  4. On first launch: Help → Manage Embedded Software Packages → install your target MCU family package.

E. Install STM32CubeProgrammer

  1. Make executable and run: 
    chmod +x SetupSTM32CubeProgrammer-X.Y.Z.linux
sudo ./SetupSTM32CubeProgrammer-X.Y.Z.linux
  2. Default install path: /home/<user>/STMicroelectronics/STM32Cube/STM32CubeProgrammer
  3. Add CLI to PATH: 
    echo 'export PATH="$HOME/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

# Verify
STM32_Programmer_CLI --version

F. ST-LINK USB udev Rules (Critical on Linux)

Linux requires udev rules to give non-root users permission to access the ST-LINK USB device. Without this step, you'll get "Permission denied" or "No ST-LINK detected" errors. 

# The udev rules file is installed by CubeIDE/CubeProgrammer at:
# /etc/udev/rules.d/49-stlinkv2.rules  (or similar)
# If not present, create it manually:

sudo tee /etc/udev/rules.d/49-stlink.rules <<'EOF'
# ST-LINK/V1
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="3744", MODE="0666", GROUP="plugdev"
# ST-LINK/V2
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="3748", MODE="0666", GROUP="plugdev"
# ST-LINK/V2-1
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374b", MODE="0666", GROUP="plugdev"
# ST-LINK/V3
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374e", MODE="0666", GROUP="plugdev"
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374f", MODE="0666", GROUP="plugdev"
SUBSYSTEMS=="usb", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="3753", MODE="0666", GROUP="plugdev"
EOF

# Reload udev rules
sudo udevadm control --reload-rules
sudo udevadm trigger

# Add your user to the plugdev group
sudo usermod -aG plugdev $USER

# Log out and log back in for the group change to take effect
echo "Logout and login again to apply group membership!"
⚠️ Important: After adding your user to the plugdev group, you must log out and log back in (or reboot) for the change to take effect. Running newgrp plugdev in the current terminal is a temporary workaround.

G. Verify ST-LINK Detection on Ubuntu

# Plug in your Nucleo/Discovery board, then:
lsusb | grep ST
# Should show: Bus 001 Device 003: ID 0483:374b STMicroelectronics ST-LINK/V2.1

# Test with CubeProgrammer CLI
STM32_Programmer_CLI -c port=SWD
# Should show: ST-LINK SN: ... connected

0.7   ✅ Verification — Hello World Blink

Once all tools are installed, verify the full toolchain end-to-end with a classic LED blink project:

1
Create project in STM32CubeIDE
File → New → STM32 Project → select your board (e.g., Nucleo-F446RE) → name it Blink.
2
Configure LED pin in CubeMX (built-in)
In the Pinout & Configuration view, set PA5 (or the board LED pin) to GPIO_Output.
3
Generate code
Click Project → Generate Code. The HAL init code is generated automatically.
4
Add blink logic in main.c
Inside the while(1) loop (between the USER CODE comments): 
/* USER CODE BEGIN WHILE */
while (1)
{
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    HAL_Delay(500);   /* 500 ms on / 500 ms off */
    /* USER CODE END WHILE */
}
5
Build & Flash
Press Ctrl+B (or ⌘B on Mac) to build. Then click the green Run button (▶). CubeIDE flashes via ST-LINK and starts the debug session. The LED should blink at 1 Hz.
🎉 Success! If your board's LED blinks, your complete toolchain — CubeMX, CubeIDE, and ST-LINK — is verified and working correctly on your platform. You are ready for Chapter 1.

0.8   🔧 Common Troubleshooting

Problem Platform Solution
"App can't be opened because it is from an unidentified developer" macOS Run xattr -dr com.apple.quarantine /Applications/STM32CubeIDE.app
CubeMX won't launch (white screen / crashes) macOS / Ubuntu Ensure Java 11+ is installed and JAVA_HOME is set correctly.
ST-LINK not detected in CubeIDE / CubeProgrammer Ubuntu Create/reload udev rules, add user to plugdev, then log out and back in.
Device Manager shows yellow warning icon for ST-LINK Windows Download and run stsw-link009.zip driver from st.com manually.
"libncurses.so.5: cannot open shared object" Ubuntu 22.04+ Run sudo apt install libncurses5.
Build fails: "arm-none-eabi-gcc not found" All Re-run the CubeIDE installer; ensure the GCC toolchain component was not skipped.
CubeIDE runs very slowly on Apple Silicon (M1/M2/M3) macOS (ARM) Ensure Rosetta 2 is installed: softwareupdate --install-rosetta.
Flash verification fails after programming All Try erasing flash first: in CubeProgrammer → Erase & Programming tab → check Full chip erase.

📝 Chapter 0 – Knowledge Check

Q1. Which file format does STM32CubeProgrammer not support for flashing?

✅ Correct: D. CubeProgrammer supports .bin, .hex, and .elf binaries. It does not flash Python (.py) files.

Q2. On Linux Ubuntu, why is it necessary to add udev rules for ST-LINK?

✅ Correct: B. Linux's security model requires explicit udev rules granting plugdev group members read/write access to the ST-LINK USB device. Without them, only root can access it.

Q3. What is the primary function of STM32CubeMX?

✅ Correct: B. STM32CubeMX is a graphical configuration wizard that lets you configure MCU pins, peripherals, and clocks visually, then generates the corresponding HAL/LL C initialisation code.

Q4. On macOS with Apple Silicon (M1/M2/M3), what additional component must be installed to run STM32CubeIDE?

✅ Correct: C. STM32CubeIDE ships as an x86-64 binary. On Apple Silicon Macs, macOS uses Rosetta 2 to transparently translate x86-64 instructions to ARM64. It is installed on first launch or via softwareupdate --install-rosetta.

Q5. After adding a user to the plugdev group on Ubuntu, what must be done for the change to take effect?

✅ Correct: B. Linux group memberships are applied at login time. You must log out and back in (or reboot) for the plugdev group membership to be recognised in your session.

📌 Chapter 0 Summary

  • Three tools form the STM32 development backbone: CubeMX (code generator), CubeIDE (build & debug), and CubeProgrammer (flash).
  • On macOS: install via .dmg / .app; use xattr to bypass Gatekeeper; install Rosetta 2 for Apple Silicon.
  • On Windows: run installers as Administrator; the ST-LINK USB driver is bundled; watch for AV interference.
  • On Linux Ubuntu: install via .deb bundle / .linux scripts; configure udev rules and add your user to plugdev.
  • Verify everything end-to-end with a 1 Hz LED blink on a Nucleo board before proceeding.
