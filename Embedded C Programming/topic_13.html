Topic 13

Callbacks & Timers

A modular firmware driver should never have hardcoded dependencies on application business logic. A UART driver, button debouncer, or hardware timer module should not directly call update_motor_speed() or turn_on_heater(); doing so couples the peripheral driver to a specific application, preventing reuse across projects.

The standard architectural solution in C is the Callback Pattern utilizing Function Pointers. A driver provides registration APIs allowing higher-level application components to register callback functions that are invoked automatically when hardware events occur. Paired with hardware timer interrupts, this pattern enables building flexible, multi-instance Software Timer Services that manage dozens of independent periodic tasks from a single hardware timer.

13.1 Function Pointers in C: Syntax & Usage

A function pointer stores the physical entry point address of executable code in Flash memory. In C, declaring a function pointer type requires explicit parentheses around the pointer name to differentiate it from a function returning a pointer: 

/* Typedef for a callback taking a void* context pointer and uint32_t event data */
typedef void (*TimerCallback_t)(void *context, uint32_t elapsed_ms);

/* Declaration of a function pointer variable */
TimerCallback_t on_timer_expire = NULL;
Program 13.1: Defining and Declaring Typed Function Pointers in C
Defensive Tip: Never invoke a function pointer without an explicit NULL check! Invoking a NULL function pointer attempts to execute address 0x00000000, instantly triggering an ARM Cortex-M HardFault or executing the vector table as code!

13.2 Hardware Timers to Software Timers

A typical microcontroller contains 4 to 8 physical hardware timers. However, real-world firmware often requires dozens of concurrent periodic intervals: blinking an LED at 1 Hz, sampling a temperature sensor at 10 Hz, polling a keypad at 50 Hz, and sending a telemetry heartbeat every 5 seconds.

13.3 Hands-On Code Implementations

The following complete module provides a production-grade Software Timer Engine supporting one-shot and periodic callback execution: 

/**
 * Program 13.2: Multi-Instance Software Timer Service with Callbacks
 * File: soft_timer.c
 */

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

typedef void (*SoftTimerCallback_t)(void *context);

typedef struct {
    uint32_t            period_ticks;
    uint32_t            remaining_ticks;
    SoftTimerCallback_t callback;
    void               *context;
    bool                is_periodic;
    bool                is_active;
} SoftTimer_t;

#define MAX_SOFT_TIMERS 8U
static SoftTimer_t s_timers[MAX_SOFT_TIMERS];

void soft_timer_init(void) {
    for (size_t i = 0; i < MAX_SOFT_TIMERS; ++i) {
        s_timers[i].is_active = false;
        s_timers[i].callback  = NULL;
    }
}

int32_t soft_timer_start(uint32_t period_ticks, bool periodic, SoftTimerCallback_t cb, void *ctx) {
    if ((cb == NULL) || (period_ticks == 0U)) return -1;

    for (size_t i = 0; i < MAX_SOFT_TIMERS; ++i) {
        if (!s_timers[i].is_active) {
            s_timers[i].period_ticks    = period_ticks;
            s_timers[i].remaining_ticks = period_ticks;
            s_timers[i].is_periodic     = periodic;
            s_timers[i].callback        = cb;
            s_timers[i].context         = ctx;
            s_timers[i].is_active       = true;
            return (int32_t)i; /* Return timer handle */
        }
    }
    return -2; /* Out of timer slots */
}

/**
 * @brief Called every 1 ms from hardware SysTick ISR or timer tick.
 */
void soft_timer_tick_isr(void) {
    for (size_t i = 0; i < MAX_SOFT_TIMERS; ++i) {
        if (s_timers[i].is_active) {
            s_timers[i].remaining_ticks--;
            if (s_timers[i].remaining_ticks == 0U) {
                /* Execute registered callback */
                if (s_timers[i].callback != NULL) {
                    s_timers[i].callback(s_timers[i].context);
                }
                
                if (s_timers[i].is_periodic) {
                    s_timers[i].remaining_ticks = s_timers[i].period_ticks;
                } else {
                    s_timers[i].is_active = false; /* One-shot expired */
                }
            }
        }
    }
}

13.4 Buggy vs. Modern Safe Code Comparison

Invoking heavy business logic directly from an ISR callback violates real-time deadlines and causes unpredictable interrupt preemption lockups.

View Buggy/Legacy Code

The callback executes heavy mathematics, Flash erasing, and serial I/O directly in the hardware timer ISR context, locking the CPU: 

/* BUGGY: Heavy blocking computation inside timer callback */
void on_timer_expire_bad(void *ctx) {
    /* Runs in ISR context! Blocking for 250 ms will starve all other hardware! */
    spi_flash_sector_erase(0x1000); 
    printf("Erase finished\n");
}
Program 13.3-A: Heavy Blocking Execution Inside Timer Callback

The safe pattern sets a lightweight atomic event flag or posts an event, deferring heavy computation to the non-interrupt background thread: 

/* SAFE / PRODUCTION-GRADE: Non-blocking flag setting in ISR callback */
static volatile bool s_erase_requested = false;

void on_timer_expire_safe(void *ctx) {
    /* Fast non-blocking flag: takes 2 clock cycles in ISR */
    s_erase_requested = true;
}

void main_superloop(void) {
    while (1) {
        if (s_erase_requested) {
            s_erase_requested = false;
            /* Heavy operation executes safely in background thread */
            spi_flash_sector_erase(0x1000);
        }
    }
}

Topic Quiz (10 Questions)

Test your understanding of function pointers, callback architectures, and timer services.

1. In C, what does the typedef 'typedef void (*ButtonCallback_t)(uint8_t pin);' declare?
  • A function returning a pointer to a button.
  • A pointer type to a function that accepts an 8-bit unsigned integer argument and returns void.
  • A struct containing an 8-bit integer.
  • An array of 8 buttons.
The syntax defines ButtonCallback_t as a function pointer type matching signatures: void func(uint8_t pin).
2. What happens if firmware invokes a function pointer that holds a NULL address?
  • The function returns 0.
  • The CPU attempts to fetch instructions from address 0x00000000, triggering an instant HardFault exception.
  • The compiler emits a warning at runtime.
  • Execution pauses for 1 ms.
Branching to NULL (0x0) executes memory outside valid code regions, causing the processor to generate an invalid instruction or memory fault.
3. Why do professional callback registration interfaces accept a 'void *context' user parameter?
  • To enable dynamic memory allocation.
  • To allow callers to pass instance-specific state data to the callback without relying on messy global variables.
  • To measure execution time.
  • It is required by the C standard.
Passing a context pointer provides an object-oriented 'this' pointer in C, allowing a single callback function to manage multiple hardware instances.
4. What is the role of a hardware timer Prescaler (PSC) register?
  • It scales the display contrast.
  • It divides the high-frequency CPU/bus clock down to a slower, manageable counter frequency.
  • It measures battery temperature.
  • It stores the interrupt vector address.
The prescaler clock divider slows down timer clock ticks, allowing microsecond or millisecond tick intervals from multi-MHz system clocks.
5. What is the Auto-Reload Register (ARR) in an embedded hardware timer?
  • A register that reloads Flash memory.
  • The register defining the maximum count value at which the timer counter resets to zero and generates an update/overflow interrupt.
  • A backup battery register.
  • The program counter.
The ARR defines timer period: when the counter matches ARR, it resets to 0 and asserts the periodic overflow interrupt flag.
6. What is the fundamental difference between a 'One-Shot' timer and a 'Periodic' timer?
  • One-shot timers run in hardware; periodic timers run in software.
  • A one-shot timer fires its callback once upon expiration and stops; a periodic timer automatically reloads its countdown and fires repeatedly.
  • Periodic timers require 64-bit integers.
  • One-shot timers ignore interrupts.
One-shot timers are used for timeouts and delays; periodic timers drive cyclic tasks like LED blinking and sensor sampling.
7. Why is it dangerous to execute long or blocking operations inside a timer callback that runs in ISR context?
  • The timer hardware melts.
  • It monopolizes CPU time at interrupt priority, blocking lower-priority interrupts and causing timing jitter or missed deadlines across the system.
  • Flash memory cannot be read during callbacks.
  • It disables compiler optimizations.
Callbacks called directly from ISRs inherit interrupt priority; blocking operations inside them starve other critical real-time subsystems.
8. What is a 'Timer Wheel' algorithm?
  • A mechanical dial on the microcontroller.
  • An efficient circular buffer data structure that schedules and fires thousands of software timers with O(1) tick complexity.
  • A motor control algorithm.
  • A debugger GUI widget.
Hashed timer wheels organize timers into circular buckets, enabling O(1) insertion and expiration checking even with hundreds of active timers.
9. Which standard ARM Cortex-M hardware peripheral provides an integrated 24-bit down-counter timer designed for RTOS and software ticks?
  • Watchdog Timer (WDT)
  • SysTick (System Tick Timer)
  • RTC (Real-Time Clock)
  • CRC Engine
SysTick is an integral core peripheral in every ARM Cortex-M CPU, providing a universal periodic 1 ms tick source across all silicon vendors.
10. Why should an array of function pointer callbacks be declared 'const' if the table is known at compile time?
  • To make the callbacks execute faster.
  • To place the dispatch table into Flash memory (.rodata), preventing RAM consumption and protecting pointers from memory corruption.
  • It enables thread locking.
  • It disables interrupts automatically.
Placing dispatch tables in Flash protects function pointers from accidental corruption by wild pointers or stack overflows.

Hands-On Assignments

Execute these 5 laboratory assignments to master function pointers, callbacks, and software timer multiplexing.

Assignment 1: Multi-Rate LED Blinker via Software Timers

Task: Using the software timer service from Program 13.2 driven by a 1 ms SysTick tick, register three periodic callbacks: (1) Green LED toggling at 500 ms, (2) Red LED toggling at 200 ms, and (3) Blue LED toggling at 1000 ms. Verify simultaneous multi-rate execution.

Assignment 2: Hardware Prescaler Calculation

Task: Given an MCU core running at 84 MHz, calculate the exact 16-bit Prescaler (PSC) and Auto-Reload (ARR) register values needed to generate an exact 1.000 kHz timer interrupt. Implement the register configuration and verify the frequency on an oscilloscope.

Assignment 3: Dynamic Callback Cancellation

Task: Implement a soft_timer_stop(int32_t handle) function. Create a one-shot communication timeout timer (3000 ms). If a simulated packet acknowledgment arrives before the timeout, stop the timer. Verify that the timeout error callback is never invoked.

Assignment 4: Button Debounce State Callback

Task: Implement a digital debouncing module for a mechanical push button. When a state change persists stably for 20 ms, fire an on_button_change(uint8_t state) callback. Verify that noisy mechanical contact bounce does not trigger false callbacks.

Assignment 5: Context-Aware Callback Structure

Task: Create a struct representing a PID heater controller. Register a periodic timer callback passing the address of this struct as the void *context argument. Inside the callback, cast the context back to the PID struct and update heater PWM output without using global variables.
