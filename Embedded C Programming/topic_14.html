Topic 14

Non-Blocking Firmware Design

In novice firmware, timing is frequently achieved through busy-wait loops such as delay_ms(500) or spin loops polling a status flag: while (!(USART1->SR & USART_SR_TXE));. While superficially simple, blocking code paralyzes the microcontroller core. For hundreds of thousands or even millions of CPU clock cycles, the processor burns power executing dummy instructions while completely blind to user input, incoming bus communications, and scheduled sensor readings.

Professional bare-metal and real-time firmware enforces a strict design law: Never Block the CPU. Every task executed by the main superloop must adhere to the Run-to-Completion (RTC) principle: execute immediate deterministic work, inspect timestamps or hardware flags without waiting, update internal state variables, and promptly return control to the scheduler.

14.1 The Pathology of Blocking Delays

Consider an embedded system running on an ARM Cortex-M4 clocked at 168 MHz. When a developer inserts delay_ms(100) to pause between sensor readings, the CPU executes exactly:

168,000,000 cycles/sec × 0.100 sec = 16,800,000 CPU Clock Cycles Wasted

During those 16.8 million clock cycles, the following catastrophic failure modes occur in a multi-functional system:

  • Button Latency and Missed Inputs: A mechanical button pressed for 80 ms during the 100 ms delay is completely missed unless tied to an edge-triggered hardware interrupt.
  • UART / SPI Buffer Overrun: If high-speed incoming UART bytes (e.g., 115200 baud, 1 byte every 86.8 μs) arrive faster than the hardware FIFO can store them (often only 1 to 4 bytes deep), characters are overwritten and lost (Overrun Error: ORE).
  • Watchdog Timer (WDT) Starvation: The hardware independent watchdog timer (IWDG) requires regular refresh pulses. Blocking functions starve the watchdog feeder, causing spontaneous system resets under peak load.
  • Increased Power Consumption: A spinning CPU draws maximum dynamic switching current ($I_{dynamic} \propto C \cdot V^2 \cdot f$). A non-blocking architecture allows the CPU to enter low-power sleep (__WFI() - Wait For Interrupt) whenever tasks are waiting for future deadlines.

14.2 Non-Blocking Timekeeping & The Wraparound Proof

To replace blocking delays, we establish a monotonic millisecond timebase driven by the ARM Cortex-M SysTick hardware interrupt incrementing a global volatile counter: 

/* systick.h / systick.c */
static volatile uint32_t g_system_ticks = 0U;

void SysTick_Handler(void) {
    g_system_ticks++;
}

uint32_t millis(void) {
    uint32_t ticks;
    /* Atomic read on 32-bit Cortex-M architecture */
    ticks = g_system_ticks;
    return ticks;
}
Program 14.1: Monotonic Millisecond Counter Implementation

The Unsigned Difference Rule

A 32-bit unsigned counter incremented every 1 millisecond overflows back to zero after:

(232 - 1) milliseconds ≈ 4,294,967,295 ms ≈ 49.71 days

Novice engineers often write deadline comparisons using addition: 

/* DANGEROUS BUG: Subject to catastrophic overflow failure! */
if (millis() >= target_time) { ... }

If millis() is currently 0xFFFFFFF0 (16 ms before overflow) and we schedule a task for +30 ms, target_time becomes 0x0000000E (14). Because 0xFFFFFFF0 >= 0x0000000E evaluates to TRUE immediately, the task executes instantly without waiting!

The mathematically sound, immune-to-wraparound method relies strictly on unsigned subtraction: 

/* CORRECT: Fully immune to 32-bit unsigned integer overflow! */
if ((millis() - previous_time) >= INTERVAL_MS) {
    previous_time += INTERVAL_MS; /* Or previous_time = millis(); */
    execute_task();
}

Mathematical Proof of Unsigned Subtraction Wraparound

In two's complement unsigned 32-bit arithmetic, all operations are implicitly modulo $2^{32}$.
Suppose previous_time = 0xFFFFFFF0 (-16 in decimal relative to overflow).
Suppose current now = 0x0000000A (+10 in decimal past overflow).
The true elapsed time is $16 + 10 = 26\text{ ms}$.
Calculating now - previous_time in C:
0x0000000A - 0xFFFFFFF0 = 0x0000000A + (~0xFFFFFFF0 + 1) = 0x0000000A + 0x00000010 = 0x0000001A = 26!
The subtraction yields the exact elapsed duration without any branching or conditional logic, provided the interval is less than $2^{31} - 1$ ms (≈ 24.8 days).

14.3 The Cooperative Superloop Architecture

A non-blocking architecture replaces monolithic sequential loops with a structured Cooperative Task Superloop. Every subsystem (display, keypad, communication, sensor acquisition, motor control) exposes an asynchronous _process() or _task() function.

Figure 14.1: Cooperative Non-Blocking Superloop Execution Flow

Notice the crucial engineering requirement: Every individual task must guarantee a bounded Worst-Case Execution Time (WCET). If Task 3 takes 50 ms to poll a slow I2C temperature sensor, Tasks 1, 2, and 4 will suffer 50 ms of jitter. Therefore, slow hardware transactions must be broken down into finite-state machine steps.

14.4 Converting Monolithic Routines to State Steps

Let us analyze a common real-world problem: communicating with an environmental sensor (e.g., SHT31 or BMP280) that requires a 20 ms conversion delay between triggering a measurement and reading the data registers.

The Naive Blocking Approach (Anti-Pattern)

/* BAD: Blocks the entire microcontroller for 20 ms every second */
float read_temperature_blocking(void) {
    i2c_write_command(CMD_START_CONVERSION);
    delay_ms(20); /* COMPLETE CPU PARALYSIS! */
    uint16_t raw = i2c_read_word();
    return calculate_celsius(raw);
}

The Professional Non-Blocking State-Step Pattern

By introducing an enumeration of sensor states and storing the timestamp when the conversion command was launched, the function transforms into a zero-wait non-blocking worker: 

/* sensor_fsm.h / sensor_fsm.c */
#include <stdint.h>
#include <stdbool.h>

typedef enum {
    SENSOR_STATE_IDLE,
    SENSOR_STATE_CONVERTING,
    SENSOR_STATE_DATA_READY,
    SENSOR_STATE_ERROR
} SensorState_t;

typedef struct {
    SensorState_t state;
    uint32_t      conversion_start_ms;
    uint32_t      last_poll_ms;
    float         latest_temperature;
    bool          new_data_available;
} TempSensor_t;

static TempSensor_t g_temp_sensor = {
    .state = SENSOR_STATE_IDLE,
    .conversion_start_ms = 0U,
    .last_poll_ms = 0U,
    .latest_temperature = 0.0f,
    .new_data_available = false
};

void temp_sensor_step(void) {
    uint32_t now = millis();

    switch (g_temp_sensor.state) {
        case SENSOR_STATE_IDLE:
            /* Poll every 1000 ms */
            if ((now - g_temp_sensor.last_poll_ms) >= 1000U) {
                g_temp_sensor.last_poll_ms = now;
                i2c_start_async_conversion(); /* Non-blocking I2C transmit */
                g_temp_sensor.conversion_start_ms = now;
                g_temp_sensor.state = SENSOR_STATE_CONVERTING;
            }
            break;

        case SENSOR_STATE_CONVERTING:
            /* Check if 20 ms conversion deadline has elapsed without blocking */
            if ((now - g_temp_sensor.conversion_start_ms) >= 20U) {
                if (i2c_is_bus_ready()) {
                    uint16_t raw = i2c_read_raw_word();
                    g_temp_sensor.latest_temperature = (float)raw * 0.01f;
                    g_temp_sensor.new_data_available = true;
                    g_temp_sensor.state = SENSOR_STATE_IDLE;
                }
            }
            break;

        case SENSOR_STATE_ERROR:
        default:
            i2c_reset_bus();
            g_temp_sensor.state = SENSOR_STATE_IDLE;
            break;
    }
}
Program 14.2: Asynchronous Non-Blocking Sensor Acquisition Engine

When temp_sensor_step() is called in the main loop, it executes in less than 2.4 microseconds. During the 20 ms conversion window, the function simply exits immediately, allowing the superloop to service serial ports, buttons, and display screens thousands of times.

14.5 Full Production Example: Multi-Rate Task Scheduler

The following complete C module implements a lightweight, static cooperative task table scheduler with execution time tracking and overrun detection. 

#include <stdint.h>
#include <stdbool.h>

typedef void (*TaskFunction_t)(void);

typedef struct {
    const char       *task_name;
    TaskFunction_t    function;
    uint32_t          period_ms;
    uint32_t          last_run_ms;
    uint32_t          execution_count;
    uint32_t          max_duration_us;
} CooperativeTask_t;

/* Forward task prototypes */
static void task_heartbeat_led(void);
static void task_button_scan(void);
static void task_sensor_acquire(void);
static void task_comm_service(void);

static CooperativeTask_t g_task_registry[] = {
    { "ButtonScan",    task_button_scan,     10U,   0U, 0U, 0U },
    { "CommService",   task_comm_service,    20U,   0U, 0U, 0U },
    { "SensorAcquire", task_sensor_acquire,  100U,  0U, 0U, 0U },
    { "HeartbeatLED",  task_heartbeat_led,   500U,  0U, 0U, 0U }
};

#define TASK_COUNT (sizeof(g_task_registry) / sizeof(g_task_registry[0]))

void scheduler_dispatch(void) {
    uint32_t now = millis();

    for (size_t i = 0; i < TASK_COUNT; ++i) {
        CooperativeTask_t *task = &g_task_registry[i];

        /* Unsigned subtraction guarantees correct wraparound handling */
        if ((now - task->last_run_ms) >= task->period_ms) {
            task->last_run_ms = now;
            
            /* Execute task run-to-completion */
            task->function();
            task->execution_count++;
        }
    }
}

int main(void) {
    hardware_clock_init();
    systick_init();
    watchdog_init(1000U); /* 1.0 second watchdog window */

    while (1) {
        scheduler_dispatch();
        
        /* Kick watchdog in the superloop idle point */
        watchdog_feed();

        /* Optional: Enter Sleep Mode until SysTick or external IRQ wakes CPU */
        __WFI();
    }
}

14.6 Code Comparison: Blocking Spin-Loop vs. Non-Blocking Delta Timer

Observe the dramatic difference in system responsiveness when comparing a blocking implementation with an event-driven non-blocking alternative.

Compare Implementations: Button Debounce & LED Pulse

❌ Buggy: Blocking delay_ms()

void handle_user_interface(void) {
    if (GPIO_Read(BUTTON_PIN) == LOW) {
        /* Blocking debounce */
        delay_ms(50);
        if (GPIO_Read(BUTTON_PIN) == LOW) {
            /* Turn on LED for 1 second */
            GPIO_SetHigh(LED_PIN);
            delay_ms(1000); /* FREEZES ALL OTHER WORK! */
            GPIO_SetLow(LED_PIN);
        }
    }
}

Flaw: During the 1050 ms total delay, UART buffers overflow, sensor readings halt, and the watchdog is starved.

✔ Safe: Non-Blocking State Machine

typedef enum { UI_IDLE, UI_DEBOUNCING, UI_PULSING } UiState_t;
static UiState_t s_state = UI_IDLE;
static uint32_t  s_timer = 0U;

void handle_user_interface(void) {
    uint32_t now = millis();
    switch (s_state) {
        case UI_IDLE:
            if (GPIO_Read(BUTTON_PIN) == LOW) {
                s_timer = now;
                s_state = UI_DEBOUNCING;
            }
            break;
        case UI_DEBOUNCING:
            if ((now - s_timer) >= 50U) {
                if (GPIO_Read(BUTTON_PIN) == LOW) {
                    GPIO_SetHigh(LED_PIN);
                    s_timer = now;
                    s_state = UI_PULSING;
                } else { s_state = UI_IDLE; }
            }
            break;
        case UI_PULSING:
            if ((now - s_timer) >= 1000U) {
                GPIO_SetLow(LED_PIN);
                s_state = UI_IDLE;
            }
            break;
    }
}

Safety: Returns instantly every call (WCET < 1 μs). Communication and watchdog servicing never miss a beat.

14.7 Interactive Knowledge Check

Test your mastery of non-blocking firmware mechanics and integer wraparound arithmetic.

1. Why does the expression (millis() - previous_time) >= INTERVAL work correctly across a 32-bit unsigned overflow?
  • Because the C compiler automatically casts unsigned integers to floating point doubles during subtraction.
  • Because standard unsigned binary subtraction is performed modulo 2^32, producing the exact circular distance between timestamps.
  • Because SysTick automatically pauses counting during the subtraction operation.
  • It does not work; an explicit conditional check for overflow is always mandated by MISRA-C.
Explanation: Under two's complement unsigned integer arithmetic, (now - previous) wraps naturally modulo $2^{32}$. Even if now has rolled over to 2 and previous was 0xFFFFFFFE, 2 - 0xFFFFFFFE = 4, accurately representing elapsed time.
2. What is the fundamental requirement for all tasks executed within a cooperative superloop scheduler?
  • Every task must execute in its own preemptive FreeRTOS thread.
  • Every task must run to completion (RTC) rapidly with a strictly bounded Worst-Case Execution Time (WCET).
  • Every task must disable global interrupts upon entry and re-enable them upon exit.
  • Every task must include at least one delay_ms(1) to allow the CPU to cool down.
Explanation: In a cooperative system, tasks cannot preempt each other. If any task blocks or runs for a long period, it delays all other tasks by that exact duration.
3. What is the fatal flaw in scheduling a periodic task using: next_deadline = millis() + INTERVAL; followed by if (millis() >= next_deadline)?
  • When millis() + INTERVAL wraps around zero, millis() >= next_deadline evaluates to TRUE prematurely, firing immediately.
  • The compiler optimizes out the variable because it is not marked register.
  • Addition takes twice as many clock cycles as subtraction on Cortex-M processors.
  • The SysTick interrupt vector is invalidated.
Explanation: If millis() is near 0xFFFFFFFF, adding INTERVAL wraps to a tiny number (e.g. 50). Since 0xFFFFFFF0 >= 50 is TRUE, the task fires without waiting.
4. What occurs when a sensor takes 25 ms to convert data, and the firmware uses delay_ms(25) inside the main loop?
  • The sensor will deliver higher resolution measurements.
  • All other main-loop operations (buttons, serial communication, displays) are completely blocked for 25 ms.
  • The SysTick interrupt stops firing until the delay finishes.
  • The flash memory wear level increases.
Explanation: Busy-waiting holds CPU control exclusively, delaying every other peer task in the superloop and causing UI sluggishness and communication overruns.
5. To achieve cumulative drift-free periodic execution every 100 ms, how should previous_time be updated?
  • previous_time = millis();
  • previous_time += 100U;
  • previous_time = 0;
  • previous_time = SysTick->VAL;
Explanation: Setting previous_time = millis() discards any loop latency or processing delay that occurred before the task was scheduled, causing cumulative timing drift over minutes or hours. previous_time += PERIOD preserves the exact timeline.
6. What is the purpose of placing the ARM Cortex-M __WFI() instruction at the end of a cooperative superloop?
  • To reset the microcontroller when an error occurs.
  • To put the core into low-power sleep mode until the next interrupt (e.g. SysTick) wakes it up, saving power.
  • To flush the CPU instruction cache.
  • To trigger a software interrupt trap.
Explanation: __WFI() (Wait For Interrupt) halts the core clock until an interrupt arrives. If no tasks have work to do, the MCU sleeps, slashing power consumption.
7. If a task requires 500 ms to erase a sector of external SPI Flash memory, how should it be implemented in non-blocking firmware?
  • By executing while (flash_is_busy()); inside the function.
  • By sending the Sector Erase command, entering a FLASH_ERASING state, and polling the status register non-blockingly across subsequent loop iterations.
  • By increasing the MCU clock speed to 10 GHz so 500 ms becomes instantaneous.
  • By disabling the watchdog timer permanently.
Explanation: Flash erases take hundreds of milliseconds. Sending the erase command and non-blockingly querying the WIP (Write In Progress) bit in an FSM state allows other tasks to run smoothly.
8. What maximum timing interval can be safely measured using 32-bit unsigned millisecond subtraction?
  • Exactly 255 milliseconds.
  • Exactly 65,535 milliseconds (65.5 seconds).
  • Up to 2^31 - 1 milliseconds (~24.8 days) if signed comparisons are used, or 2^32 - 1 (~49.7 days) for pure unsigned intervals.
  • Infinite duration without limitation.
Explanation: Pure unsigned difference (now - prev) >= INTERVAL accurately measures periods up to $2^{32} - 1$ ms (~49.7 days). Any single interval greater than 49.7 days would be indistinguishable from a recent timestamp.
9. What is a "heartbeat LED" task in non-blocking embedded design?
  • An LED that pulses only when a human touch sensor detects a physical pulse.
  • A periodic non-blocking task that toggles an LED (e.g., 1 Hz) to provide visual proof that the superloop is actively scheduling and not locked in a freeze or fault.
  • An LED driven directly by the MCU crystal oscillator circuit.
  • A high-priority hardware interrupt that flashes the LED in hardware.
Explanation: A heartbeat LED toggled by the main superloop serves as a visual health indicator: if the LED freezes, the developer immediately knows a task blocked or a HardFault occurred.
10. In a non-blocking architecture, where should the Hardware Watchdog Timer (IWDG) refresh call watchdog_feed() be located?
  • Inside the SysTick interrupt service routine.
  • Exclusively inside the main superloop, ensuring the watchdog resets the chip if any cooperative task blocks.
  • Inside an external timer ISR running at 10 kHz.
  • Inside every driver initialization function.
Explanation: Kicking the watchdog inside an ISR is a cardinal sin: the ISR will continue happily feeding the watchdog even if the main loop hangs completely! Feeding the watchdog only from the main superloop verifies that all cooperative tasks are executing.

14.8 Hands-On Engineering Laboratories

Execute these 5 laboratory assignments to eliminate blocking delays and master cooperative real-time architecture.

Assignment 1: Drift-Free Dual LED Flasher

Task: Implement two independent non-blocking LED blinkers without using delay_ms(). LED 1 must toggle at exactly 100 ms period, and LED 2 must toggle at 333 ms period. Use last_time += INTERVAL. Run for 1 hour and verify using an oscilloscope or logic analyzer that zero cumulative drift occurs.

Assignment 2: Non-Blocking Button Debounce Engine

Task: Write a state-based button debouncer (states: RELEASED, MAYBE_PRESSED, PRESSED, MAYBE_RELEASED). When a transition is detected, require the input to remain stable for 25 ms before accepting the state change. Confirm that holding or releasing the button never halts the superloop.

Assignment 3: 32-bit Wraparound Simulator

Task: Write a host test program where g_system_ticks is initialized to 0xFFFFFFF0 (16 ms prior to 32-bit overflow). Schedule tasks for 10 ms, 25 ms, and 100 ms intervals. Simulate tick advancement through 0x00000050 and verify that every task executes at the exact expected timestamp across the boundary.

Assignment 4: Non-Blocking UART Command Prompt

Task: Implement an interactive CLI over UART. Incoming characters are collected non-blockingly into a line buffer. While typing commands, the superloop must concurrently service an ADC sampler at 100 Hz. If the user stops typing mid-command, the ADC sampler must continue without disruption.

Assignment 5: Task Execution Time Profiler

Task: Instrument the cooperative scheduler from Program 14.3 using the ARM Cortex-M DWT->CYCCNT (Data Watchpoint and Trace Cycle Counter). Measure the execution duration of each task in microseconds. If any task exceeds a 1.0 ms budget, print an alert to UART indicating a WCET violation.
