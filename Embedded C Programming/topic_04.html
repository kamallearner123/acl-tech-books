Topic 4

Assertions, Logging & Debugging Methodology

When firmware fails in a laboratory setting or deployment field, developers rarely have access to rich terminal stack traces. Standard desktop C's assert() macro calls abort(), which on a bare-metal microcontroller typically jumps into an infinite loop or triggers a watchdog reset without preserving diagnostic clues.

Professional embedded firmware demands a tailored diagnostic framework: custom target-safe assertion handlers that capture the failed expression, filename, and line number in non-volatile battery-backed RAM; non-blocking ring-buffer logging that never stalls real-time interrupt service routines; and systematic hardware debugging techniques using ARM Cortex-M DWT (Data Watchpoint and Trace) cycle counters.

4.1 Assertions: Design-Time Contract Enforcement

An assertion is a statement verifying a condition that must strictly be true if the program is operating correctly. Unlike standard input validation (which handles expected real-world variations such as noisy sensor inputs or severed wires), assertions exist to detect programmer logic bugs and violated API contracts.

Golden Rule of Assertions: Never place side-effect operations inside an assertion! For example, ASSERT(read_fifo() != 0); will break completely in release builds when assertions are disabled via -DNDEBUG, because the FIFO read will be stripped from the binary!

4.2 Non-Blocking Telemetry & Ring Buffer Logging

Calling blocking serial functions like printf() over an 115,200-baud UART requires roughly 87 microseconds per character. Printing a 40-character diagnostic message takes approximately 3.5 milliseconds—an eternity in a 1 kHz motor control loop or inside an interrupt handler.

Figure 4.1: Decoupled Non-Blocking Circular Logging Architecture
Architectural Benefits:
  • Zero Timing Distortion: Pushing a log entry into a memory buffer takes under 2 microseconds, preventing probe effect / heisenbugs.
  • Safe in Interrupts: Single-producer single-consumer circular buffers require zero mutex locks or interrupt disabling if head and tail indices are updated atomically.

4.3 Retargeting printf in Newlib GCC

On ARM Cortex-M cross-compilers using the Newlib C runtime, standard I/O calls (printf, puts) route through low-level Unix system call stubs. By implementing the _write() syscall, developers retarget formatted output to a physical UART or ARM Serial Wire Output (SWO) instrumentation port.

4.4 Hands-On Code Implementations

The following complete module provides a production-grade custom assertion framework and an interrupt-safe non-volatile crash recorder: 

/**
 * Program 4.1: Target-Safe Embedded Assertion & Non-Volatile Crash Recorder
 * File: embed_assert.c
 * Target: ARM Cortex-M / Embedded Systems
 */

#include <stdint.h>
#include <stdbool.h>
#include <stdio.h>

/* Non-Volatile Crash Information Structure (Allocated in backup RAM or battery RAM) */
typedef struct {
    uint32_t magic_header;       /*!< 0xDEADBEEF indicates valid crash log */
    uint32_t timestamp_ms;       /*!< System uptime at crash */
    uint32_t line_number;        /*!< Source code line number */
    char     filename[32];       /*!< Base name of source file */
    char     expression[64];     /*!< String representation of failed condition */
    uint32_t checksum;           /*!< Simple additive parity checksum */
} CrashDiagnostic_t;

/* Located in a retained RAM section not zeroed out during reset */
static CrashDiagnostic_t g_crash_record __attribute__((section(".noinit")));

#define CRASH_MAGIC  (0xDEADBEEFUL)

/**
 * @brief Custom assertion failure handler.
 * @note Decorated with noreturn to enable compiler unreachable optimizations.
 */
void __attribute__((noreturn)) custom_assert_handler(const char *expr, const char *file, uint32_t line) {
    /* Disable all interrupts immediately to freeze system state */
    __asm volatile ("cpsid i" : : : "memory");

    /* Populate non-volatile diagnostic log */
    g_crash_record.magic_header = CRASH_MAGIC;
    g_crash_record.timestamp_ms = 45210UL; /* In real firmware: get_uptime_ms() */
    g_crash_record.line_number  = line;

    /* Safe bounded copy of filename and expression string */
    snprintf(g_crash_record.filename, sizeof(g_crash_record.filename), "%s", file);
    snprintf(g_crash_record.expression, sizeof(g_crash_record.expression), "%s", expr);

    /* Safe safe-state: Turn off motor drivers, heaters, high-voltage outputs */
    /* safe_hardware_shutdown(); */

#if defined(DEBUG_BUILD)
    /* If running under debugger, trigger hardware breakpoint instruction */
    __asm volatile ("bkpt #0");
#endif

    /* Trigger hardware reset via System Reset Request in NVIC AIRCR */
    volatile uint32_t * const aircr = (volatile uint32_t *)0xE000ED0CUL;
    *aircr = (0x5FAUL << 16) | (1UL << 2); /* SYSRESETREQ */

    while (1) {
        /* Wait for reset to complete */
    }
}

/* Custom assertion macro */
#if defined(ENABLE_ASSERTIONS)
    #define EMBED_ASSERT(expr) \
        do { \
            if (!(expr)) { \
                custom_assert_handler(#expr, __FILE__, (uint32_t)__LINE__); \
            } \
        } while (0)
#else
    #define EMBED_ASSERT(expr) ((void)0)
#endif

4.5 Buggy vs. Modern Safe Code Comparison

Calling blocking serial I/O directly inside a high-speed Interrupt Service Routine is one of the most destructive bugs in real-time firmware, completely violating real-time deadlines.

void SysTick_Handler(void) {

Program 4.2-A: Blocking Printf Inside Real-Time Interrupt Handler

The safe architecture pushes a compact, binary-formatted telemetry packet into an interrupt-safe circular ring buffer in microseconds, allowing the background superloop to stream the data asynchronously: 

/* SAFE / PRODUCTION-GRADE: Non-blocking binary telemetry logging */
#include <stdint.h>
#include <stdbool.h>

typedef struct {
    uint32_t timestamp;
    uint16_t event_id;
    int16_t  payload;
} LogEntry_t;

#define LOG_QUEUE_SIZE 64U
static LogEntry_t s_log_queue[LOG_QUEUE_SIZE];
static volatile uint8_t s_head = 0U;
static volatile uint8_t s_tail = 0U;

/* Lock-free push into circular ring buffer: takes only 8 CPU cycles */
bool log_event_isr(uint16_t event_id, int16_t payload) {
    uint8_t next_head = (s_head + 1U) & (LOG_QUEUE_SIZE - 1U);
    if (next_head == s_tail) {
        return false; /* Buffer full: drop gracefully without blocking */
    }
    s_log_queue[s_head].timestamp = 0; /* read HW timer */
    s_log_queue[s_head].event_id = event_id;
    s_log_queue[s_head].payload = payload;
    s_head = next_head;
    return true;
}

void SysTick_Handler(void) {
    /* Fast non-blocking push: finishes in < 1 microsecond! */
    log_event_isr(0x01, 100);
}

Topic Quiz (10 Questions)

Test your knowledge of assertions, telemetry loggers, and embedded debugging workflows.

1. What is the fundamental distinction between an assertion and defensive runtime input validation?
  • Assertions run in SRAM; validation runs in Flash.
  • Assertions catch internal software logic bugs and contract violations; validation handles expected external data variations.
  • Assertions are written in assembly; validation is written in C.
  • Validation is disabled in release builds.
Assertions verify software design invariants that must never happen; input validation handles real-world corrupted data, packet timeouts, and noise.
2. What preprocessor macro disables standard C assert() statements when defined during compilation?
  • DISABLE_ASSERT
  • NDEBUG
  • RELEASE_BUILD
  • NO_CHECK
Defining NDEBUG causes <assert.h> to expand assert(expr) into ((void)0), stripping all assertion code from the binary.
3. Why is calling a standard blocking printf() over UART forbidden inside an Interrupt Service Routine (ISR)?
  • UART registers cannot be accessed inside interrupts.
  • Blocking serial transmission takes milliseconds, stalling the CPU, starving other interrupts, and violating real-time deadlines.
  • printf() modifies the link register.
  • The compiler emits a syntax error.
Transmitting serial characters at typical baud rates takes hundreds of microseconds to milliseconds, blocking all lower-priority interrupts and breaking real-time behavior.
4. Which low-level C runtime system call stub must be implemented in Newlib GCC to retarget printf() to a hardware UART?
  • _read()
  • _write()
  • _sbrk()
  • _exit()
In Newlib-based toolchains (like arm-none-eabi-gcc), printf() funnels output bytes through the _write(int file, char *ptr, int len) system call stub.
5. What is the ARM Cortex-M 'BKPT #0' instruction used for?
  • To restart the CPU clock.
  • To halt execution and trigger a hardware breakpoint for an attached JTAG/SWD debugger.
  • To clear the cache.
  • To enter sleep mode.
BKPT triggers a debug fault, causing the processor to halt and hand control to an attached hardware debugger like GDB via OpenOCD.
6. What is a 'Heisenbug' in firmware engineering?
  • A bug caused by radioactive decay in memory cells.
  • A timing defect that disappears or changes behavior as soon as debugging instrumentation (like printf) is introduced.
  • A bug that only occurs on German microcontrollers.
  • A linker script error.
Intrusive print statements alter system timing. When the print statement is added, a race condition may temporarily vanish, hiding the defect.
7. Which hardware component in ARM Cortex-M processors provides a non-intrusive 32-bit CPU cycle counter for microsecond profiling?
  • The SysTick Timer
  • The DWT (Data Watchpoint and Trace) CYCCNT register
  • The RTC (Real-Time Clock)
  • The Watchdog Timer
The DWT CYCCNT register increments once per CPU clock cycle, allowing cycle-accurate non-intrusive execution time benchmarking.
8. What is the advantage of using ARM Serial Wire Output (SWO) / ITM over standard UART for logging?
  • SWO uses 4 parallel data lines.
  • ITM hardware instrumentation transmits trace packets out a dedicated debug pin with minimal CPU cycle overhead.
  • ITM operates without a clock.
  • SWO eliminates the need for a C compiler.
The Instrumentation Trace Macrocell (ITM) outputs trace packets over the dedicated SWO pin without CPU busy-wait loops, minimizing probe effects.
9. Where should persistent crash diagnostic logs be stored so they survive a hardware reset?
  • On the CPU stack
  • In a local automatic variable
  • In an uninitialized RAM section (.noinit) or battery-backed backup registers
  • In the instruction cache
The .noinit RAM section is not modified during the C runtime startup code, allowing crash structures to survive a warm reset.
10. Why should an embedded assert handler be decorated with the [[noreturn]] or __attribute__((noreturn)) attribute?
  • To enable multi-threading.
  • To inform the compiler optimizer that the function never returns, allowing it to eliminate dead code and suppress false return warnings.
  • To store the function in EEPROM.
  • To disable compiler warnings on unused variables.
Marking the assertion handler noreturn informs the compiler that control flow ends there, generating cleaner machine code and eliminating spurious warnings.

Hands-On Assignments

Execute these 5 laboratory exercises to implement professional debugging and assertion workflows.

Assignment 1: Custom Assert with .noinit RAM Persistence

Task: Modify your project linker script to create a 256-byte .noinit section in SRAM. Implement a custom assertion macro that records the failed condition, file, and line into this section. Trigger an assertion, reset the board, and verify upon reboot that the startup code reads and prints the recorded crash details.

Assignment 2: Lock-Free Single-Producer Single-Consumer (SPSC) Ring Buffer

Task: Implement a circular ring buffer logger for 8-byte binary messages. Benchmark the push operation using the DWT cycle counter. Verify that pushing an entry from within a timer ISR finishes in under 20 CPU cycles without disabling global interrupts.

Assignment 3: Newlib _write() Syscall Retargeting

Task: In an ARM GCC project, provide a custom implementation of int _write(int file, char *ptr, int len) that routes stdout and stderr characters to a mock UART transmission function. Test by calling standard printf("Temperature: %d C\r\n", 25); and verify proper formatting.

Assignment 4: DWT Cycle Counter Micro-Benchmarking

Task: Enable the ARM Cortex-M DWT CYCCNT register (CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk; DWT->CTRL |= DWT_CTRL_CYCCNTENA_Msk;). Measure the exact CPU cycle execution duration of an integer square root algorithm compared to floating-point sqrtf().

Assignment 5: Multi-Level Verbosity Logger Filter

Task: Design a preprocessor-driven logging module with 4 verbosity tiers: LOG_LEVEL_ERROR, LOG_LEVEL_WARN, LOG_LEVEL_INFO, and LOG_LEVEL_DEBUG. Show how setting the active build level to ERROR eliminates debug string literals completely from Flash memory.
