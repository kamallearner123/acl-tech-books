Topic 25

Integrated Firmware Architecture

Combine modular C, interfaces, drivers, events, and FSM logic into a system where each layer has one responsibility.

event producer → bounded queue → FSM dispatcher
                                      ↓
                              driver / HAL API
                                      ↓
                              BSP and hardware

Integration checklist

  • Can the FSM run in a host test with fake drivers?
  • Are queue capacity and overflow behavior defined?
  • Does application code avoid register addresses?
  • Are driver APIs documented and error-aware?
  • Can every state transition be tested from an event sequence?

The final architecture is successful when changing the MCU or board affects the BSP/driver boundary more than the application logic.
