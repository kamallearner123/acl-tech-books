Topic 25

Integrated Firmware Architecture (Grand Capstone)

Throughout this curriculum, we have dissected the fundamental disciplines of embedded C programming: strict type safety and error containment (Module 1), compilation pipelines and binary inspection (Module 2), reactive event loops and non-blocking timing (Module 3), MISRA-C compliance and state machines (Module 4), and modular 4-tier layered abstraction (Module 5).

In this final Grand Capstone chapter, we unite all 24 individual disciplines into a complete, cohesive, production-grade Integrated Firmware Architecture. We examine an end-to-end mission-critical embedded system — an Industrial Autonomous Telemetry Node — illustrating how interrupts, thread-safe queues, finite-state automata, hardware abstractions, and watchdog health supervisors interact harmoniously in production C code.

25.1 End-to-End System Architecture Blueprint

The Grand Capstone system adheres to the Active Object / Reactive Superloop model. Hardware interrupts (UART RX, Pushbutton EXTI, SysTick) perform zero business logic; they capture raw physical data, package it into structured events, push them onto a thread-safe circular event queue, and immediately return.

25.2 Capstone Implementation: The Complete Telemetry Node

Below is the unified C implementation demonstrating all architectural layers functioning in complete harmony: 

/**
 * @file      main_integrated.c
 * @brief     Grand Capstone: Integrated Reactive Telemetry Firmware Node.
 * @details   Integrates MISRA-C compliance, SPSC event queues, table FSM,
 *            bounded HAL drivers, and non-blocking watchdog supervision.
 *
 * @copyright (c) 2026 Apt Computing Labs. All rights reserved.
 */

#include <stdint.h>
#include <stdbool.h>
#include <stddef.h>

/* ========================================================================= */
/* 1. EVENT DEFINITIONS & SPSC QUEUE (MODULE 3 & 5)                          */
/* ========================================================================= */
typedef enum {
    SIG_NONE = 0,
    SIG_TICK_100MS,
    SIG_BTN_USER_PRESS,
    SIG_SAMPLE_COMPLETE,
    SIG_FAULT_DETECTED
} Signal_t;

typedef struct {
    Signal_t signal;
    uint32_t payload;
} Event_t;

#define EVENT_QUEUE_CAPACITY (16U)
#define EVENT_QUEUE_MASK     (EVENT_QUEUE_CAPACITY - 1U)

typedef struct {
    Event_t         storage[EVENT_QUEUE_CAPACITY];
    volatile size_t head;
    volatile size_t tail;
} EventQueue_t;

static EventQueue_t g_event_queue = { .head = 0U, .tail = 0U };

bool event_queue_post_from_isr(const Event_t * const p_evt) {
    if (p_evt == NULL) return false;

    const size_t next_head = (g_event_queue.head + 1U) & EVENT_QUEUE_MASK;
    if (next_head == g_event_queue.tail) {
        return false; /* Queue Full: Drop event gracefully */
    }

    g_event_queue.storage[g_event_queue.head] = *p_evt;
    __DMB(); /* Data Memory Barrier */
    g_event_queue.head = next_head;
    return true;
}

bool event_queue_get(Event_t * const p_evt) {
    if (p_evt == NULL) return false;
    if (g_event_queue.tail == g_event_queue.head) return false; /* Empty */

    *p_evt = g_event_queue.storage[g_event_queue.tail];
    __DMB();
    g_event_queue.tail = (g_event_queue.tail + 1U) & EVENT_QUEUE_MASK;
    return true;
}

/* ========================================================================= */
/* 2. FINITE-STATE MACHINE ENGINE (MODULE 4)                                  */
/* ========================================================================= */
typedef enum {
    STATE_IDLE = 0,
    STATE_ACQUIRING,
    STATE_TRANSMITTING,
    STATE_FAULT,
    STATE_MAX
} AppState_t;

typedef struct AppFsm_t AppFsm_t;
typedef void (*StateAction_t)(AppFsm_t * const p_fsm, const Event_t * const p_evt);

typedef struct {
    AppState_t    next_state;
    StateAction_t action;
} StateTransition_t;

struct AppFsm_t {
    AppState_t state;
    int32_t    latest_temp_mdegc;
    uint32_t   packet_sequence_id;
};

static void act_start_acquisition(AppFsm_t * const p_fsm, const Event_t * const p_evt);
static void act_transmit_packet(AppFsm_t * const p_fsm, const Event_t * const p_evt);
static void act_handle_fault(AppFsm_t * const p_fsm, const Event_t * const p_evt);
static void act_ignore(AppFsm_t * const p_fsm, const Event_t * const p_evt) { (void)p_fsm; (void)p_evt; }

static const StateTransition_t g_fsm_table[STATE_MAX][5] = {
    [STATE_IDLE] = {
        [SIG_TICK_100MS]      = { STATE_ACQUIRING,    act_start_acquisition },
        [SIG_BTN_USER_PRESS]  = { STATE_ACQUIRING,    act_start_acquisition },
        [SIG_SAMPLE_COMPLETE] = { STATE_IDLE,         act_ignore },
        [SIG_FAULT_DETECTED]  = { STATE_FAULT,        act_handle_fault }
    },
    [STATE_ACQUIRING] = {
        [SIG_TICK_100MS]      = { STATE_ACQUIRING,    act_ignore },
        [SIG_BTN_USER_PRESS]  = { STATE_ACQUIRING,    act_ignore },
        [SIG_SAMPLE_COMPLETE] = { STATE_TRANSMITTING, act_transmit_packet },
        [SIG_FAULT_DETECTED]  = { STATE_FAULT,        act_handle_fault }
    },
    [STATE_TRANSMITTING] = {
        [SIG_TICK_100MS]      = { STATE_TRANSMITTING, act_ignore },
        [SIG_BTN_USER_PRESS]  = { STATE_TRANSMITTING, act_ignore },
        [SIG_SAMPLE_COMPLETE] = { STATE_IDLE,         act_ignore },
        [SIG_FAULT_DETECTED]  = { STATE_FAULT,        act_handle_fault }
    },
    [STATE_FAULT] = {
        [SIG_TICK_100MS]      = { STATE_FAULT, act_ignore },
        [SIG_BTN_USER_PRESS]  = { STATE_IDLE,  act_ignore }, /* Reset fault */
        [SIG_SAMPLE_COMPLETE] = { STATE_FAULT, act_ignore },
        [SIG_FAULT_DETECTED]  = { STATE_FAULT, act_ignore }
    }
};

static void act_start_acquisition(AppFsm_t * const p_fsm, const Event_t * const p_evt) {
    (void)p_evt;
    /* Layer 2 Driver call across Layer 3 HAL */
    int32_t temp = 0;
    if (sensor_read_temperature_mdegc(&temp) == 0) {
        p_fsm->latest_temp_mdegc = temp;
        Event_t evt_ready = { .signal = SIG_SAMPLE_COMPLETE, .payload = (uint32_t)temp };
        event_queue_post_from_isr(&evt_ready);
    } else {
        Event_t evt_err = { .signal = SIG_FAULT_DETECTED, .payload = 0xEE };
        event_queue_post_from_isr(&evt_err);
    }
}

static void act_transmit_packet(AppFsm_t * const p_fsm, const Event_t * const p_evt) {
    (void)p_evt;
    p_fsm->packet_sequence_id++;
    telemetry_send_frame(p_fsm->packet_sequence_id, p_fsm->latest_temp_mdegc);
    p_fsm->state = STATE_IDLE; /* Return to IDLE */
}

static void act_handle_fault(AppFsm_t * const p_fsm, const Event_t * const p_evt) {
    (void)p_fsm;
    (void)p_evt;
    bsp_emergency_actuator_quench();
    bsp_led_strobe_fault_code(0x01);
}

/* ========================================================================= */
/* 3. MAIN COOPERATIVE SUPERLOOP & SUPERVISION (MODULE 1, 3, 5)             */
/* ========================================================================= */
static AppFsm_t g_system_fsm = {
    .state = STATE_IDLE,
    .latest_temp_mdegc = 0,
    .packet_sequence_id = 0U
};

int main(void) {
    /* 1. Hardware Initialization via BSP */
    bsp_system_clock_init();
    bsp_gpio_init();
    systick_init();
    bsp_watchdog_init(1000U); /* 1000 ms hardware window */

    /* 2. Driver & Service Setup */
    hal_i2c_init();
    hal_uart_init(115200U);

    Event_t current_event;

    /* 3. Infinite Run-to-Completion Superloop */
    while (1) {
        /* A. Dispatch queued asynchronous events */
        while (event_queue_get(&current_event)) {
            if ((g_system_fsm.state < STATE_MAX) && (current_event.signal < 5)) {
                const StateTransition_t * const p_trans = 
                    &g_fsm_table[g_system_fsm.state][current_event.signal];

                if (p_trans->action != NULL) {
                    p_trans->action(&g_system_fsm, &current_event);
                }
                g_system_fsm.state = p_trans->next_state;
            }
        }

        /* B. Background Non-Blocking Periodic Maintenance */
        bsp_heartbeat_led_step();

        /* C. Watchdog Feed: Verified safe at superloop idle point */
        bsp_watchdog_feed();

        /* D. Enter Sleep Mode until next interrupt wakes CPU */
        __WFI();
    }
}

25.3 The Pre-Deployment Integration Checklist

Before any embedded C firmware image is signed and deployed to target production hardware, it must pass the rigorous Firmware Production Readiness Gate:

Verification Domain Mandatory Engineering Check Passing Evidence
Type Safety & Compiler Build with -Wall -Wextra -Werror -pedantic -std=c99. Zero warnings, clean compilation across all translation units.
Static Safety Analysis MISRA-C:2012 compliance audit via Cppcheck / PC-lint. Zero Mandatory violations; approved formal deviation records for Required.
Memory & Stack Bounds Stack watermarking and memory segment footprint verification. Stack margin > 30% under worst-case nested interrupt loading.
Timing & Responsiveness Worst-Case Execution Time (WCET) profiler with DWT cycle counter. Every cooperative superloop task executes in < 2.0 milliseconds.
Hardware Watchdog Deliberate fault injection (induced infinite spin-loop). Watchdog resets chip cleanly within 1000 ms; actuators quench safely.

25.4 Code Comparison: Chaotic Monolith vs. Integrated Architecture

Observe the contrast between an ad-hoc firmware script and the unified reactive architecture.

Compare Architecture: Industrial Sensor Node

❌ Chaotic Monolith (Spaghetti)

void main() {
    init();
    while (1) {
        read_sensor();
        delay_ms(1000); /* Stalls everything */
        if (button_pressed) {
            send_uart(); /* Drops if cable cuts */
        }
        /* Watchdog kicked inside ISR! */
    }
}

Flaws: Blocking delay blinds CPU, button events missed, unhandled communication freezes, watchdog improperly fed inside ISR, zero testability on host.

✔ Integrated Reactive Architecture

int main(void) {
    bsp_init();
    while (1) {
        while (event_queue_get(&evt)) {
            fsm_dispatch(&g_fsm, &evt);
        }
        bsp_watchdog_feed();
        __WFI(); /* Low-power idle */
    }
}

Excellence: Zero blocking delays, lock-free SPSC event queues, deterministic FSM state transitions, bounded execution time, fully testable on PC.

25.5 Interactive Knowledge Check

Test your comprehensive mastery of integrated embedded C architecture across all 25 curriculum topics.

1. In an event-driven integrated firmware architecture, what is the primary role of an Interrupt Service Routine (ISR)?
  • To execute complete complex business algorithms and write to Flash memory.
  • To execute immediate minimal hardware service, package the event into an SPSC queue, and exit rapidly in under a few microseconds.
  • To wait in a 10 ms spin loop for sensor conversion.
  • To format strings and print them over UART.
Explanation: ISRs must be ultra-short run-to-completion handlers that offload processing to the main loop via thread-safe queues.
2. Why should the Hardware Watchdog Timer (IWDG) feed call be placed exclusively in the main superloop rather than an ISR?
  • Because watchdogs can only be written from Thread mode.
  • Feeding in an ISR is a critical flaw: an ISR will continue kicking the watchdog even if the main superloop or FSM is completely hung or deadlocked.
  • Because watchdog registers cannot be accessed at high clock speeds.
  • To reduce SRAM consumption.
Explanation: Kicking the watchdog in the superloop verifies that all scheduled tasks are progressing and no task is blocked in an infinite spin-loop.
3. What is the fundamental advantage of host-based unit testing (e.g. using Unity on a PC) for embedded C firmware?
  • It eliminates the need for compiling the code.
  • It allows automated test suites to run thousands of state transitions, edge cases, and fault injections in seconds without physical microcontrollers.
  • It increases Flash ROM size on the target chip.
  • It generates PCB layout gerber files automatically.
Explanation: Hardware abstraction lets developers test pure algorithmic and state logic on PCs within CI/CD pipelines at orders-of-magnitude faster speeds.
4. What happens when two's complement unsigned integer subtraction (now - previous_time) is calculated during a 32-bit timer rollover?
  • The MCU enters a HardFault exception.
  • The subtraction wraps naturally modulo 2^32, producing the exact circular elapsed time without any conditional branching or error.
  • The elapsed time becomes negative and crashes the loop.
  • The SysTick interrupt vector is reset.
Explanation: Unsigned subtraction is modular arithmetic: (0x00000005 - 0xFFFFFFFA) = 11 ticks, guaranteeing drift-free, rollover-immune timing.
5. Why does MISRA-C:2012 strictly ban dynamic memory allocation (malloc/free) in safety-critical firmware?
  • Heaps suffer from non-deterministic allocation latency, memory fragmentation, and unpredictable out-of-memory crash risks.
  • Because microcontrollers lack physical SRAM.
  • Because malloc only works with 8-bit integers.
  • It causes the CPU clock frequency to decrease.
Explanation: Real-time safety standards mandate static determinism. Dynamic memory heaps fragment over time, risking catastrophic allocation failure.
6. What is the role of the __WFI() (Wait For Interrupt) instruction at the end of the cooperative superloop?
  • To restart the microcontroller.
  • To halt the processor core clock until the next hardware interrupt fires, dramatically slashing dynamic power consumption during idle periods.
  • To flush the compiler cache.
  • To calibrate the internal RC oscillator.
Explanation: __WFI() enters low-power sleep when no events remain in the queue. Any peripheral interrupt wakes the CPU instantly with zero latency penalty.
7. How does the 4-tier layered architecture isolate silicon supply-chain disruptions?
  • By storing the firmware in satellite networks.
  • By confining all chip-specific register code to the BSP and HAL; replacing an MCU requires updating only Layers 3 and 4, leaving application logic intact.
  • By eliminating the need for microcontrollers.
  • By automatically redesigning the PCB.
Explanation: Strict abstraction walls ensure that business logic and device drivers depend solely on abstract HAL interfaces, enabling painless silicon migration.
8. In defensive C programming, why is every public pointer argument validated against NULL before dereferencing?
  • Dereferencing a NULL pointer triggers an unrecoverable HardFault exception on ARM Cortex-M processors, freezing the core.
  • To prevent the GCC optimizer from running.
  • Because NULL pointers consume 64 KB of Flash.
  • It is required only in C++ projects.
Explanation: On microcontrollers without MMUs, accessing address 0x00000000 triggers bus faults or reads vector tables, corrupting execution.
9. What is the purpose of "Stack Watermarking" prior to releasing embedded software to production?
  • To stamp a digital copyright into Flash ROM.
  • To measure the maximum historical stack consumption under peak system loads, mathematically proving that stack will never collide with global SRAM.
  • To cool down the silicon die temperature.
  • To compress RAM by 50%.
Explanation: Watermarking with a pattern (e.g. 0xA5A5) reveals the exact deepest stack penetration, verifying safety margins against stack overflow.
10. What defines a truly professional embedded C software engineer?
  • Someone who memorizes register addresses and writes 5,000-line main.c files in one night.
  • An engineer who designs decoupled, deterministic, MISRA-compliant architectures with strict bounds checking, automated tests, and fail-safe recovery.
  • Someone who relies on infinite blocking delays for all timing.
  • Someone who ignores compiler warnings.
Explanation: Embedded mastery is the rigorous discipline of building predictable, resilient, and maintainable systems that operate flawlessly in the physical world.

25.6 Capstone Engineering Laboratories

Execute these 5 comprehensive capstone assignments to build, verify, and validate a production-ready embedded system.

Assignment 1: Complete Capstone System Integration

Task: Build and compile Program 25.1 into a target microcontroller. Connect a real or simulated temperature sensor and push button. Verify via an oscilloscope or logic analyzer that the main superloop sleeps in low-power WFI mode and wakes smoothly on each 100 ms tick and button press.

Assignment 2: Host PC Mock System Simulation Harness

Task: Port the Capstone application to run on your host development PC using GCC. Implement mock BSP and HAL functions. Write an automated test scenario that injects 1,000 events (including simulated I2C bus lockups) and verifies that the FSM transitions cleanly without a single crash or memory leak.

Assignment 3: Full Static MISRA-C Compliance Audit

Task: Run cppcheck --addon=misra.py across the entire integrated capstone project. Resolve all flagged issues until zero Mandatory or Required rule violations remain. Document any unavoidable hardware register deviations in a formal Markdown deviation report.

Assignment 4: Worst-Case Execution Time (WCET) Profiling

Task: Instrument the main superloop using the ARM Cortex-M DWT->CYCCNT cycle counter. Measure the maximum execution time of each state action. Confirm that no task exceeds a 1.5 ms execution budget under peak event loading, verifying zero watchdog starvation.

Assignment 5: Silicon Porting Verification

Task: Take the Capstone project and re-target it to a different microcontroller family (or a separate simulator target). Demonstrate that only the bsp/ and hal/ directories require modification — the core application, FSM table, event queue, and sensor driver files remain 100% bit-for-bit identical.
